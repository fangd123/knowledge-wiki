# 终端环境改造：按症状排查

同一个 SSH 窗口里，画字的是本地 Windows Terminal，解释命令的是远端 Shell，保住会话的是服务器上的 tmux。先找出哪一层出了问题，不用为了一个方框重装三套工具。

| 你看到什么 | 先做一个区分 | 接下来去哪儿 |
|---|---|---|
| 中文正常，只有提示符里的分支图标变成方框 | 在 tmux 外看同一个提示符。如果仍是方框，先看本地 Terminal 当前配置文件选的是不是带该字形的字体；如果连普通中文也乱码，再分别检查文本编码和远端 locale。 | [主文：窗口与字体](利器/01-利器01：Windows_Terminal_与_Bash_改造记录.md#窗口字体装在看屏幕的这台电脑上) |
| 在普通 SSH 提示符里能拖选，进 tmux 后却复制不出 | 拖动可能交给了 tmux，而不是本地终端。试着按住 `Shift` 拖选，让 Windows Terminal 接管，再用它的复制操作。tmux 的复制缓冲区和 Windows 剪贴板不是一回事。 | [主文：会话和鼠标模式](利器/01-利器01：Windows_Terminal_与_Bash_改造记录.md#会话断开-ssh-以后怎么接回来) |
| 装了插件，输入命令却没有建议 | 在当前交互窗口执行 `ps -p $$ -o comm=` 看自己用的 Shell。如果还是 Bash，改 `.zshrc` 不会生效；若已经是 Zsh，再核对插件目录和 `plugins=(...)`。 | [主文：在远端配置 Zsh](利器/01-利器01：Windows_Terminal_与_Bash_改造记录.md#输入在远端配置-zsh) |
| 安装工具时一直超时 | 看清报错的是哪台机器、哪个下载地址。能在本地浏览器打开项目首页，不等于远端能下载发行包。先按官方说明检查网络和软件源，不要把旧博客里的镜像拼到安装命令里。 | [Oh My Zsh](https://ohmyz.sh/) · [Starship](https://starship.rs/guide/) |
| 断开 SSH 后，回来只见一个空提示符 | 先在**同一台服务器、同一账户**执行 `tmux ls`。会话还在，就按名字接回；如果任务原本没在 tmux 里，事后开一个新会话不会把它找回来。 | [主文：重新连接](利器/01-利器01：Windows_Terminal_与_Bash_改造记录.md#会话断开-ssh-以后怎么接回来) |

要从头搭这套环境，读[《利器01》](利器/01-利器01：Windows_Terminal_与_Bash_改造记录.md)；想知道本地多标签和远端多窗格为什么不重复，读[《Terminal 工作流》](Terminal工作流.md)。
