# FormFill 功能差异、首发任务与取舍建议

核验日期：**2026-11-17，Asia/Singapore**。本报告接续本目录既有研究，负责功能与定位，供父会话统筹定价、宣传和 SEO。没有安装任何竞品，没有进行竞品真实填表测试、模型调用、注册或付款；没有改动业务源码、部署或发布，没有使用真实用户资料、读取凭据或继续委派，也不执行子任务 Plane log。

## 1. 先回答“现在有什么不同”

**现在有可展示的能力组合，但还没有证据证明存在难以替代的功能优势。** 本项目已能把中文自然语言、`.docx`、`.xlsx`、`.txt`、`.md` 的内容交给自选 HTTPS OpenAI 兼容模型，再填写当前网页。相对只接收文本的 Filly，原生 Office 输入和接口配置更宽；相对 Formly 的托管额度服务，自带模型且没有本项目后端中转是架构与费用选择上的区别。相对 Excel 专用工具，本项目能尝试理解字段语义与非表格文字，不要求先把内容整理成与网页标签一致的列名。

但三个方向都已有强反证：

- **FastFiller** 的作者文档已宣称 BYOK、多个 profile、原始文本、填前逐字段编辑/跳过、撤销和本地 Ollama。本项目不能以“可选模型、多档案或审核”宣称领先；后两项本项目还没有。
- **Formly** 已宣称 PDF/Word/Excel/CSV/图片到网页，Excel 多人记录可以选人并即时切换，切换不额外调用 AI。仅添加“选一行”不足以形成差异。
- **XL2Web、File Form Filler Classic/Automation、Excel Paste Filler** 已有行/记录选择或多行填写、字段匹配及复用能力。特别是 Excel Paste Filler 的商店描述已有表头智能匹配，不能描述成只能按控件顺序粘贴的旧式工具。

**建议先对照两类候选任务：“同一企业资料→多个外部登记网页”与“同一业务网页→多条记录”。** 通用首页不先收窄；先观察频率、现有原生导入/规则替代与人工复核负担，再选择映射复用或来源检查的最小原型。这些仍是产品假设；本轮没有证明其他所有产品都不做，也没有用户付费证据。Qwen 复核后的执行口径见 [计划](46-FormFill_网站、功能、宣传与_SEO_执行计划.md)。

## 2. 比较口径与当前能力表

证据标签：**本地**＝本仓库源码静态核实；既有运行复现会另标“既有复现”。**宣称**＝官网、作者文档或商店描述，本轮未安装验证。**公开源码**＝读取竞品源码得到的静态观察，同样不是运行实测。**未知**＝所读材料不足，不能当作“不支持”。**未实现**仅用于本仓库已读主流程和数据结构未提供该能力的判断。所有外部产品均未安装实测，不比较成功率、耗时或准确率。

### 2.1 AI 与资料到网页的直接比较

| 能力 | 本项目 FormFill | FastFiller [F1–F3] | Filly [Y1–Y3] | Formly（ExcelToForm 产品线）[E1–E5] |
|---|---|---|---|---|
| 自然语言/非结构文字理解后填网页 | **本地**：文字及文件内容 → 模型 → `fieldId/value` → 页面 | **宣称**：raw text/profile → 语义映射 → 页面 | **宣称+公开源码**：上下文文件与网页字段/正文 → 模型 → 页面 | **宣称**：上传文件 → AI 自动匹配字段 |
| 原生文件输入 | **本地**：xlsx、docx、txt、md；不支持旧 doc/xls、PDF/图片/CSV 解析 | **宣称**：txt/md/json profile 导入；所读文档未证实原生 xlsx/docx 解析 | **宣称+公开源码**：txt/md/json/csv/yaml/yml，按文本读；没有 xlsx/docx 解析路径 | **宣称**：PDF、docx、Excel、CSV、图片 |
| Excel 多工作表 | **本地**：全部 sheet 转 Markdown；不是选择 sheet/记录 | **未知** | **公开源码**：未提供 Excel 二进制解析；CSV 是普通上下文 | **未知**：已宣称支持 Excel，但 sheet 选择范围未核实 |
| Excel 逐条记录选择/执行 | **未实现**：无行选择、当前记录身份、下一条游标或逐行执行器 | **未知**；大表单“分批字段”不能当成多条 Excel 记录处理 | **公开源码**：CSV 全文送模型；未见行选择/逐条执行路径 | **宣称**：检测多人资料、选择本次记录、即时切换且无额外 AI 调用；不据此推断无人值守批量提交 |
| AI 字段映射 | **本地**：模型返回本次扫描的字段 ID 和值 | **宣称**：语义映射 | **宣称+公开源码**：字段 key 到值 | **宣称**：名称不一致时也自动匹配 |
| 保存“源列/源字段 → 网页字段”映射 | **未实现**：历史值样本不是显式映射；临时 fieldId 仅本次扫描有效 | **未知**：profiles/templates 是资料模板，不足以证明保存列到控件的映射 | **公开源码**：保存单份 context；未见独立映射配置 | **未知**：当前页结果缓存不等于持久映射模板 |
| 固定资料模板/多档案 | **未实现**：无命名资料档案；学习样本不等于用户管理的多个主体 | **宣称**：多 profile、复制/搜索、JSON 导入导出、日期变量 | **公开源码**：记住一份文件，可删除/替换；未见多 profile 管理 | **宣称**：同文件多记录切换；持久多档案管理**未知** |
| 人工复核发生在何时 | **本地**：模型返回后直接写；用户在目标网页检查并自行提交 | **宣称**：填前 inspector 可编辑值、勾选跳过、确认再注入；也可填后检查 | **公开源码**：直接写；文件文本 Preview 不是逐字段填前审核 | **宣称**：填写后检查再提交；政策说明处理结果在点击 Fill 后写入；是否有逐字段填前编辑列表**未知** |
| 撤销本次写入 | **未实现**；已有取消请求不等于撤销已写值 | **宣称**：注入前 DOM 快照、一键恢复 | **公开源码**：所读主流程未见快照/撤销 | **未知** |
| 每个值定位到源文件位置 | **未实现**：无 sheet/cell/段落来源标识与展示 | **未知**：字段 drawer 高亮目标网页，不等于定位资料来源 | **公开源码**：JSON 值没有来源结构 | **未知**：选记录不等于逐字段来源定位 |
| 模型选择/BYOK | **本地**：API Key、模型名、HTTPS base URL；单组当前设置、连接测试 | **宣称**：多供应商、custom gateway、模型发现、BYOK、本地 Ollama | **公开源码**：选择 OpenAI/Anthropic，自带 Key；模型在代码中固定，没有自定义 base URL/模型输入 | **宣称**：托管免费/付费 fills；政策称用 OpenAI/Anthropic；用户 BYOK/选模型能力**未知** |
| 无产品后端中转 | **本地**：直达所配服务；资料与字段摘要会外发，不等于离线 | **宣称**：直连选定模型，无中间服务器 | **公开源码**：popup 直连供应商 API | **政策宣称**：经过其 Cloudflare Workers 后端转发，后端不保留文件/提取值；有额度/账户关联数据 |
| 默认 HTTP localhost Ollama | **当前不支持配置**：UI/权限只接受 HTTPS，且要求 Key；不能从“OpenAI 兼容”推断默认可用 | **宣称**：`http://localhost:11434/v1` | **公开源码**：只有两家固定 HTTPS API | **未知** |

Formly 政策还明确：最近文件的处理结果可在本地缓存，便于重开 popup；“服务端不存文件”并非完全不缓存。它的后端“不保留文件”也不等于“不经过后端”。本项目可以准确说明少一个产品方中转环节，不能据此保证模型供应商零留存或宣称竞品实际泄露数据。

### 2.2 Excel 专用替代：重复录入上不能忽略

| 能力 | File Form Filler Classic/Automation [E1、E6–E7] | XL2Web [X1–X3] | Excel Paste Filler [P1] |
|---|---|---|---|
| 输入与填写单位 | **宣称**：Excel/CSV 上传或粘贴；首行/首列为标题；Row/Column 模式每行/列为完整记录 | **宣称**：xlsx/CSV；设置 sheet、header row、data row | **宣称**：复制 Excel/Sheets 单元格粘贴；支持多行 |
| 逐行/记录控制 | **宣称**：`Index to fill` 选择记录，每次填写后自动增加 | **宣称**：行号指定记录；最后一页动作完成后可自动增加，支持多页 | **宣称**：填网页表格多行或重复表单条目；没有证据证明可无人值守跨页提交 |
| 匹配机制 | **宣称**：按 label、placeholder、aria-label、附近文本匹配表头；需要准备对应标题；非 LLM | **宣称**：点击捕获 selector、列映射；Refresh 对空映射找最佳表头匹配；未宣称用 LLM | **宣称**：顺序粘贴，另有 v2.1.4 Smart Header Matching，按 label/placeholder/name 精确、词级、部分匹配；未宣称用 LLM |
| 映射/固定模板保存 | **宣称**：Guide 有 Template File 方式；持久保存映射的具体机制**未知**；Automation 可预设点击/输入 | **宣称**：website profile 保存 pages/selectors/actions/mappings，JSON 导入导出，可分享配置 | **宣称**：最近 10 次粘贴可重放；不据此推断具备显式持久映射模板 |
| 多档案的含义 | 多条文件记录；命名档案管理**未知** | **宣称**：多个“网站流程 profile”，不是多个人/企业资料档案 | **宣称**：粘贴历史；主体档案管理**未知** |
| 人工复核、异常 | 指导用户选记录后填写；逐字段填前审核/撤销/来源定位**未知** | 手工配置与手动填充可控；逐字段填前审核/撤销/源单元格定位**未知** | **宣称**：未匹配表头、空标题、越界、数值错误即时提示，严重错误停贴；完整填前审核/撤销/源位置定位**未知** |
| 数据处理与模型选择 | **宣称**：Classic/Automation 全本地；非模型产品，不需 BYOK | **宣称**：本地处理；非模型产品，无已核实 BYOK 功能 | **宣称**：填表数据本地处理、免费无账号；独立翻译功能不能据“填表本地”外推为所有功能离线 |
| 对本项目的直接约束 | 逐条选择、自动递增、固定输入并非空白；不应把 Classic 与 Formly AI 混成一款功能 | 映射保存、导入导出、多页、等待/按钮动作已有；难以靠“保存映射”一项收费 | 免费工具已有表头语义近似匹配、多行、异常提示；简单整齐表格未必需要 AI |

### 2.3 本地核实的实现边界

| 代码/既有证据 | 能确认什么；不能推断什么 |
|---|---|
| `utils/file-parser.ts:29`、`:70`、`:214` | 读全部 sheet、转 Markdown，最终内容最多 50,000 字符；10MB 文件限制。格式化日期为 ISO、单元格转字符串，不能承诺保留 Excel 显示格式/所有标识符语义。多 sheet 标题文本不是结构化来源追踪。 |
| `entrypoints/background.ts:60`、`:72`、`:86`、`:93` | 文件全文与用户补充输入拼接；按 origin/表单签名追加历史值；模型指令返回后直接发送填写。没有选记录→预览→确认的独立阶段。 |
| `utils/messaging.ts:30`、`:36` | 指令只有 `fieldId/value`；文件只有正文/文件名/类型/截断标志，无 sourceId、sheet/row/cell、evidence、原值快照或映射版本。 |
| `entrypoints/content.ts:49`、`:132`、`:165`、`:270` | 扫描 open Shadow DOM、支持原生 input/textarea/select，按临时 ID 解析目标并写值、派发事件、跳过部分类型。未提供 iframe/closed Shadow DOM、通用自定义 combobox、导航/点击代理或自动提交。 |
| `entrypoints/popup/App.tsx:28`、`:117`、`:609`；`wxt.config.ts:11` | 只允许 HTTPS base URL，需 API Key/模型；文件正文短摘要已有，但不是拟写字段预览。未核实不同供应商的实际兼容性，`thinking` 参数也不能假设每个兼容接口都接收。 |
| `utils/learn.ts:17`、`:62`；`utils/settings.ts:23` | 按 origin+表单签名保存历史值，最多 50 条、30 天，用户可清空；不是训练模型、不是源列映射、不是多主体档案。 |
| `website-audit.md` P0 专项；本轮重读内容脚本/学习链路 | **既有复现**证实学习首次同意前可记录、读取同页其他表单；本轮源码仍有 document submit/整页提取路径。历史样本可能发模型；附近文本可能夹带文本域初值。不能把当前学习功能作为可信差异卖点，也不能把本地采集问题描述成已实测网络上传密码。 |

本轮没有重复运行原审计测试，没有调用真实模型；已有 46 项测试通过等结论引用前次报告，不冒认为本轮新验证。引用的是当前工作区文件，仓库有既存未提交修改，不能把当前状态自动等同于任何已发布版本。

## 3. 三类卖点：哪些现在能说，哪些尚不能

### 已有、可展示的优势，但只相对于特定替代方案

| 可以展示 | 比较对象与实际价值 | 必须带上的限制 |
|---|---|---|
| 中文文字、Office 资料直接作为填表输入 | 对 Filly 的纯文本文件流程，减少先把 xlsx/docx 转文本的操作；对固定表头工具，容许不同标签和非表格文字 | 是能力组合，Formly 已有且格式更多；没有证明中文准确率领先；xlsx 是上下文，不是逐条执行 |
| 用户控制模型接口与费用承担方式 | 对 Formly 托管额度模式，用户可选已有 HTTPS 兼容模型服务；没有 FormFill 后端中转 | FastFiller/Filly 亦有 BYOK/直连；需要配置 Key，模型费另计；HTTP 本地模型当前不支持 |
| 源码可读、行为边界可核查 | 用户可以检查解析、请求和写入；MIT 允许修改分发，技术用户可接入自己的工作流程 | FastFiller 亦为 MIT；开源不等于已通过安全审计；P0 修复前不营销“放心无感学习” |
| 当前页面辅助填写、用户自行提交 | 比追求无人值守的通用自动化，任务边界清楚，便于演示和控制 | FastFiller 也明确不自动提交；这是一种产品选择，不是独有能力；本项目还缺填前审核和撤销 |

“可展示”指可以制作真实演示证明已有路径，本轮尚未制作真实扩展录屏，也未建立跨模型/网站成功率基线。

### 同质化基础功能，不能靠它单独定价或宣传独家

- AI 看标签匹配字段、文字/资料辅助录入、Key 本地保存、直连模型、模型自选、无开发者后端、用户手动提交。
- 标准输入/下拉/单选/复选，错误处理、取消和连接测试；这些是可用性的组成部分。
- **要补但不是差异壁垒**：填前预览与编辑、跳过和保留原值、撤销、多档案、Excel 选记录、命名模板。FastFiller/Formly/XL2Web 已分别覆盖其中多项。
- 密码排除、授权采集、删除、数据流说明、避免静默覆盖等安全与信任基础，应默认提供，不作为高级付费门槛。来源缺失/冲突提示一旦实现也不宜靠收费隐藏风险。

### 尚未验证、值得做最小原型的潜在差异

| 假设 | 应证明的用户收益 | 为什么现在只能叫假设 |
|---|---|---|
| 每个建议值都能定位到资料来源 | 目标“公司英文名”旁显示源文件、sheet/cell 或段落，点开核对；减少在多份相似资料里寻找 | 本项目无实现；所读竞品文档未证实相同链路，未知不等于别人没有；用户是否愿意持续使用尚未验证 |
| 明确区分原文、格式转换、缺失、冲突 | 电话/日期等可验证转换有规则；缺失时留空；同名主体/矛盾版本让用户选择，不能自动取历史值 | 当前 prompt 仍允许合理推断；不能用模型自报“置信度 95%”代替证据或校验 |
| AI 建议一次、人工确认后保存可检验映射 | 同一来源结构/同一表单，后续记录采用已确认映射，减少重复推理与逐字段复核；结构变化先停下 | 保存映射和选记录别人已有；必须组合来源核对、结构失效处理、实际减少复核工作量才可能成立 |
| 中文业务任务的公开兼容样例与失败清单 | 让用户判断自己的企业名称、业务简介、日期和联系人字段等是否适用，知道何时改手填 | 不是“中文语言包”就形成优势；应先用非敏感合成样例测语义与控件，不能泛化成中文准确率领先 |

首发不建议用证照号、银行、支付或身份资料做宣传示例；上述任务中的联系人用合成数据验收，正式使用前遵守组织的数据处理要求。这里没有推定任何合规认证。

## 4. 推荐唯一首发任务：企业资料卡 → 外部合作方登记网页

**目标用户假设：**已有模型 API 使用能力的小团队运营/业务助理，反复把公司简介或供应商资料卡录入不同合作方、主办方的现有网页。先限定普通公开企业信息、业务说明及获得授权的联系字段，用户负责最终检查和提交；不包含银行、证照、医疗、认证/密码表单。

**任务承诺：**“把这一家公司的资料填进眼前的登记表，缺少的留空，填完由你检查提交。”首发用**单一企业的 docx 或文字资料**验证现有路径。多企业 Excel 必须等显式选择记录与防串资料完成后再纳入承诺；当前用户写一句“填第三行”只是模型指令，不是产品层面的记录隔离。

完成最小补洞后，理想流程是：选本次企业/资料范围 → 展示拟填字段与原值 → 用户改值/跳过 → 写入 → 本次撤销 → 用户自行提交。来源定位先覆盖 xlsx 单元格和文本段落；docx 段落号可作为应用内定位，不能伪称固定页码或原 Word 精确版式位置。

| 为什么优先这个任务 | 功能与竞争依据 | 不应夸大的地方 |
|---|---|---|
| 比求职首发更贴合已有输入 | 现有 docx/xlsx/文字与中文业务标签有直接用途；求职需要 ATS、履历分段、申请追踪等可靠性，FastFiller/Simplify 等已有专门叙事 | 并未证明此客群市场更大或获客更便宜；FastFiller 也有 CRM/企业场景，Formly 也接受业务资料 |
| 比通用 Agent 范围更可交付 | 只处理当前页字段，不需要导航、附件上传、账户会话编排、跨页任务恢复；易用可重复任务验收 | 不是所有登记表都是一页；遇 iframe、附件、复杂级联要明确停在支持边界 |
| 比纯剪贴板/固定模板更有理由用模型 | 不同网页把同一事实叫不同名字，且源资料包含叙述文字；首次匹配有语义价值 | 表头整齐、网页固定且频繁重复时，Excel Paste Filler/XL2Web 可能更快、更便宜；不要强行给这类任务加 AI |

**验证办法：**使用合成的单企业文字、单企业 docx、多人/企业 xlsx，覆盖联系人/企业名称歧义、多个地址、缺失值、冲突值和页面原有值。记录“正确完成一份登记所需的人工修正、复核与重试”，同时保留实际任务/字段分母，不预填准确率或节省时长。只有用户连续在自己的适用任务中选择复用，才支持继续扩大范围。

## 5. 路线图：补洞与差异功能分开决策

成本只给相对工程复杂度（低/中/高），不编工日。它基于当前源码耦合判断，不是排期承诺。每项验收均使用合成资料与可控页面；跨网站验证要逐例记录，不能由单个 fixture 通过推断全部兼容。

### A. 先完成发布与控制基础

| 顺序/项 | 竞争依据与归类 | 可执行验收任务 | 成本与风险 |
|---|---|---|---|
| A0 修复学习授权、表单范围与摘要采集，统一说明 | 本地 P0 已有复现；直连/本地架构没有抵消采集缺陷。**补洞，免费基础** | 首次未同意、未用扩展、提交其他 form、关闭学习均不新存样本；只记录明确授权对象；合成 textarea/密码标记不经附近文本泄出；请求只带已说明资料；用户可查/删样本 | **中**：涉及监听器、摘要、样本和文案；必须重跑专项否定测试。若来不及可靠修复，先移除/关闭自动采集入口并验证实际不采集，不能只改营销词 |
| A1 可安装、真实演示、文件边界与配置引导 | Formly/XL2Web/Excel Paste Filler 有商店路径；FastFiller 有 release/source 安装说明。**补洞** | 干净浏览器从获取入口走到首次填表；无 key/错 URL/错模型/拒绝权限有可理解反馈；`.doc/.xls` 不宣称可读；不把模拟 Demo 当模型实测 | **低–中**，但发布审核外部时间未知；兼容接口可能拒绝扩展的 thinking 参数，需实际选定服务组合验收 |
| A2 拟填字段与原值预览，可编辑/跳过，默认保护非空值 | FastFiller 已宣称完整 inspector，单靠预览不能差异化。**补洞，免费基础** | 模型完成前后均不自动写；选择某字段后才写；用户已有值默认保留，覆盖要显式；页面/字段变化时旧结果不得写错对象 | **中–高**：需拆“生成/确认/应用”阶段，暂存扫描上下文与目标 tab/form，防 SPA 重绘导致旧 fieldId 失效 |
| A3 本次填写撤销与部分失败反馈 | FastFiller 已宣称快照/撤销；当前 cancel 不撤回写入。**补洞，免费基础** | input/textarea/select/checked 状态可还原；写一半失败可解释；用户后续自己编辑的字段不被静默回滚；不承诺撤销页面已经触发的服务器副作用 | **中–高**：本地快照、框架事件、依赖字段复杂；先限定支持控件，无法还原时明确说明 |
| A4 Excel sheet/表头/记录选择与当前主体确认 | Formly 已能选人；Classic/XL2Web 有 index/row，Excel Paste Filler 有多行。**补洞** | 合成两 sheet、多条同名记录，显式选 sheet/行；请求只含所选记录和用户明确选入的公共说明；手机号/前导零/日期有保真策略与提示；没有记录选择时不混送全文件 | **中–高**：解析结果要保留结构，不只 Markdown；合并单元格、多表头、日期显示/标识符需明确边界。先做选一条和手动下一条，暂不自动提交 |

### B. 一个差异原型与一个复用闭环

| 顺序/项 | 竞争依据与归类 | 可执行验收任务 | 成本与风险 |
|---|---|---|---|
| B1 字段值来源定位 + 缺失/冲突可见 | 本轮重点竞品资料未证实逐字段源定位，但不能证明独家。Excel Paste Filler 已有异常停贴。**差异假设** | `公司名 ← 文件A/Sheet1/B3`；文字用段落/字符区间；引用的证据必须在源中存在且属于当前记录；转换标记独立展示；矛盾地址需用户选择，无证据字段留空；点击可看到对应原文 | **高**：模型捏造来源、合并字段、一对多来源、转换后值校验；不能仅让 LLM 输出一段解释就叫追溯。先支持 xlsx+纯文本，再扩 docx；预览与缺失/冲突警告作为基础能力 |
| B2 保存人工确认映射，后续确定性复用，结构变更停用 | XL2Web 已保存 mapping，FastFiller 已有资料模板。**效率假设，单项同质化** | 首次人工确认源字段→目标字段；换一条合成记录只换值，复用不重新让模型猜列；站点/表单/来源结构变更时提示重确认；日期转换规则可检查；模板不夹带上个主体值或 Key | **高**：临时 fieldId 不能持久保存，需稳定定位/签名与版本；过度宽松匹配会错填，过度严格会反复配置。依赖 A4 的主体隔离、稳定来源标识及目标定位；不依赖完整 B1/Word/多文档追溯 |
| B3 从“自动学习最终值”改成“用户保存本次映射/改正” | 现有学习 P0、跨主体历史值可能污染；竞品显式 profile/configuration 更易解释。**产品调整** | 由用户主动保存，展示保存内容；资料档案与站点映射分离；下一条记录不沿用旧主体事实；删除映射/资料互不混淆 | **中–高**：迁移旧样本、废弃隐式行为。可先停用旧学习，避免并行维护两套模糊概念 |
| B4 固定首发任务兼容清单与可重复资料包 | 竞品都有广泛兼容营销；本项目可以用具体条件建立信任。**持续交付能力** | 每项列源码/构建版本、模型配置、输入、网页控件、预期、失败边界；中文别名/长文本/选项/缺失值/结构变化可重复；人工修正与复核成本有原始任务记录 | **中，持续成本**：维护表单变更和多模型差异；不能以测试页面通过宣称任意外部站点支持 |

**收敛顺序建议：**先 A0/A1，合成单主体资料可作技术试验；真实业务试用补 A2/A3。多记录任务须先 A4；若进入多记录付费交付，记录选择与防串填验收是收款前置。观察复用后可做稳定来源/目标定位下的最小 B2/B3；完整 B1 是验证检查收益后的增量实验，不阻塞结构化映射。不要并行堆完所有差异设想，也不先开发无人值守。

- **基础版应完整可控**：模型配置、普通资料填写、预览/编辑/跳过、撤销、密码/敏感字段排除、授权与删除、风险/缺失/冲突提示。不要以付费解锁“能看清将写什么”或“避免静默错误”。
