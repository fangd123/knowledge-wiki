# FormFill 网站与产品发布审计

审计窗口：2026-11-16 晚至 2026-11-17 凌晨，Asia/Singapore。目录日期保留任务开始日期。

这是一份基于当前工作区源码、生产构建、本地浏览器实测的审计。没有提供或从仓库找到可确认归属的正式网站域名，因此不把本地结果冒充线上状态；网上其他同名 FormFill 产品也不视为本项目。没有改动业务源码、发布网站、提交商店或发送推广帖。

## 结论与定位

当前形态是“具备可工作的扩展核心与展示站的开发者预览版”。最值得先解决的是隐私承诺与实际行为的一致性、可靠的试用/安装路径、Demo 正确性和响应式布局。现阶段不建议先购买广告，或批量生产大量 SEO 文章。

建议优先验证的客群：已经有模型 API 配置能力、经常把现成资料复制到不同网页表单的运营人员或技术用户。自然语言 + Word/Excel 内容 + 自带模型服务，是值得讲清的组合；是否足够构成竞争优势，需要真实试用验证，不能直接宣传为唯一产品。

首屏建议文案：

> 把已有资料，填进网页表单。  
> 粘贴一段文字，或导入 Excel / Word 文件，让 FormFill 为网页字段匹配内容。使用你配置的模型服务，填写后由你检查并提交。  
> 支持 .xlsx、.docx、.txt、.md；需配置模型 API Key，模型费用由服务商计费。

当前尚无正式商店链接，主 CTA 应明确是“查看演示”或“开发者预览版安装”，有真实下载包后才写“下载预览版”。上架后主 CTA 改为实际商店安装，副 CTA 留演示。不要把未实现的预览确认、撤销、PDF、批处理或所有网站兼容写进承诺。

## 已做对的事情

- 页面有独立的 title / description、OG/Twitter 基础标签、图标、独立隐私页；无需重复立项说“全部缺失”。
- Demo 已明确注明本地模拟。无后端配置的本次构建只向本地站点发出资源请求。
- 扩展已有字段 ID 白名单、密码字段拒填、取消、超时、连接测试、可选模型域名权限、学习样本条数/期限限制。
- 表单扫描覆盖不在 `<form>` 内的控件与 open Shadow DOM；文件解析库已有动态导入，不能把大解析包等同于首屏全部加载。
- 网站具备跳转到正文、键盘焦点与减少动画偏好支持，基础测试与构建均通过。

这些是源码和测试层面的核验；真实浏览器内连接不同模型提供商、实际网站完整填表仍未覆盖。

## P0 隐私问题的具体证据

### 1. 学习记录早于首次使用确认，且范围超过提交表单

源码链路：

- `utils/settings.ts:23`：`learningModeEnabled: true`，同时 `privacyNoticeAccepted: false`。
- `entrypoints/content.ts:22` 及生成的 manifest：内容脚本匹配 `<all_urls>`；能否运行仍受浏览器实际站点访问授权影响。
- `entrypoints/content.ts:369–399`：内容脚本初始化后安装 document 的 `submit` 捕获监听器；只检查学习开关，不检查首次确认，也不检查是否由本扩展填过该表。
- 提交后调用 `extractValuesFromDom(document)`，它遍历整页控件；不是仅取 `event.target` 代表的表单。

复现：同一页面放两个表单，用 `SYNTHETIC_FIRST` / `SYNTHETIC_UNRELATED` 假数据。学习开启、首次确认关闭，初始化内容脚本后仅触发第一个表单的 submit。保存函数收到两张表单的值。本测试没有进行任何模型请求，也没有使用用户数据。

影响：目前不能笼统说“只会在用户主动触发填表时读取页面”。这并不表示提交瞬间就发生网络上传；此处首先证实的是提前本地采集和采集范围问题。

建议：以用户主动授权为前提启用学习；按当前表单/本次操作限定作用域；只有同意后发生的适用提交才记录；考虑展示样本内容与明确删除。建立未同意、未填表、其他表单、学习关闭四类否定测试。

### 2. “不会上传”与历史辅助数据流冲突

`public/_locales/zh_CN/messages.json:76` 写“且不会上传”，英文同键写 “never uploaded”。但 `entrypoints/background.ts:72–79` 会在学习开启且匹配到历史时，把 `learned.values` 拼进发给模型的用户消息。

网站隐私页已有“历史学习样本（可选）会一并发送”的说明，说明不同入口已经相互矛盾。应统一成：

> 学习样本保存在扩展本地，不上传到 FormFill 自有服务器。开启历史辅助并再次使用相应表单时，匹配到的样本可能随本次请求发送给你配置的模型服务。

应将“存在哪里”“什么时候读取”“什么时候传输”“谁处理”分别讲清。不能用“没有自有后端”推导出“没有数据离开设备”。

### 3. 密码结构未整体排除，附近文本可能带入文本域初始内容

- `isSerializableControl()` 排除了 hidden/file/按钮等，没有排除 password。因此密码字段名称、标签、类型仍会进入字段摘要；模型规则要求跳过，填充侧也拒绝写入。
- 现有测试甚至明确期待 password 的结构信息，另一条测试的注释却说“完全排除”，显示测试描述和实际断言不一致。
- `getSafeControlValue()` 确实不读取普通输入/文本域的 value，但 `getNearbyText()` 读取父层 `textContent`；`<textarea>初始文本</textarea>` 的文本可从此路径带入摘要。

复现结果：假密码值未出现在摘要中，填充密码字段被跳过；假文本域初始值 `SYNTHETIC_PRIVATE_NOTE` 出现在自身和旁边控件的 `nearbyText`。因此应精确描述为“结构和部分附近文本仍可能发送”，不能写成“已证实直接上传密码值”。

建议从扫描白名单排除 password；采集附近文本前移除 input/textarea/select 等控件内容及隐藏内容；保留必要标签上下文，增加实际业务样例验证。不要仅通过降低隐私承诺来代替最小化采集。

## Demo 的实测结果

本地地址：`http://127.0.0.1:4173`，使用 `website` 生产构建。

1. 默认“活动报名”：正确填入张三、邮箱、手机号、公司、职位。
2. 再选“发票信息”：变为李雷和财务邮箱，但张三手机号、产品经理职位仍保留。
3. 再选“招聘申请”：变为王小明，但邮箱仍是财务邮箱、公司/税号仍是上一张发票的值。
4. “开始演示”后立即“清空”：约420ms的旧模拟任务完成后，表单重新出现张三的信息。
5. 英文资料 `My name is Jane Smith, email jane@example.com, phone +1 415 555 0123, company Acme, role Engineer.`：仅邮箱被识别。
6. 空输入有提示，正常路径未见浏览器运行异常。

原因分别是 `setFormValues(current => ({...current, ...result.values}))`、切示例不清表、没有 pending/取消/序号保护、中文限定的模拟解析器。

这只证明网页 Demo 的缺陷，不能据此断言真实模型也无法解析英文。

另外，若将来设置 `VITE_FORMFILL_DEMO_API`，当前页面仍会初始显示“不会上传”，而代码会 POST 用户 prompt；失败时又静默回落本地解析。启用后端前必须同步展示真实模式、传输提示、错误状态、超时与响应校验。

## 视觉与可访问性

证据图：`desktop-home.png`、`home-390.png`、`home-1061.png`、`desktop-demo-mixed-records.png`、`privacy-desktop.png`。

- 1440×900：首屏中文标题以约115px字体、0.88行高排版，字形过于拥挤；右侧示意图内的邮箱长串撑开 grid，目标字段被父容器裁掉。需要缩小并重排，而非继续添加装饰。
- 390px视口：文档宽432px；360px与320px亦为432px。1061/1100px断点附近也有17px溢出。应先处理 `min-width:0`、`minmax(0,1fr)`、长邮箱换行和伪元素边界，再调断点。
- 720px以下，导航与“获取插件”同时隐藏，没有替代导航；移动访问者不易找到安装说明。建议保留紧凑导航与“在电脑上安装”说明/链接复制入口。
- Demo 标题区使用双列grid容纳三个子项，读序与视觉顺序不清楚；sticky header 与锚点没有统一滚动留白，需逐一检查锚点落位。
- axe 自动扫描首页与隐私页均发现品牌链接的可见文本与 accessible name 不一致；这是工具发现，仍需人工判断适当的品牌可访问名称。
- 未完成真实屏幕阅读器、键盘全流程和不同操作系统字体测试；不要把自动化高分等同于完整无障碍合格。

## SEO 与性能：事实、边界与建议

当前有：首页/隐私页独立title与description、OG/Twitter基础标签、favicon、html语言。当前没有：canonical、hreflang、多语言正文、站点地图、实际robots.txt、场景/教程/比较页、结构化数据。OG图仍为128px应用图标，建议制作能展示产品用途的分享图并使用确定域名上的绝对URL。

首页原始 HTML 中正文只有 root 容器，禁用 JS 时 body 无可见文本。**这不是“Google无法收录React”的证据。** Google当前文档明确会渲染JavaScript；2026-03-04还删除了笼统“使用JS让Google更难访问”的旧说法。静态输出建议的依据是：主要营销内容无需等待脚本、其他不执行JS的抓取器可读、分享与检查更稳定。保留 React Demo、给其余正文预渲染即可，不要求迁移整个框架。

本地 preview 对 `/robots.txt`、`/sitemap.xml` 和不存在页面均回200首页HTML，因此 Lighthouse 报robots无效。这是本地托管行为，生产平台是否相同尚未知。部署时应提供真实文件与正确404状态，不能直接写“线上有soft 404”。

单次本地 Lighthouse 移动模拟：Performance 100、Accessibility 100、Best Practices 100、SEO 91；FCP/LCP约0.8s、TBT原始值7ms（显示10ms）、CLS 0。此结果不含真实网络、生产CDN、全球用户或现场Core Web Vitals，不是线上性能评级；且Accessibility总分100仍有不计分的label-name问题。

网站构建主JS约11.26kB、共享React等约194.79kB，gzip分别4.64kB/61.42kB；CSS gzip约3.37kB。扩展有约509kB的大解析chunk，但已经按需导入。当前证据不支持优先投入大型性能重构。

## 最小的内容与转化重构

推荐首页读序：

1. 一句话说明解决的任务 + 实际可用的安装/预览入口 + API Key前置条件。
2. 30–60秒真实扩展录屏，使用合成资料，在一张真实或明确标注的测试表单上走完整流程。
3. 文字、Word、Excel 三种来源的具体例子，标明文件限制；不要用混合发票/招聘表代替场景。
4. 三步入门：安装 → 配置模型/测试连接 → 填写并人工检查。
5. 数据流与权限：用户资料/页面结构/可选历史 → 配置的服务商；说明本地保存和清除。
6. 当前限制：iframe、closed Shadow DOM、特殊组件、旧doc转换、模型服务费用。
7. FAQ：是否免费、是否需要API key、支持哪些网页、能否覆盖已有内容、不会自动提交、如何清理数据。
8. 有效支持入口、版本日志、源码、隐私政策。

FAQ为帮助用户作决定而写；不要承诺FAQ富结果，Google当前官方更新记载该搜索展示已于2026-05-07停止。

现阶段不要编造评价、安装人数、节省时间或成功率。可用可重复的合成表单任务替代：记录字段总数、正确填写、跳过、错误填写、人工修正、耗时、模型与版本，展示样本范围和失败条件。
