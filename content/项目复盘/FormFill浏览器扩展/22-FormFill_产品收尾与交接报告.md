# FormFill 产品收尾与交接报告

> **最终状态（2026-11-18）：已停止产品化并冻结。** FormFill 保留为技术档案与可复用资产，不再继续扩展功能、上架商店、部署正式域名、开展营销或 SEO、收费、招募用户或承诺持续维护。

本文是项目收尾后的单一交接入口，面向未来的维护者、合作方或重启项目的决策者。事实以仓库代码、测试和 `docs/execution/` 中的证据为准；本文不把研究假设、本地测试或技术样机表述为已上线产品或已验证市场。

## 1. 正式决定

2026-11-18，项目所有者决定停止 FormFill 产品化。决定后，项目进入**归档冻结**状态：

- 停止产品开发与新增基础功能。
- 停止 Chrome Web Store、Microsoft Edge Add-ons 等渠道上架准备和执行。
- 停止生产域名、正式网站部署、GSC 和线上运营。
- 停止推广、社区发布、付费投放与用户招募。
- 停止定价实验、适配收费和商业化承诺。
- 保留现有源码、测试、文档、研究资料、演示包和网站源码，供审计、学习、复用或未来重新评估。

这不是已证明市场需求为零，也不是代码质量失败。它是对以下商业判断的接受：通用自动填表功能的技术门槛低，独立插件难以形成足够强的持续付费护城河；现有产品已达到技术样机水平，但尚未取得真实重复任务、付费、复用或渠道方面的市场证据。

## 2. 冻结时的产品定位

FormFill 是一个 WXT + React + TypeScript 的 Chrome / Edge Manifest V3 扩展。它把自然语言说明或导入的 Excel、Word、文本、Markdown 资料转换为网页表单填写建议，并通过以下流程降低误填风险：

1. 扫描当前页面支持的表单控件。
2. 由用户自备的模型服务生成字段到值的建议。
3. 在预览中逐项核对、编辑和勾选。
4. 用户确认后写入页面。
5. 对本次写入提供有限撤销。
6. 由用户自行检查并提交，扩展不自动提交。

项目曾优先研究“B2B 供应商把企业主档重复录入多个 SRM、采购和行业平台”这一场景。该方向只能视为**有公开线索、冻结时尚未取得真实复现的假设**：目标类型平台的合格复现样本为 0，真实频率、剩余字段价值、BYOK 接受度和付费意愿均未验证。详细证据边界见产品原点与场景方向重估。

## 4. 停止产品化的原因

1. **通用能力可复制。** DOM 扫描、提示词映射、表单写入和浏览器扩展外壳不是足够深的护城河。客户、平台厂商或同规模开发者可以自行研发。
2. **替代入口强。** 浏览器原生自动填充、RPA、平台 Excel/CSV 导入、ERP、OCR、统一主体库、工商带出和专用客户端都在争夺相同任务入口。
3. **独立插件的持续付费理由不足。** 用户价值集中在首次适配、规则维护、复核和交付；单纯按年售卖通用插件难以证明长期价值。
4. **没有完成市场闭环。** 项目具备工程完成度，但尚未取得真实重复任务、可验收付费、明确维护责任或合作渠道。继续扩功能无法替代这些外部证据。

## 5. 保留的可复用资产

| 资产 | 可复用内容 | 使用边界 |
|---|---|---|
| DOM 扫描与受控写入协议 | 控件摘要、已有值保护、受保护字段跳过、预览、应用、页面变化拒写、有限撤销 | 仅覆盖标准网页控件；不支持 iframe 内表单、Shadow DOM 内控件、附件上传或自动提交 |
| Excel 单记录与映射复用 | 工作表、表头、单记录选择；只发送选中记录；结构映射复用 | 映射绑定同一 origin 与表单结构，表单变化后失效；不证明可跨站点迁移 |
| 模型服务适配 | 13 个服务商选项（12 个预设 + 自定义）、OpenAI 兼容配置、超时、取消、重试和错误分类 | 外部接口与模型目录会变化；预设不保证长期可用或兼容 |
| BYOK 与隐私边界 | 数据直传用户配置接口、Key 本地存储、不采集提交、受控外发说明 | 仍可能发送表单结构、用户说明和导入内容；敏感字段需单独评估 |
| 测试与证据体系 | Vitest、JSDOM、Playwright MV3 E2E、布局与可访问性检查、执行证据归档 | 历史测试只证明当时环境和版本，不等于当前浏览器或外站兼容 |
| 网站与调研材料 | 四页网站源码、竞品与社区研究、SEO 研究、用户画像、演示包 | 均为历史资料；不再执行原定发布、推广和 SEO 计划 |

## 6. 冻结与保留边界

- 功能路线图中的 F07、F08、W07 或任何多模型、PDF/OCR、跨页代理、自动提交、团队云库等扩展。
- 商店材料补全、版本 `0.2.0` 发布、商店账号申请与提交。
- 生产域名购买、网站部署、canonical、sitemap、404、OG、GSC 和线上观测。
- 新内容、社区发帖、付费投放、关键词采样、定价测试和用户招募。
- 针对 M01 访谈、平台预检或垂直交付的继续投入。

### 继续保留

- 全部源码、扩展、网站、测试、演示资料和研究证据。
- 既有 Git 历史、远程仓库和分支，除非项目所有者另行决定归档或迁移。
- 文档中已经披露的 MIT 许可口径；对过往公开材料可能已经形成的授权，本次不主张撤销，实际权利状态仍须核实。
- 已存在的本地构建和测试命令，作为档案复现手段；不构成维护、兼容或发布承诺。

## 8. 重启前的最低条件

本项目不因这份报告自动回到产品路线。若要重新评估，至少先取得以下证据，并从垂直交付、嵌入组件或明确合作渠道开始：

1. **真实重复任务。** 真实用户在一个月内多次执行同类填写，且有页面、时间、字段数和人工基线证据。
2. **可测量的价值。** 在同一初始态、可比较字段集下，包含回源与复核的总耗时或错误率有稳定改善。
3. **明确的数据授权。** 涉及真实个人或企业资料时，已说明模型服务商、字段范围和外发路径，或改用本地模型。
4. **明确的购买与验收。** 有客户愿意为一次适配、维护或嵌入能力签署验收条件并付款，而不只是口头预算或点赞。
5. **明确的责任与渠道。** 已确定维护人、规则更新责任、支持范围和可触达渠道。
6. **可复现的目标页面。** 至少一个目标类型平台完成授权演示与受控写入验证，不使用自建 mock 代替兼容性结论。

满足条件后，应重新做一次独立的产品原点审查，不能直接恢复“通用浏览器插件、订阅制、全渠道推广”的旧路线。
