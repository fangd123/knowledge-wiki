# S02 静态预渲染独立审查（Qwen）

2026 年 11 月 17 日的 S02 审查问的是两件事：不运行 JavaScript 能否读到四页的主文案？打开 JavaScript 后，是否会出现两份正文？当日结论是同意提交本地构建改动，而不是认定网站已经上线。

## 一份 HTML，两次看正文

首页、隐私、安装和 Excel 指南先在浏览器中渲染，再把自有静态文案写入构建产物。读静态 HTML 时，四页都有各自的主句和链接。启用 JavaScript 后，React 重新建立页面而不是接续使用旧 DOM；检查记录里每页只有一个一级标题，指定的正文句只出现一次，没有页面错误。审查的输入是本项目固定文案，不涉及外部投稿或用户输入；这个结论不能移用为其他网站的安全认证。

有个容易误判的地方：视口外的节没有出现在当时读取的可见文本里，却仍在 DOM 内。核对整份文本才分得清“没显示在这里”和“根本不存在”。这能证明**静态文件有文案，浏览器接管后没有重复**；不能推出搜索引擎怎么抓，更不能推出已收录。

## 整体可重复，单步不可重复

当时审查者在本地复跑完整构建：每次先生成干净 HTML，再做预渲染，四页均完成。如果只对已经预渲染的产物再做最后一步，原标记已被替换，脚本会明确报错并停止，而非静默叠加一份正文。审查者建议把两者的区别写进使用说明，不要求取消这项保护。

布局记录有四页 × 九个宽度，36 组无失败；自动无障碍检查亦通过。审查者区分了自己复跑的构建和核读的检查结果。站点地图和规范网址仍依赖生产域名，当时没有真实爬虫结果；参见[冻结时的 SEO 状态](27-[历史]_SEO_与索引准备状态（S01–S05）.md)与[项目交接](22-FormFill_产品收尾与交接报告.md)，线上验证后来没有进行。
