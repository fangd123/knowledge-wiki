## 1. 对照两类工作流，再选择客群、渠道与收入

**候选 A：同一套公司资料，从 `.xlsx`/`.docx` 录入多个合作伙伴的登记网页。候选 B：同一业务网页反复录入多条结构化记录。** 每次由人核对并提交。先研究可用合成资料复现的任务；目标用户有可用模型 API 或团队配置能力。先检查原生 CSV 导入/API 与规则工具是否已经满足，再判断语义映射是否有增量价值。

两者都是假设，尚无访谈证明频率和预算。A 的资料入口匹配但单个网页可能只填一次；B 便于摊薄同站映射成本，但规则工具可能更好。分开记录同一资料的目标网页数量、同一网页的记录数量与发生时间，不用“经常填表”混合二者。试点使用范围按已验证能力确定，不承诺企业级能力。

| 环节 | 围绕候选工作流的验证 |
|---|---|
| 价值主张 | 已有公司资料 → 当前网页字段，减少逐字段复制；由用户选模型，填写后人工核对。节省幅度待实测 |
| 首批获客 | 经允许的中文运营/效率工具交流、Gitee 问题讨论，以及“Excel/Word 资料填网页”的实操搜索；招募确实做此任务的人。开发者社区用于安装和兼容反馈，不能代替买家需求 |
| 产品重心 | 先做到一份明确资料受控填入当前表单；多记录任务必须先选人/公司并防串填，再验证同站映射复用；完整来源追溯按检查收益决定，不先做全自动跨站提交 |
| 收入路径 | 免费自行使用；对反复遇到同类问题的客户，开发并交付指定资料模板 + 指定网页的适配和验收说明 |
| 暂不主攻 | 求职自动投递、家庭医疗资料、PDF/OCR 全能工具、联系人外联机器人；这些会引入不同竞争、风险和交付范围 |

优势应表述为**适合这一工作流的能力组合与可验证服务**，而不是已有技术壁垒。现在没有证据证明 FormFill 比所有同类更快、更准或更隐私。

| [FastFiller 官网](https://fastfiller.aeigs.com/)、[GitHub](https://github.com/mauryaankur99/FastFiller)、[MIT LICENSE](https://github.com/mauryaankur99/FastFiller/blob/main/LICENSE) | 官网称无订阅、无填表次数限制；BYOK、浏览器会话、本地 Ollama；预填审核、撤销、多资料档案均有公开说明。仓库确有 MIT 许可；本轮未验证安装和兼容效果，也不采信“模型零成本”“任意网页”等绝对承诺 | **免费 + MIT + BYOK + 无自有中间服务器已是直接替代。** 预览/撤销也是免费竞品的基础能力，不适合作为主要收费墙 |

相对浏览器地址 autofill，当前区别在于临时文字/文件到业务字段；相对 Text Blaze，区别在于不先为每种内容手工建立 snippet 才做语义映射。相对 FastFiller/Formly，**当前证据不足以断言功能更强**。可争取的选择理由是中文资料的具体演示、清楚的数据流、易排查的配置，以及经开发和验收的指定任务兼容性。中英 UI、GBK 回退、Office 解析是已实现事实，不等于中文场景准确率优势。

## 3. 现在能说、满足什么条件以后再说

| 状态 | 宣传边界 |
|---|---|
| 现在可说 | 开发者预览；公开 MIT 源码；输入自然语言、`.xlsx`/`.docx`/`.txt`/`.md`；配置 HTTPS OpenAI 兼容模型接口；结果写入网页后需要人核对；没有 FormFill 自有后端。安装按钮必须指向真实源码构建说明 |
| 数据流必须同时说 | 文件在本地解析，但解析内容、用户输入、表单上下文会发给配置的模型服务。配置/学习样本本地保存；匹配历史可能参与后续请求。已知默认学习/采集范围问题仍待修复，不能以“隐私优先”淡化它们 |
| 修复并复测后才能说 | 学习仅在独立同意后启用、只取适用表单；数据发送范围可预测；Demo 无残留/异步回写。修复前不进行面向普通用户的大规模推广；修复完成不自动等于通过安全审计 |
| 开发并验收后才能说 | 填前预览/改值/撤销、字段到来源片段、明确选择 Excel 记录、保存任务配置、指定网页适配及回归维护。每一项需真实版本、可复现样例及兼容范围；“来源可追溯”要落实片段定位，不是模型自报置信度 |
| 不能说 | 唯一/市场领先、任意网站、100% 准确、不会猜测、零错误、资料绝不离开设备、本地模型开箱即用、无需 API Key、模型调用免费、自动处理所有 PDF/旧 `.doc`、已上架商店、已有团队后台/SSO/云同步/托管 credits、未实测的省时或 ROI |

错误预防、数据最小化、基础预览/撤销与隐私控制建议进入免费基础能力。付费不应成为用户避免误填或控制外发资料的条件。

## 4. 一条可选收费实验：免费工具 + 有范围的适配交付

**当前：软件使用费 ¥0；用户自行向模型供应商支付 API 费用。** 不设置现有自然语言/四类文件输入/BYOK/本地历史的次数墙。免费不代表推理免费；连接测试、失败重试也可能产生供应商费用。没有托管后端，就不出售“包模型调用次数”的订阅。

**可选价格实验：¥699/个限定工作流，一次性交付，不自动续费。** 仅面向完成重复任务观察、确有适配需求且成本可承担的试点客户；这是待验证的报价假设，不是现有商品，也不是由竞品美元价格换算。先不另立美元套餐；海外需求应单独访谈、报价和验证。适配有人买不等于软件订阅成立，软件权益、分发便利或共性维护需另有需求证据。

为什么不按 token 加价：供应商直接对用户计费，FormFill 不承担推理成本，也无计量结算后端；同一表单的 token 受文档长短、历史样本、模型和重试影响，不能代表用户价值。按次数卡免费 MIT 功能还很容易被自行构建绕过。适配交付则能把价格关联到一个能验收的任务及维护责任。

个人先用免费版；确有特殊表单也可按相同范围买交付，不建虚假的 Personal Pro。小团队以工作流而非席位购买，重复使用不另按人收费。**暂不推出团队 SaaS、共享后台或 ¥/人/月套餐。** 等多个独立客户反复请求同一适配、愿付维护费且支持工时可控，再测试持续更新包；届时才确定周期、金额、交付能力与退出方式。一次性成功不能证明订阅需求。

**第一轮明确报价假设：人民币 ¥699/次项目交付，不自动续费。** 先和目标用户讨论任务、范围与价格，再决定必要新增开发；正式付费交付须相应能力已可试、可验收。范围为一个资料模板、一个已约定网页表单（最多 20 个普通字段，排除 iframe/复杂自定义控件）、一个 Chrome/扩展/模型组合；交付适配配置或代码、合成验收样例与操作说明，含一次不超过 60 分钟的配置指导、验收后 14 天内约定范围的缺陷修正。客户自备 API，模型账单另付；网站结构改变、新模板、新站点不含在原范围，先评估再另报价。若范围内也无法交付则不收款；退款与税费口径需在真实售卖前写清。本轮不收订金、不挂付款链接、不承诺服务已存在。

**报价单必须写明重复价值单元。** 若卖同一表单×多记录，明确记录选择/主体隔离是收款前置，并用两条相似主体的合成记录验证不串填；当前整工作簿上下文不能代替该能力。若卖同一资料×不同网页，仍按每个约定表单交付，先算实际重复收益是否覆盖逐站适配费；内部映射复用不自动变成不限站承诺。报价前设可用开发/支持工时和超限处理，不以 14 天缺陷支持掩盖未完成能力。

验收前固定必填字段、资料和网页版本，用至少三份合成资料走完“填写 + 人工核对”；错误和手动步骤逐项列出，由客户确认是否满足任务，不把一次模型成功当保证。¥699 是待测试的项目价格，不是按成本算出的合理价，也不是已验证的支付意愿；若开发、支持和返工超过可承受范围，必须缩小范围或停止，不用低价许诺无限兼容。先只测试人民币市场，美元市场须另做客群和报价实验，不把 ¥699 换算成美元制造价格锚定。

**许可边界：**根 `LICENSE` 的 MIT 已授予取得现有版本者使用、修改、分发、再许可和销售等权利；不能靠新定价、更新页或安装包许可开关收回。MIT 不禁止收费，继续免费是本阶段产品策略；错误预防、隐私控制、基础预览建议作为免费可靠性改进。若将来另建收费模块，需单独确定新代码许可及贡献者权利；本报告不建议靠追溯改许可实现收入。服务费用买的是实施与约定支持，不是撤销用户已有 MIT 权利。

**年度维护价格：待定。** 原综合报告提出的 ¥199/年缺乏维护工时和持续需求依据，现撤出建议价，仅作历史存档；不是现售套餐，也不以另一个无依据金额替换。

父会话复核：已将工作流范围统一为上一段的**一个资料模板、一个网页表单、最多 20 个普通字段、一次配置指导、验收后 14 天范围内缺陷修正**，删除早期草稿中不同的表单数量和支持期限。交付代码若继续采用 MIT，客户可以合法复用和分发；不能把打包便利或技术限制描述成对既有授权的撤回。

## 5. 开发顺序与付费实验

| 阶段 | 做什么 | 应保留的证据与决策 |
|---|---|---|
| 0：发布基础 | 接续已有审计修复学习/采集范围、格式文案和 Demo；跑通干净环境安装；补真实支持入口 | 安装和风险行为通过专项复测。未完成时只招技术测试者，不卖可信赖的业务交付 |
| 1：观察重复任务，与基础修复并行 | 招 5–8 位自愿用户，尽量覆盖 A/B 两种候选；先观察手工和原生导入/规则替代，再用同等难度合成资料试验；实际有任务时回访。真实业务试用须预览/已有值保护/有限撤销已完成 | 分别记录配置时间、操作+核对+纠错总时间、需改字段、任务频率和失败原因；没遇到下一次任务记“未观察”；不承诺固定两周内发生复用 |
| 2：只开发重复出现的缺口 | 免费控制基础先完成；多记录任务先补选记录和隔离；再按实际阻力选映射复用或最小来源检查。已有替代足够就不为收费重造 | 资料/网页版本、选定模型、结果和维护工时；映射依赖稳定来源/目标定位，不依赖完整 Word 追溯；准确性问题先修，不成为付费升级理由 |
| 3：真实付款验证 | 同一明确范围向 3–5 位有已观察需求的人报 ¥699；交付可试版本后按清单验收并真实付款。访谈愿付金额、预约和点赞均不计收入 | 记录“符合条件/收到报价/完成试用/验收/实付/退款/拒绝理由”的原始人数；不要把所有网站访问当分母。这里的样本量是工作计划，不是显著性设计 |
| 4：决定是否继续 | 可事先约定：至少两个互不关联客户实付、实际复用，且每单贡献覆盖可用工时，才继续同一产品方向；否则先核实价值、门槛或范围 | 这只是内部决策门槛，不能宣传转化率已统计验证。若无复用就不年付；若免费功能足够就不强推适配；若支持过重就不卖维护承诺 |

不要同时分成 ¥299/¥699/¥1,499 三组做“小样本 A/B”。先固定任务、范围和价格，记录真实购买阻力；若改价，标记新一轮条件和原因，不比较成因果价格弹性。任务价值也应考虑“手工更快”“模型配置太难”“网站完全不兼容”等失败结果。

先用自愿回访和用户自己保留的任务记录评估，不悄悄给无追踪扩展加遥测。不采集文件正文、Key、姓名、目标网页中的资料；研究材料只保留匿名任务类别、耗时与合成失败例。是否上线网站聚合统计是另一个透明决策。

## 6. 经济约束：先测工时，再谈利润或 ROI

**下面是可填入真实数据的公式，不是已经测得的成本或收益。**

```text
用户单任务净收益 = (手工总分钟 − 工具操作/核对/纠错总分钟) ÷ 60 × 用户认可的时间价值
                 − API 实际费用 − 分摊的交付费用
单笔交付贡献 = 实收款 − 支付/退款/税费 − 实际开发与支持工时 × 内部小时成本 − 其他直接成本
维护周期贡献 = 维护收入 − Σ(网站变更次数 × 单次修复工时 × 小时成本) − 发布/支持成本
获客成本 = 同口径现金与可归属获客工时成本 ÷ 新增实付客户数
可用交付工时 = (报价 − 税费/支付/退款准备 − 其他直接成本 − 目标贡献) ÷ 内部小时成本
```

时间价值由用户提供，不能把工资换算一律当能兑现的现金节省。API 费用读供应商账单并记录模型、请求大小、重试，不用竞品 credit 作代替。收入周期与成本周期一致；没有付款客户时 CAC 无法计算，不能报零。没有持续收入与留存数据时不报 LTV 或回本周期。

维护压力来自网页 DOM/控件、级联字段、SPA 更新、模型输出、浏览器权限/API 和资料模板变化；支持每种模型/网站都会扩大成本。先维护少数公开可复现的范围，按版本列“验证过/有限支持/不支持”，不要把可扫描 open Shadow DOM 写成复杂控件全兼容。

MIT 绕过付费是合法替代，无法靠前端许可开关建立收费壁垒；付费理由应是交付速度、可信验收和有限支持。未来即使有人复制适配，也不代表可阻止其再分发；若客户只愿买一次服务，应按项目生意核算，不虚构高毛利 SaaS。免费竞品与供应商免费层也会压低通用填表的支付意愿。

## 8. SEO 用来找到这类任务，不用便宜关键词定义产品

首批只做能提供实际资料、真实结果和限制的主题；下面是主题优先级判断，**没有关键词月量、CPC、KD 或排名证据**。

| 顺序 / 主题 | 独有内容与转化动作 |
|---|---|
| 1：Excel/Word 公司资料填写网页登记表 | 合成文件 + 样例网页 + 真实结果；说清 `.xlsx`/`.docx`、一条记录、人工核对、无自动提交。引导试用同一任务 |
| 2：中文资料字段名不同如何对应 | 同一家公司在两个不同标签表单上的实测、失败和手动处理；若没测成功，作为排障记录，不建虚假行业落地页 |
| 3：BYOK 配置与数据流 | HTTPS 地址、测试连接、常见 401、模型账单、历史样本如何参与请求；降低本工作流的配置流失 |
| 4：AI 语义映射、浏览器 autofill、表格规则匹配如何选 | 同输入同任务比较，承认固定字段/确定性场景的规则方案可能更优；Formly/FastFiller 的金额和功能只写有日期的来源事实 |

`free AI form filler` 可在核心页 FAQ 如实答“软件免费、API 另计费”，无需做大量“free/cheap/unlimited”近义页面来吸引只要免费模型的流量。不要为排名添加未实现 PDF、招聘自动投递、每个行业或每个竞争品牌的薄页。中英文围绕同一任务完整本地化，而不是先扩几十篇英文列表。

评价 SEO 的顺序是：真实相关 query → 阅读任务样例 → 安装/配置 → 首次成功 → 自愿报告复用 → 符合条件的适配询问/实付。出站点击不是安装，访问不是买家，GSC 曝光不是市场搜索量。先补正式域名、可索引页和准确获取路径，技术细节接续已有 SEO 报告；未知指标继续留空。
