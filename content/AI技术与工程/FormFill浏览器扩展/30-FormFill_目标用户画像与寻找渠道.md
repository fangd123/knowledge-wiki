# FormFill 目标用户画像与寻找渠道

更新日期：2026-11-17；2026-11-18 标为历史。本文记录冻结前关于“谁可能使用、去哪里找他们”的研究，**不是已验证的用户研究结论**。画像基于当时能力约束（BYOK、预览确认、单记录、不自动提交）、[产品策略](38-FormFill_产品差异化、定价与推广决策.md)和[产品原点与场景方向重估](54-FormFill_产品原点与场景方向重估.md)。原计划的 M01 访谈与招募已随产品化停止而取消；公开平台手册和招聘样本只能证明任务线索，不能证明频率、付费或配置接受度。

## 0. 冻结前的硬约束研究

以下是冻结前对“谁会留下、谁会走”的判断，不是当前招募标准：

| 约束 | 筛掉谁 | 留下谁 |
|---|---|---|
| 自备模型 API Key（BYOK），需自行申请、充值、填 Base URL；本地 Ollama 例外（免 Key，http://localhost 合法） | 没有技术能力也不愿学的纯业务人员；以为"下载就能用"的人 | 已有 API Key 的开发者/技术爱好者；团队里负责配置工具的人；跑本地模型的玩家 |
| 冻结前技术样机：需 clone 构建、开发者模式加载且从未上架 | 只从商店安装的普通用户 | 能运行 npm 并理解项目已归档的人 |
| 每条记录需人工选择、预览、确认应用；不自动提交、不无人值守批量 | 想要"一键投一百份"的自动化需求 | 接受"AI 干活、人把关"的半自动录入者 |
| 不支持 PDF/OCR、iframe 内表单、Shadow DOM 内控件 | 扫描件录入、部分招聘站/内嵌表单用户 | 标准网页表单（input/select/textarea）用户 |
| 数据直发用户配置的模型接口 | 要求数据完全不出浏览器的人 | 接受"直发自己选的服务商、不经开发者服务器"的人 |

**冻结前的判断是最匹配人群为“有 API 配置能力 + 有真实重复录入任务”的交集。** 原计划等上架和上手流程改善后再扩大范围；上架和招募均未发生，扩大计划已取消。

## 1. 画像一（第一业务验证）：多平台 B2B 供应商的投标/商务专员

**一句话**：在工业品、制造业或企业服务供应商里，反复把同一份企业主档录进不同央国企、大型企业和行业采购平台的人。

- **典型身份**：投标专员、商务专员、销售支持、渠道运营；内部 IT/信息化人员负责协助安装和模型配置。
- **优先任务（白名单）**：供应商注册、入库、资料更新/年检、大客户 SRM 档案维护中的**纯主体信息表单字段**。附件上传、CA 认证、资格预审文件、投标响应与递交一律留人工或平台工具（黑名单见方向重估 §0）。
- **为什么比一般“填表的人”更值得先找**：公开岗位样本把多平台注册、更新、年检和 SRM 档案维护列为正式职责，且明确跨多个组织平台。注意：公开页面结构抽样来自高校/交易所/信息服务商，目标类型平台样本为 0，**不构成技术可达证据**；频率、付费同样未知。排序是判断口径，详见[方向重估](54-FormFill_产品原点与场景方向重估.md) §4。
- **已有资料**：公司主档 Excel/Word、资质清单、联系人、业绩等；最适合先整理成“一行一公司、一列一字段”的合成主档。**身份证号、银行账号等个人/金融敏感字段默认排除**（BYOK 直发所选模型接口），仅本地模型或明确脱敏前提下个案评估；M01 不采集真实值。
- **当前替代**：手工复制、平台 OCR/主体库、**信用代码→工商数据自动带出**、**平台一键带入历史/已填资料**、**代办/代入驻服务商**、专用投标客户端、企业资料库、RPA/定制脚本。已有替代足够好的平台不强推 FormFill；价值口径是**扣除平台自动带出后剩余字段**的转录与复核成本（见方向重估 §5）。
- **选择理由假设**：跨组织平台的字段叫法和结构不同，逐站写规则成本高；预览、已有值保护、单主体隔离和撤销可减少复制与复核负担。**映射复用只在同站同结构生效**（同平台更新/年检、同页多记录），平台改版即失效，年检间隔长；复用命中率与跨平台首次映射成本在冻结时均未验证，不作跨平台卖点。
- **关键障碍**：每个平台是否只填一次；附件、搜索下拉、级联、iframe 和多步流程；敏感资料能否发给所选模型；未上架与 BYOK 配置。
- **付费潜力**：业务主管/老板可能为可验收的重复任务付配置与适配费，操作者未必是预算人。¥699 在冻结时只是单模板×单网页×≤20 普通字段的报价实验（“字段”按方向重估 §3 逻辑字段口径清点，不按控件数）；该实验从未启动，随后取消。
- **原候选渠道**：曾计划从工业品、仪器仪表、新材料、设备和企业服务供应商的人脉、招投标/采购培训及行业协会社群寻找访谈候选；未联系任何人，也未招募或群发消息。
- **原话术假设**：曾拟先询问供应商平台数量及 OCR/主体库覆盖，再展示合成企业主档的预览流程；该话术未使用，也不会宣传自动投标或避免废标。

多客户投标服务商不是首选：据 E10 市级转发指南，部分平台对授权经办、机器码和独立投标设有风控（具体条款在冻结时未完成原文核对）；排除理由主要是**平台规则不确定性**而非已证条款。当时原计划只在合法授权、平台允许的登记辅助范围内访谈；该访谈未执行，不把多客户共用设备完成投标作为使用场景。

## 2. 画像二（首发协作与技术反馈）：技术型重复录入者

**一句话**：自己有模型 API Key，能帮助画像一安装、配置并提供真实任务反馈的开发者、技术爱好者或企业 IT。

- **典型身份**：独立开发者、接外包的小团队技术负责人、贸易公司的"懂技术的运营"、企业里帮业务部门做工具的 IT/信息化人员。
- **年龄段**：25–40 为主（假设，无样本证据，招募不作硬筛）；**语言**：中文优先（国内服务商预设+豆包默认是真实差异点），英文次之。
- **任务形态**（对应策略候选 A）：同一份公司/客户资料，填进多个不同伙伴的登记页、供应商入驻页、平台开店资料页（仅其中纯主体信息字段，身份证号/银行账号等敏感字段按白名单默认排除）；或（候选 B）同一个后台页面，逐条录入客户/商品/员工记录（**敏感口径同 §0**：身份证号/银行账号/成绩等高敏字段默认排除、不进 BYOK 真实值路径，仅非敏感记录类型或满足本地模型/外发批准前置时纳入）。
- **现在的做法**：手动复制粘贴；或自己写过油猴脚本/Python 脚本但维护烦；或用过 Text Blaze 但每条资料都要先编模板。
- **痛点**：字段叫法每个网站都不一样（"联系人"/"负责人"/"Contact Person"），规则工具要逐站配置；复制粘贴慢且容易串记录；担心把客户资料传给不明第三方后端。
- **冻结前选择理由假设**：相信语义匹配可以省去逐站写规则；预览+已有值保护+撤销让"AI 填错"可控；单记录隔离不串客户；**同站同结构**映射复用第二条起免模型（快、零成本；跨站首次填写仍调模型）；数据直发自己的 Key；源码可审。上述理由均未经真实用户验证。
- **角色边界**：他可以是早期使用者和配置协作者，但不能代替画像一证明业务频率和付费；¥699 实验的真实决策者在冻结时尚未核实，该实验随后取消。
- **原候选渠道**：
  - 曾考虑 V2EX、掘金、少数派、即刻独立开发者相关圈子；
  - GitHub/Gitee 上同类开源项目（filly、xlsx2form-chrome、AI-form-filler-crx 等）的 star/issue 用户——填表需求的高意向访谈候选（注意 xlsx2form-chrome 是规则工具非 BYOK，需求形态需访谈区分）；
  - r/chrome_extensions、r/SideProject、HN Show HN（英文，技术反馈为主）；
  - 独立开发者社群（如出海/独立开发微信群、Indie Hackers）。
- **原话术假设**：曾拟以“一份 Excel 客户表 → 多个供应商登记页”讲任务，并说明预览/撤销、映射复用、自备 Key 与模型费用；未执行。

## 3. 画像三（业务价值扩展）：其他小 B2B 团队的运营/销售支持

**一句话**：不会配 API，但每月真实发生"把公司资料录进 N 个伙伴网页"的运营、商务助理、销售支持。

- **典型身份**：贸易/物流/SaaS 代理/企业服务公司里的运营专员、商务助理、渠道管理员；外贸公司的单证/跟单员。规模不限定为原假设的 10–50 人，以任务为准。
- **任务形态**：供应商入驻登记、渠道伙伴申请、平台开店资料、招投标报名中的**纯主体信息表单字段**（不含附件上传、CA 认证、投标文件与协议/同意类勾选；身份证号/银行账号等敏感字段默认排除，见方向重估 §0 白名单），以及展会/活动报名中同样受上述白名单/黑名单限定的主体信息字段——同一份营业执照+联系人资料，反复填不同网页。
- **现在的做法**：Word/Excel 存一份"标准资料"，每次打开对照复制；填错被平台驳回再返工。
- **痛点**：重复、枯燥、易错（电话/统一社会信用代码抄错一位就被驳回）；没有 IT 支持；不敢把公司资料传到陌生网站。
- **冻结前选择理由假设**：预期预览确认+已有值保护对应"怕填错"，资料只发自己公司配置的接口对应"怕泄露"；该价值判断未通过真实用户验证。
- **关键障碍**：**API 配置就是他的门槛**。原评估认为他不会自己申请 Key，需要画像二协助或托管/引导方案；托管方案从未实现，原自助获客计划也已取消。
- **历史付费假设**：原计划以 ¥699/次适配交付验证（一个资料模板×一个表单×≤20 个白名单逻辑字段）；该报价实验从未启动，不再执行。
- **原候选渠道**：
  - 曾考虑通过画像二转介业务同事/客户；
  - 外贸/跨境电商社群（福步论坛、米课圈、跨境电商微信群）里抱怨"重复录入"的人；
  - 脉脉/知乎"运营每天重复填表"类话题的答主与评论者；
  - 本地中小企业主社群（商会、行业协会活动）。
- **历史触达研究**：原话术以任务频率和现有做法为起点，并拟以“帮你配好一次”验证交付价值；尚未执行，冻结后不再招募或报价。

## 4. 画像四（技术反馈与传播，非商业验证）：开源/隐私敏感玩家

**一句话**：关注 BYOK、本地存储、源码可审的开源爱好者与隐私敏感用户。

- **典型身份**：开源贡献者、self-hosted 玩家（Ollama 本地模型用户）、效率工具博主。
- **价值**：给安装/隐私/兼容性的高质量反馈；写测评带来早期曝光；Ollama 用户是"数据不出本机"叙事的天然受众（注意：本地模型也走 HTTP localhost，需如实说明）。
- **局限**：点赞/star 不等于业务复用与付费（策略报告明确：角色要分开）。不要把他们当商业路线的验证样本。
- **原候选渠道**：曾考虑 GitHub/Gitee 同类项目讨论区、r/selfhosted、r/LocalLLaMA、HN、V2EX 和少数派投稿；未联系或投递。
- **原沟通假设**：曾拟展示数据流图、权限理由和源码链接；未执行任何发帖或投稿。

## 5. 明确不追的人群（避免错误预期）

| 人群 | 为什么不追 |
|---|---|
| 求职者（一键海投网申） | Simplify 等已占位（竞品调研结论，见 2026-11-16 审计报告；市占率未核）；自动投递不在产品范围；本产品不支持 iframe/复杂控件，招聘站兼容未系统实测 |
| PDF/扫描件录入 | 无 PDF 输入与 OCR，关键词表已列排除意图（K19/K39） |
| 想要无人值守批量提交 | 冻结前定位是“每条人工确认”；原计划 F08 批量队列需高频证据才立项，但从未立项，冻结后不再评估 |
| 只填姓名地址的轻度用户 | 冻结前判断：浏览器原生自动填充已够，AI 无增量价值 |
| 涉密、医疗/金融高敏资料（含身份证号、银行账号字段），或 CA 签章/投标文件递交 | 不属于当前普通资料录入范围；敏感字段仅本地模型/脱敏个案评估；普通供应商网页登记只用合成或明确授权资料验证，不自动提交 |
| 跨境核心商品刊登/订单批量处理 | Amazon 等有表格路径，店小秘/马帮等 ERP 已有批量能力；只保留无原生通道的具体长尾网页 |
| AI 写标书、清单计价、自动投标 | 专用编标/CA 客户端与平台规则已存在，当前产品不覆盖，也不作为方向 |

## 6. 历史 M01 访谈设计（未执行）

以下仅保留冻结前的访谈提纲与证据门槛，不是招募或执行清单。原 M01 已在产品化停止时取消；任何重启须先满足[产品收尾与交接报告](22-FormFill_产品收尾与交接报告.md#8-重启前的最低条件)。当时的候选问题包括：

1. 上个月实际做过几次这类录入？每次多少字段？
2. 复制、核对、纠错各花多久？（总耗时=操作+等待+检查+纠错）
3. 现在用什么替代（手工/CSV 导入/API/规则工具）？为什么不够？
4. 是"同一资料填多个网页"还是"同一网页填多条记录"？各占多少？
5. API Key 对你是否是障碍？谁帮你配？
6. 谁批准付费？为一次适配付 ¥699 的接受度？
7. 愿意提供合成（脱敏）复现样例吗？

对画像一还要追加：逐字段三分记录——**平台已自动带出**（OCR、主体库、信用代码工商带出、一键带入）/ **必须人工且非白名单**（附件、CA、自定义组件、敏感排除字段、协议/同意勾选）/ **FormFill 可填**（radio/checkbox 标未证），成因无留证的 readonly 与疑似日历控件另记未判定类，给出第三类字段数与耗时占比；代办服务是否更省心？入库、更新、年审各自多久再发生一次？对老后台录入者还要检查 iframe、ActiveX、扩展安装权限和 RPA 替代。
