# ch00. 入门预读

> 本书从可验收的计算服务出发，比较采购、供给组织、激励与支付制度。先区分文本词元、服务用量、预付权益和支付资产，再判断是否需要额外的流转安排。动态资料的观察日期见各章与 [附录 C](02-附录_C._核心文献、行业规范与实证数据源汇编.md)。

## 0.1 大语言模型：从软件工具到可调用服务

大语言模型通过训练获得参数，在推理时根据上下文生成输出。模型服务可以按席位、调用次数、输入输出词元、容量时段或任务成果收费；按量 API 只是其中一种商业模式。传统软件也有云资源、带宽和人工支持等边际成本，因此“传统软件零边际成本、LLM 严格线性成本”不是可靠的二分法。

企业真正采购的是可用的业务结果。一次推理耗费电力与 GPU 时间，不代表其输出正确、有用或可以替代同等人类劳动。应把模型账单、质量验证、人工返工和业务损失放在同一核算边界。

## 0.2 Token：特定模型与账单中的计量单位

文本 Token 是分词器产生的离散符号，可能对应整词、子词、字符或字节。某一模型/API 可以有明确的计量规则，但它不是跨模型恒定的能量、FLOPs 或智能单位。多模态模型还采用图像、音频等专门的编码与计费规则。

英文“约四个字符一个 token”只能作粗估；中文、代码、数字和不同 tokenizer 的比例差别很大。不能把“一个汉字约 1.5 token”用于所有模型。预算可先估算，结算及模型对比必须采用指定版本分词器或 API 返回的 usage 数据。

### 四个必须区分的对象

| 对象 | 示例 | 经济含义 |
|---|---|---|
| 文本词元 | 模型输出序列中的一个 token | 信息表示，不是可持有的支付资产 |
| 服务用量 | 本次消耗 6,000 输入 token | 计费数量；与模型、方向、缓存状态绑定 |
| 预付服务权益 | 账户预付余额或固定次数服务券 | 受合同约束的请求权，存在到期、退款和履约条件 |
| 支付资产 | 银行存款、USDC、TAO | 分别属于不同货币或加密资产安排，与文本 token 无直接同一性 |

“USD 3/百万 token”中，美元是记账单位，token 是服务数量单位，如同“元/千瓦时”中的千瓦时不是货币。购买一美元余额也不等于买到固定数量的未来 token。

### 输入、输出与缓存的计费

输入预填充通常可批量并行，输出解码常有顺序依赖；但实际成本取决于模型架构、批量、上下文、硬件利用率和缓存。MoE 不必每步激活所有参数。输出价高于输入价是常见商业定价，不能由此推出固定 3–5 倍的物理成本定律。

以下只是可复算的教学示例，不对应当前某家模型报价：

- 输入 6,000 token，输入价 USD 2/百万 token；
- 计费输出 750 token，输出价 USD 8/百万 token；
- 模型账单 = $6000\times2/10^6+750\times8/10^6=\$0.018$。

若另有收费推理词元、缓存写入/存储、搜索、音频或平台费，应按各自规则加入。不要把已包含在 output usage 中的 reasoning tokens 再加一次。完整计算见 [ch16](19-ch16._跨模型任务成本：完整账单、验收与迁移条件.md)。

## 0.3 API：智能机器经济的互联总线

API 是软件调用服务的接口；API Key 是访问凭证，不一定是加密后的字符串，更不是可自由转售的服务资产。机器可以通过 API 自动采购和记账，也可以采用月结、批量净额结算或企业预算账户，不必每调用一次就发生一笔链上交易。

例如采购 Agent 可以自动检索报价、起草订单，再由确定性权限系统验证预算与审批条件。模型负责建议或编排，支付权限由账户持有人授予；Agent 通常不是独立法律主体。

## 0.4 加密货币与稳定币：可编程结算层

加密资产可借助分布式账本转移，但网络确认、法律最终性、商户履约与退款是不同问题。法币支付同样可以通过 API、自动扣款或实时支付系统编程执行，区块链不具有“自动支付”的排他性。

稳定币试图锚定某种参考价值，并不保证永远按面值成交。以法币储备型产品为例，兑付取决于发行人、合格持有人条件、储备管理及适用法律；脱锚、冻结、托管和操作风险仍然存在。USDC 与 USDT 的资格和条款不能相互替代，“合规稳定币”也不是全球统一许可证。

本书讨论的可行组合是**按 token/请求/任务计量、用法币记账，并按客户可用的支付轨道结算**。稳定币只是其中一种选择，并不是“算力本位”的必需条件。参见 [ch04](07-ch04._概念坐标系：异构服务的四项交易坐标.md) 与 [ch06](09-ch06._服务契约的四组约束：计量、权利、漂移与归责.md)。

## 0.5 智能体（AI Agent）：受托执行的软件系统

Agent 可以拆解任务、调用模型和工具、维护状态并执行获授权的行动。其两类支出应分账：

1. 完成分析与编排的计算成本；
2. 购买数据、服务或实物的外部支出。

采购价值一万元的商品，不等于产生一万元 AI 服务收入；这一区分是 [ch10](13-ch10._市场边界：从客户任务到可获得收入的测算.md) 避免重复计数的起点。机器支付还需要幂等键、预算预占、超时处理、对账和争议证据，不能仅靠提示词中的“不要超支”。

## 0.6 产业核心参与者格局（2026 演进视角）

| 环节 | 示例 | 需辨明的边界 |
|---|---|---|
| 模型及托管 | OpenAI、Anthropic、Google、DeepSeek、Qwen 等 | 模型能力、托管服务、API 定价是不同对象 |
| 聚合与治理 | OpenRouter、LiteLLM、TensorZero 等 | 路由不自动构成做市，也不保证节省成本 |
| 支付交互 | x402、Tempo 与 Stripe 的 MPP | 协议不等于结算资产或支付牌照 |
| 受托授权 | AP2 | 授权证据不等于商业纠纷的法律裁判 |
| 去中心化网络 | Bittensor、Akash 等 | 网络代币价格不等于真实服务收入 |

[MPP 的官方发布](https://stripe.com/blog/machine-payments-protocol)日期为 2026-03-18。生态和版本细节见 [ch05](08-ch05._生态地图：全球计算经济与支付结算全景透视.md)，不以项目出现的数量推断市场份额。

## 0.7 核心术语与缩略语对照

- **TPM / RPM**：每分钟 token / 请求速率限制，不等于实际吞吐保证。
- **GMV**：交易总额；需说明哪些交易纳入、是否去重。
- **ARR**：经常性收入的年化指标，不等于已确认年度收入、净利润或现金到账。
- **预付权益**：未来服务请求权；未使用余额通常还对应提供方的履约义务。
- **任务有效成本**：在明确质量、时限和失败处理规则下的交付成本。

完整定义见 [附录 A](01-附录_A._核心术语与经济学概念对照表.md)。

## 0.8 全书核心研究命题概要

本书的共同问题是：**在同等质量、履约和风险约束下，候选制度能否比现行法币采购降低采购、履约与交易的总成本，或带来足以覆盖新增成本的服务价值？** “现行采购”包括客户已有的人工流程、直连 API、云合同与治理工具，不是假设什么都没有的空白市场。

分析按三个环节推进：先定义任务与验收，建立成本和契约边界；再比较供给、核验、授权及支付安排；最后检验客户是否采用、经营者能否持续交付。服务券和货币化只在特定接受与兑付需求下进入比较，不是必经阶段。

## 0.9 贯穿案例与三项采购工具

**教学任务队列，不是客户实测：**设一家企业需要核验一批获合法授权的技术报告，交付引用与数值不一致清单、可追溯来源以及专家处理的未决事项。事先规定任务范围、重大错误、截止时间与最终验收规则。比较现行人工流程、单模型加人工复核、多模型路由加人工复核；所有方案处理同一批任务，失败与放弃记录不得删除。初始沿用法币采购和现金报酬，不预设积分、专用指数或金融合约。

### 工具一：从用量到完整账单

若互不重复的词元计费类别为 $j$，数量为 $n_j$，单价为 $p_j$ 美元/百万 token，则：

$$C_{\text{bill}}=\sum_j\frac{n_jp_j}{10^6}+C_{\text{non-token}}$$

$C_{\text{non-token}}$ 汇总尚未包含的工具、存储、平台等账单项；缓存、reasoning 与折扣按供应商规则映射，同一费用只计一次。它仍是服务账单，不是企业完成任务的全部成本。完整映射见 [ch16 §16.3.1](19-ch16._跨模型任务成本：完整账单、验收与迁移条件.md#16.3.1%20通用逐次调用费用)。

### 工具二：从账单到最终验收任务成本

$$\widehat{EC}=\frac{C_{\text{all tasks}}}{N_{\text{accepted}}}$$

分子包括队列全部任务的调用、失败、重试、工具、自动核验、人工与运维，成本桶互不重叠；分母是最终满足预定规则的任务数。须同时报告验收率、重大错误和时限，不能靠拒绝难题压低成本；分母为零时该指标未定义。完整处理政策与成本分桶见 [ch16 §16.3.4](19-ch16._跨模型任务成本：完整账单、验收与迁移条件.md#16.3.4%20通用有效成本：全量成本除以最终验收任务数)。

### 工具三：从单位节约到迁移决策

两方案满足相同交付与风险约束，预计需要交付 $N$ 个可比合格任务，单位运行成本为 $EC_A$、$EC_B$，另有一次性迁移费用 $F_{\text{migration}}$：

$$N(EC_A-EC_B)>F_{\text{migration}}$$

才说明该周期的成本节约覆盖迁移费用；迁移费不得已摊入单位成本后再加一次。任务量、成本和验收结果不确定时须报告区间与敏感性。若候选方案主张更高业务价值而非降本，还需客户支付意愿或损失改善的独立证据。完整条件见 [ch16 §16.4.1](19-ch16._跨模型任务成本：完整账单、验收与迁移条件.md#16.4.1%20固定迁移费用必须与任务量对应)。

后文始终问同一件事：新增组件是否改善这批任务的交付或风险，收益是否覆盖新增义务？“只改核验流程，不发券、不建指数”也是完整结论。
