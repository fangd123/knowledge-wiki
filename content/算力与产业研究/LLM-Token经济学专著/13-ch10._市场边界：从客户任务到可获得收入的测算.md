# ch10. 市场边界：从客户任务到可获得收入的测算

> 本章接 [ch11 的客户任务卡](14-ch11._垂直任务筛选：客户需求与核验流程的五项检查.md)，检查候选业务可能覆盖多少客户、交付多少任务、确认多少收入。已发布预测、教学输入与已实现收入分开；规模用于约束上限，不证明客户采用或产品优越。

## 10.1 规模测算的第一性纪律

| 指标 | 含义 | 不等于什么 |
|---|---|---|
| Influenced GMV | 受 AI 辅助决策影响的商品交易额 | 不一定由 Agent 下单或付款 |
| 实际交易 GMV | 按规定边界计入的商品或服务成交额 | 平台收入、利润或现金余额 |
| 已确认营业收入 | 按履约与会计政策确认的对价 | 收款额、预付款或年化速率 |
| ARR | 按定义年化的经常性收入指标 | 已实现全年收入或经审计净收入 |
| Run-rate | 最近某期间数据的年化外推 | 已锁定收入或未来预测的保证 |
| 资本开支 CapEx | 购建长期资产的支出 | 同期模型 API 或软件收入 |
| 代币市值 | 代币价格乘相应供给量 | 外部服务需求、收入或可兑付现金 |

“净收入”还可能表示扣除退货后的收入、代理佣金或其他口径，必须逐家定义。API 转售额、下游应用收入与上游芯片收入不能直接相加后称为最终需求。

铜消费量乘价格得到的是一次终端消费价值的近似，不是含多次转手的全产业链 GMV；信息服务的收费率则须由合同、竞争和实际客户行为确定，不能从实物消费价值类推。

## 10.2 外部预测只作边界参照

截至 2026-11-15，可确认出版商公开披露的两组例子如下（2026-11-17 复核仍在线且数字口径一致）。它们描述不同对象，不能拼成一个已校准总市场；完整来源状态与未采用的输入集中于 [附录 C](02-附录_C._核心文献、行业规范与实证数据源汇编.md)。

| 来源 | 披露数字 | 测算时的用途与边界 |
|---|---|---|
| [Grand View Research](https://www.grandviewresearch.com/industry-analysis/enterprise-agentic-ai-market-report) | 2024 年 USD 2.6B；2026 年估计 USD 5.3B；2030 年预测 USD 24.5B；CAGR 46.2% | Enterprise Agentic AI 的出版商估计，2026-11-17 复核一致；不能擅自缩窄为纯软件许可净收入，完整统计边界须查报告 |
| [Juniper Research](https://www.juniperresearch.com/press/agentic-commerce-set-to-generate-15-trillion-globally-by-2030-as-payments-infrastructure-leaders-revealed/) | 2030 年 USD 1.5T | 2026-04-07 官网新闻稿确认 agentic commerce spend 预测，2026-11-17 复核仍在线且数字一致；这是商业支出，不是支付服务商收入，公开摘要不足以断言其是严格已清算流水口径 |

出版商确实发布过预测，不代表预测已经实现。2026-11-17 复核另证实两组出版商原文：[McKinsey（2025-10-17 报告）](https://www.mckinsey.com/capabilities/quantumblack/our-insights/the-agentic-commerce-opportunity-how-ai-agents-are-ushering-in-a-new-era-for-consumers-and-merchants)预测 2030 年 agentic commerce 全球 USD 3T–5T（美国 USD 900B–1T），脚注注明为早期估计、**仅含商品零售，不含服务与 B2B**；[Deloitte US（2025-09-18 文章）](https://www.deloitte.com/us/en/Industries/financial-services/articles/how-agentic-ai-is-transforming-e-commerce-and-commerce-payments.html)给出 2030 年“最高 USD 17.5T”的上限情景。它们与 Juniper 的 USD 1.5T 统计对象和口径不同，量级差异主要反映边界设定，不能取平均、也不能选最大者当总市场；来源细节与仍未核实的输入见[附录 C](02-附录_C._核心文献、行业规范与实证数据源汇编.md)。候选服务的自下而上估计与外部预测差异较大时，应先检查对象、时期和统计范围。

## 10.3 六组方案的收费基数与可获得收入

TAM 是理论总市场，SAM 是在产品、客户和地域约束下可服务部分，SOM 是结合渠道、产能和竞争可获得部分。用任意市场乘任意份额，只能得到情景算术，不能自动得到可实现 SOM。

六组方案可以叠加在同一笔客户支出上。应用购买路由、账户或分布式供给时，要按 [ch09](12-ch09._价值链分布：利润池结构、议价权与演化迁移.md)剔除中间交易重复，不能把六行潜在收入相加称为终端总市场。

### 方案一：垂直核验服务

可先按客户底层业务量估计：

$$R=N_{\text{eligible customers}}\times a_{\text{adoption}}\times T_{\text{paid tasks/customer/year}}\times P_{\text{recognized revenue/task}}$$

重复客户、赠送任务、退款和人工交付上限须处理。假设 USD 1T 专业服务支出有 5% 转为本产品，再获 0.5%–1%，算术上是 USD 250M–500M；但这三项都是未经验证的输入，不能据此宣称平台具备该 ARR。

### 方案二：路由与治理网关

设 API 支出为 $M$，第三方可收费路由份额为 $\alpha$，综合留存费率为 $f$，厂商份额为 $s$：

$$SAM_{\text{fee}}=M\alpha f,\qquad R_{\text{firm}}=M\alpha f s+R_{\text{separate software}}$$

软件费仅在未包含于 $f$ 时相加。仅作教学假设，若 $M=\$35B\text{–}\$50B$、$f=5\%$，在所有支出均可收费路由的上限下费用池为 **USD 1.75B–2.50B**；实际计算仍须乘 $\alpha$。

若仅作教学假设，$\alpha=20\%$，行业费用池为 **USD 0.35B–0.50B**；厂商份额再假设为 $s=10\%$，则费用收入为 **USD 35M–50M**。这些不是 2026 年已观测规模，也不能直接称净利润或 ARR。

### 方案三：采购风险管理

可用敞口乘覆盖率和服务费估计收费规模，但名义本金、客户实际成本风险与收入不同。教学假设 $250B\times(15\%\text{–}25\%)\times(1\%\text{–}2\%)$ 的区间乘积为 **USD 0.375B–1.25B**，须注明币种与年度收费期间。

这仍只是情景。对冲、融资、保证金和尾部赔付成本可能显著侵蚀费用收入，容量保障也须另核算。

### 方案四：服务券与可转让权益

流通余额是存量，转账额是流量，兑付服务收入与发行费又是不同口径。不能把“百亿美元市值 × 1%–3%”自动当成年收入，除非说明收费依据、频率、兑付和会计确认方式。

### 方案五：分布式专业服务

用独立客户已付款、已交付的服务收入计算，并剔除补贴、自交易与代币市值变化。网络规模应能对应可审计客户与履约记录。

### 方案六：账户与支出控制

若假设年度交易基数 USD 1.5T、可承接份额 5%、留存费率 0.5%–1.0%，算术结果为 **USD 375M–750M**。须再验证服务范围、支付通道成本、客户采用和是否重复收费；交易费收入不是天然的订阅 ARR。

## 10.4 机构收入锚点的使用纪律

机构披露只在范围匹配时才是规模锚点。例如，聚合商调用流水、手续费收入和订阅收入应分列；年度收入与最近月份年化速率不能作为同一口径的两个样本。

后续更新每条应记录：来源日期、统计期间、币种、收入组成、总额或净额列报、是否经审计、是否管理层或媒体估计，以及重估历史值的原因。订阅加 API 的公司收入不能直接等于全球 API 市场。

## 10.5 中国本土市场的估计与业务边界

国内计费币种、优惠、开放权重、自建部署和云打包差异很大，公开 API 标价不能代表企业实际采购均价。本书没有足以校准全国 API 总支出的同口径样本。

可执行的本地估计应从目标行业客户数、真实预算、部署方式、数据要求和采购周期自下而上建立。产业软件、普通专家报酬和容量合同并不只有积分一条路径；是否涉及支付、加密资产或金融业务须看具体交易，见 [ch06](09-ch06._服务契约的四组约束：计量、权利、漂移与归责.md)。

## 10.6 跨行业规模比较与敏感性分析

跨行业比较必须统一币种、时点、税、地域与交易层次。比较芯片 CapEx、模型 API 收入和铜消费价值只能说明不同活动规模，不能证明替代关系。

最有用的敏感性表应同时改变市场基数、可服务比例、采用率、留存费率及获客能力，并展示现金和产能约束。没有这些信息，远期 CAGR 与份额假设只会放大输入误差。

对于技术报告核验队列，应先估计有相同需求且有权处理数据的客户、每客户付费任务量、专家产能和采购周期。即使全国相关支出很大，无法触达客户或无法按时复核，也会限制可获得收入。该限制随后进入 [ch12](15-ch12._联合压力测试：五类冲击、损益传导与决策触发器.md) 的压力测试。

## 10.7 本章小结

本章输出的是带输入来源、交付上限和敏感性的收入区间，而不是客户已经采用的证明。若缺少任务量或真实付费样本，应把区间标为情景，并优先补证，而非用更大的 TAM 填补缺口。
