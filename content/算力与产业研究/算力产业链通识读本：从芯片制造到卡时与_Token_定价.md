# 算力产业链通识读本：从芯片制造到卡时与 Token 定价

> **文档定位**：理解一笔算力交易，需要回答“客户要完成什么、需要哪些投入、谁承担空置和履约风险”。本读本从芯片制造到模型服务梳理产业链，连接交付能力、任务需求与合同。教学算例明确假设，动态型号与价格资料集中见[日期化数据附录](算力与_token_经济：数据附录（2026-11-15—16_快照）.md)。

## 0. 三个起点

算力资源使用权、模型调用服务和业务结果是不同商品。相同芯片不等于相同交付条件；相同 Token 数量不等于相同智能质量；低价格也不直接证明低成本。

研究时先定义市场边界：客户可以买哪些替代品、在哪些地区和时段交付、切换需要多久、能否满足质量和延迟要求。地域与业务边界应由替代性判断，不能统一设为全球、全国或都市圈。

## 第一部分：算力是什么，如何计量

### 1.1 运算量、运算速率与资源占用

| 指标 | 含义 | 局限 |
|---|---|---|
| FLOP | 浮点运算次数 | 不代表所有类型的计算工作或任务质量 |
| FLOP/s，常写 FLOPS | 每秒浮点运算速率 | 必须注明精度、稠密/稀疏模式、峰值或实测 |
| GPU·小时 | 指定 GPU 资源占用一小时 | 不自动保证独占、网络、有效吞吐或利用率 |
| Token | 模型切词器处理的单位，可能对应子词、字节或多模态编码 | 不是固定汉字比例，也不是“最小语义单位” |
| 成功任务 | 按验收标准完成的业务单元 | 需要公开任务与质量评估方法 |

NVIDIA H100 SXM 官方规格中，80 GB HBM3、3.35 TB/s 显存带宽、BF16 Tensor 稠密峰值约 989 TFLOP/s。峰值不能直接换算为“相当于几千台笔记本”，也不能用来估计未经公开披露模型的实际训练时长。

### 1.2 CPU、GPU 与其他加速器

CPU 擅长通用控制、分支与系统工作，GPU 用大量并行执行单元及矩阵单元提高特定计算吞吐；GPU 并非没有分支控制。GPU 也不是所有 AI 加速器的统称，TPU、昇腾 NPU 等应按自身架构分类。CPU 核数、CUDA 核数和 Tensor Core 数量没有可直接相加的性能意义。

训练和推理需要 CPU、内存、存储与网络配合。某芯片峰值高，不意味着在指定模型与软件栈下端到端成本更低。

### 1.3 不可储存的是时段服务

今日未出售的一小时算力容量不能保存到明日再出售。硬件、模型权重、已完成的计算结果和缓存可以保存，预留合同也可以约定未来容量；应把这些存量与当期服务流量区分。

这种不可储存性增加运营商对负载与出租率的敏感性，但不禁止远期、期货或现金结算。电力还可借助储能转移部分供给，两行业的物理机制不能完全等同。

## 第二部分：从芯片到模型服务的产业链

```text
架构设计与软件生态 → 晶圆制造、HBM、先进封装
                  → 加速器、服务器、互联与存储
                  → 机房、电力、冷却、调度和运维
                  → 模型训练、推理托管、API 与业务应用
```

### 2.1 供应链分工

| 环节 | 职能 | 代表性参与者或技术 |
|---|---|---|
| 芯片设计 | 计算架构、内存系统、编译与软件支持 | NVIDIA、AMD、华为及其他加速器厂商 |
| 硅片与晶圆制造 | 半导体材料与电路制造 | 信越、SUMCO、台积电、三星、中芯国际等 |
| 高带宽存储 | 堆叠 DRAM 及封装互联 | SK 海力士、三星、美光 |
| 先进封装 | 连接计算裸片、HBM 与其他组件 | CoWoS 等封装方案 |
| 服务器与网络 | 主机集成、供电散热、机内/机间连接 | OEM、ODM、网卡和交换机厂商 |
| 云和机房运营 | 形成可用服务并承担持续交付 | IDC、公有云、专用 GPU 云、自建集群 |

瓶颈随代际、产能、区域政策和订单变化。判断某环节是否约束交付，应比较放松它能增加多少有效产出，以及其他环节是否仍有限制；市场份额、物料占比和渠道价格各有不同分母。

**互联的分层**：NVLink 是 NVIDIA 的高速互联技术；HCCL 是华为集合通信库。InfiniBand、以太网/RoCE 属于网络体系；集合通信库运行在相应硬件和协议之上。服务器形态与并行策略共同决定机内、机间通信需求，八卡节点只是其中一种常见组织方式。

### 2.2 制造、销售与经营采用不同核算边界

制造成本、芯片原厂售价、渠道到手价和服务器整机价格属于不同边界。若要分解一张卡的购买价格，需要相同分母、互不重叠的项目，以及可核查的物料与渠道数据。

公司毛利率为 $(收入-销售成本)/收入$，并不是“每张 GPU 的纯经济租金”；研发、销售管理、融资与资本机会成本仍需考虑。芯片与云厂商的财报毛利率也会受到费用归类及业务组合影响，不能直接代表整个产业链的价值分配。

## 第三部分：运营成本与商业形态

### 3.1 硬件装载不等于产能交付

服务器上架后，还需供电、网络、驱动、模型适配、冗余与测试。区分采购容量、上架容量、已通电容量、可服务容量、已售容量与实际有效产出。销售宣传中的卡数并非可直接出租的同质产能。

### 3.2 一套可复用的成本账

对固定规划期间，设资本年化费用 $A$、固定运维 $F$、变动运营成本 $V$，实际付费卡时 $H$：

$$AC_{\mathrm{GPUh}}=(A+F+V)/H.$$

若有 $N$ 张卡，商业付费利用率为 $u$，则非闰年 $H=8760Nu$。但 $V$ 应包括空闲和冗余设备实际消耗的能源，而不是简单令其随 $u$ 从零线性增长。

资本成本可以用租赁费、会计折旧口径或经济年化口径分析，不能在同一成本账同时重复计入全部购置支出、折旧及融资本金。经济年化需考虑残值、期限和资金成本；会计折旧年限不等于资产物理寿命、经济寿命或投资回收期。

**算例**：假设一套八卡系统购置 240,000 美元、残值零、直线摊销 4 年，则每日历卡时折旧为 $240000/(4\times8760\times8)\approx0.856$ 美元。在付费利用率 50% 时，每付费卡时对应折旧约 1.71 美元，还未包括电力、场地、维护和融资。该例说明利用率的分母效应，不是 H100 市场成本报价。

**功率算例**：1,000 张卡组成 125 台八卡服务器，每台 8–12 kW，则服务器 IT 功率为 1–1.5 MW；再加未包含的网络存储和设施损耗。

### 3.3 四种交付形态

| 形态 | 主要交付 | 买方保留的责任 |
|---|---|---|
| IDC 机房托管 | 场地、电力、冷却及约定运维 | 通常仍需设备、系统与模型运营 |
| 云资源服务 | 实例、裸金属或专属集群 | 依托合同承担软件、数据、负载和容量规划 |
| MaaS/API | 约定模型服务与计费接口 | 任务设计、验收、数据治理和业务集成 |
| 自建自用 | 组织内部资源池 | 承担投资、空置、维护和代际风险 |

大型企业可以同时经营多种形态。内部转移价格可能包含补贴或管理分摊，不能视为行业最低物理成本；云目录价与折扣合同的差额也不是稳定常数。

### 3.4 价格栈怎样比较

按需租赁卖的是灵活性，保底长租把一部分空置风险转给买方，Spot 可能把中断风险转给买方，模型 API 则由供应商承担更大范围的调度和交付。必须比较完整服务包。

API 收入除以假定吞吐得到的是**情景化收入折算值**，需要另与实际资源支出核对。比较各层价格时，先固定日期、区域、交付和合同，再判断容量与替代性：供给宽松且可替代时，竞争更容易把降本转为改善报价；容量紧张或服务差异化时，调整可能先体现在利润、质量或配额。详见[价格传导的三情景框架](大模型推理的微观生产函数与架构经济学.md)。

## 第四部分：训练、推理与权重制度

### 4.1 训练与推理的差异

训练更新权重，推理使用权重完成请求。训练有一次性大规模项目，也有持续后训练；推理有单机部署，也有大型专家并行系统。二者都可能按量、包时或内部核算，不能以是否“脉冲式”或是否“万卡”划出绝对边界。

推理又分输入预填充、缓存读取和输出解码。输出通常需要串行依赖，但投机解码及其他机制可改变每轮产出。输入、命中和输出应分别计量。

### 4.2 权重制度与服务能力共同决定进入条件

权重复制比重新训练便宜，但分发与托管并非零成本。公开权重也不自动等于符合 OSI 定义的开源；下载、内部使用、商业服务、再分发和大规模使用可能有不同条款。

核对许可时，应分别记录内部使用、对外 MaaS、嵌入终端应用、再分发与大规模使用的条件，并核对关联方、收入统计窗口和例外。模型架构、权重大小与部署支持则进入技术可行性评估。GLM、DeepSeek、Kimi 的具体模型卡和许可快照统一见[数据附录第 10 节](算力与_token_经济：数据附录（2026-11-15—16_快照）.md)。

公开权重降低模型获取壁垒，运营能力和客户替代性决定这个变化能多快转化为实际进入。许可还会改变研发者能取得的授权与服务收入，因此开放决策会同时影响研发激励与托管竞争，详见[产业组织专题](大模型层的内生沉没成本、开源溢出与定价机制.md)。

### 4.3 任务价值、使用强度与成本反馈

推理预算、工具轮次与重试会改变每任务词元量，没有通用的“必然膨胀 1.5–10 倍”。若单价降到原来的 0.7、词元量变成 4 倍，纯 Token 账单为原来的 2.8 倍；但资源成本还受缓存与吞吐影响。

企业应比较：

$$C_{\mathrm{success}}=\frac{\text{Token、工具、基础设施、复核与失败总支出}}{\text{通过同一验收标准的成功任务数}}.$$

这个指标回答既定任务怎样交付更划算。是否采用，还要比较预期业务收益、集成投入与人工或其他软件等替代方案；采用之后，再按新增任务或推理预算的边际收益决定用量。价格降低可以扩大使用，但工作流改造、组织能力和验收瓶颈也可能限制采用。

需求反过来改变供应商成本：可池化订单增加可能改善出租率、批处理与缓存，拥堵则可能降低服务质量并要求扩容。因而技术、任务组合、净价、利用率与质量要共同观察，不能把其中一个量固定后解释所有市场变化。

## 第五部分：构建可比报价的 SKU 网格

| 维度 | 需记录的信息 |
|---|---|
| 芯片与系统 | 完整 SKU、显存、功率限制、主机 CPU/内存和驱动 |
| 拓扑与性能 | 机内互联、机间网络、共享程度、指定负载的验收测试 |
| 隔离与交付 | 独占卡/整机、MIG/vGPU、权限、数据及运维边界 |
| 地域与设施 | 数据驻留、网络距离、电力与冷却约束 |
| 期限和风险 | 按需/保底/可中断、取消、预付款、SLA、税费 |

这些维度是联合描述，不一定统计正交。独占并不总是最便宜，也不自动提供“100% 数据安全”；切片也不必然损失同样比例的性能。差价需要同规格、同时间、同合同口径比较。

硬件代际、容量和出口许可属于动态信息。本读本不把旧版“对华合规特供”标签当成当前采购许可；具体交易应核对当时规则、目的地、最终用户与许可条件。对国产与进口设备的经济比较，应采用同任务、同质量与 SLA 的实测，并计入迁移成本。

## 第六部分：价格发现与信息产品

公开挂牌价是可观测的商业承诺或报价信号，不是无价值噪音；成交价更贴近实际支付，但也可能非代表性、关联或附带隐含条件。合理的数据层次是原始合同/成交、可执行买卖报价、目录报价与分析估值分别标记，并进行双边核验。

价格评估网格、供需地图、RFQ、任务成本指数与风险管理工具可以并行发展。产品优先顺序应由用户需求、样本覆盖和可验证性决定，不能断言所有市场必然“卡时先行、Token 随后”。

市场行情需要保留日期、币种、税费、地域、配置、期限、样本数及异常处理；分析成本需要实际费用和负载记录。两种资料可以相互检验，但不能相互替代。

## 小结：沿同一笔任务连接产业链

从客户任务和验收条件出发，先确定可替代的交付方案，再测量资源耗用、核算成本并比较合同净价。订单和负载影响运营经济性，预期回报影响后续采购与扩容；所有权与合同则决定谁承担空置、价格、技术和履约风险。沿这条链分析，可以解释分工与价格差异，而无须预先设定哪类厂商必胜或最终只剩一种计费单位。
