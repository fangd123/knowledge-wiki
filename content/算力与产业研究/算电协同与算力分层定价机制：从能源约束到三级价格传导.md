# 算电协同与算力分层定价机制：从能源约束到三级价格传导

> **导读**：算电协同把选址、接电、用能与任务调度放进同一套交付决策。任务的时限与可迁移性决定哪些能源优势可用，负载与设施决定成本，合同和竞争决定节约怎样传递给客户。“电量与容量—卡时—模型服务”是相互连接的交易层级，各层都需要自己的计量、价格和风险边界。

## 一、物理基础：功率、能量与有效产出

### 1.1 AI 服务需要连续的基础设施支持

训练和推理需要芯片、主机、存储、网络及冷却共同工作。芯片采购只是产能形成的一步；供电容量、变压器交期、机柜功率密度、网络和人员都可能制约上线速度。小集群也可能受到接电或机房约束，不能用规模阈值把它们一概忽略。

必须区分三个量：

| 量 | 单位 | 含义 |
|---|---|---|
| 功率及可接入容量 | kW、MW | 某时点负载及可保障的容量上限 |
| 电能 | kWh、MWh | 功率在时间上的积分，1 MW 持续 1 小时为 1 MWh |
| 有效计算服务 | 合格卡时、满足 SLO 的 Token、成功任务 | 还需指定硬件、模型、工作负载及质量条件 |

生成一个词元所需电能随系统与负载变化；总用电由计量或功率积分得到：

$$E_{\mathrm{facility}}=\int P_{\mathrm{facility}}(t)\,dt,\qquad
\mathrm{PUE}_{[a,b]}=\frac{E_{\mathrm{facility},[a,b]}}{E_{\mathrm{IT},[a,b]}}.$$

PUE 的分母是同一边界、同一期间内全部 IT 设备用电，不是 GPU 芯片单独用电。低 PUE 表示设施附加用电少，不能单独证明每个成功任务更省电。

### 1.2 一个功率核算算例

假设一台八卡服务器平均 IT 功率为 10 kW，千卡集群正好由 125 台组成，则服务器功率合计 1.25 MW。若 PUE=1.2，且这里的 IT 边界已包含相关设备，则设施功率约 1.5 MW；未包含的网络、存储应先补入 IT 负载。

在电价 0.5 元/kWh 的假设下，该服务器每小时分摊设施电费为 $10\times1.2\times0.5=6$ 元，即每卡时 0.75 元。这只是能耗项，还未包括设备资本、机柜、运维和网络费用。

## 二、算电协同解决什么问题

### 2.1 空间错配与工作负载分类

能源、土地、冷却条件与终端需求的地理分布可能不同。训练、离线批推理和部分后台任务通常更能容忍距离；实时交互仍需比较用户至节点的延迟、数据传输费用和合规要求。不能笼统断定所有在线推理都不能跨区，或所有训练都可以无成本迁往低电价地区。

选址宜比较单位成功任务总成本：

$$C_{\mathrm{task}}=C_{\mathrm{capital}}+C_{\mathrm{energy}}+C_{\mathrm{network}}
+C_{\mathrm{operations}}+C_{\mathrm{delay/failure}}+C_{\mathrm{migration}}.$$

低电价不保证总成本最低。用量不足、软件不适配、跨区数据往返与停机损失，都可能抵消电费节约。

### 2.2 时间调度和可中断性

低价时段运行可推迟任务，可以改善负载因子并降低购电支出；收益取决于检查点、重启、任务截止期和设备空闲功耗。把集群作为需求响应资源，还要满足供电合同和调度要求。调度者应比较节省的能源与容量成本、延迟或中断损失，以及同一设备在其他任务上的机会收益。

负载并不是固定不变的背景：有截止期余量的客户可能接受批处理折扣，供应商因此得到更平滑的任务队列；但折扣也可能吸引超出可用窗口的需求。可移峰任务比例、到达相关性与最终交付率，应和电费一起观察。

储能可以转移部分电能；预计算和缓存可以提前完成部分工作。它们均不能保存“昨天未使用的一小时 GPU 服务”本身。

### 2.3 绿色属性与可靠性

绿电直供、购电协议、绿证以及逐时无碳电力匹配是不同安排。购买年度绿证不等于每小时物理用电都来自可再生能源；签署核电或绿电 PPA 也不自动意味着绕过电网的表后直连。报告应分别记载合同能源属性、物理供电路径、可靠性与排放核算边界。

中国《数据中心绿色低碳发展专项行动计划》是政策背景来源之一。具体选址应将政策目标、枢纽建设要求、地方项目审批与企业购电条款分别列明，记录适用设施、地区、年份及考核口径。能源属性、可靠性与总成本可以共同约束方案，不能只以单一绿电比例排序。

## 三、跨区域比较：把地域条件变成项目输入

### 3.1 接电路径：区分供给接入与大负荷接入

在美国等需分别申请发电接入和大负荷接入的市场，发电、储能项目的队列反映供给侧建设摩擦，数据中心的接入资料才直接约束其上线计划。项目分析应沿自己的接电路径追踪里程碑，而不是用某一全国队列总量替代。

评估一个数据中心的约束，需要大负荷申请、已签接电协议、变电站扩建、可交付 MW、预期通电时间及实际投运率。发电项目排队可以反映系统扩建摩擦，但它只是背景变量。

### 3.2 区域分工：将距离转换为交付代价

以新加坡与柔佛等相邻市场为候选，终端连接与后台产能可以组合为不同交付方案。是否有净收益，要测试具体端点的时延、带宽与可靠性，核对数据驻留，并比较已可交付容量与完整合同成本。公告容量、在建容量、已通电容量和已售容量分别进入不同的规划步骤。

### 3.3 异构资源：将名义卡数转换为可售能力

比较中国及其他市场的资源池时，应区分上架率、通电率、出租率、GPU busy、有效训练利用率和满足 SLO 的服务吞吐。不同芯片的软件适配、互联和任务组合会改变可售能力。同一个区域可能同时存在闲置资源和紧缺服务；应按可替代的任务市场分别评估供需。

区域政策、价格与队列数字属于日期化输入，其核验口径见[数据附录](算力与_token_经济：数据附录（2026-11-15—16_快照）.md)。本节提供项目比较方法，不给国家或城市固定排名。

## 四、三级计量与价格传导

### 4.1 三层交易标的

| 层级 | 常见计价单位 | 需明确的合同要素 |
|---|---|---|
| 能源与机房 | 元/kWh、元/kW·月、机柜月租 | 能量费、需量/容量费、网络费用、PUE 边界、能源属性 |
| 硬件资源 | 元/GPU·小时、整机月、集群年 | 型号、显存、拓扑、独占性、期限、地域、SLA |
| 模型服务 | 元/百万输入或输出 Token、吞吐承诺、成功任务 | 模型版本、缓存类别、质量、时延、计费范围 |

同一型号的卡时也不是无条件同质商品；同样数量的 Token 更不保证相同质量。Token 通常是用量计价单位，“按结果付费”另需定义结果与验收。

三层的价格频率没有固定排序。电力现货可以小时内变化，GPU 按需价格也可实时变动，而 API 目录价可能保持数月。应区分实时交易价、固定采购协议和公开牌价。

### 4.2 交付成本先统一单位

设每卡的年化资本与固定运维费用为 $A$，年付费卡时为 $H_{\mathrm{bill}}$，每卡分摊设施电能为 $e_{\mathrm{h}}$ kWh/卡时：

$$c_{\mathrm{GPUh}}=\frac{A}{H_{\mathrm{bill}}}+p_e e_{\mathrm{h}}
+c_{\mathrm{network}}+c_{\mathrm{variable}}.$$

所有右侧项必须统一为货币/付费卡时。若电费已在整机或机柜租赁合同中，不能再重复相加。设备空闲与冗余能耗也须分摊到实际服务，而不是默认只在付费时才耗电。

对于固定模型和工作负载，若每个付费卡时实现 $y$ 个合格处理词元，粗略成本为：

$$c_{\mathrm{1Mtok}}=10^6c_{\mathrm{GPUh}}/y.$$

输入、缓存命中和输出处理开销不同，应分桶计量。$y$ 会随利用率、批次、SLO 和软件改变，不能从 API 牌价倒推出唯一 GPU 租价。

### 4.3 从成本变化到合同价格

成本变化首先落到支付该项费用的主体，再通过合同与竞争传递。应逐层检查，而不是把电价涨幅乘一个固定系数当作 API 涨幅。

| 合同安排 | 成本变化的直接承担者 | 向下游传递的窗口 |
|---|---|---|
| 电费包含在固定机柜或算力租价中 | 服务方先承担其实际购电成本变动 | 合同允许调价、续约或重谈时；还受替代供应商约束 |
| 电费按实结算或有明确联动公式 | 按约定计量与公式分配给客户 | 随结算周期传导；仍需审查损耗、分摊与服务费 |
| 按量模型服务 | 模型服务方管理底层资源成本和空置风险 | 通过价目、折扣、质量或利润调整，用量同时响应 |

固定价合同对买方提供一定价格稳定性，却可能附带最低承诺和取消限制；浮动价格保留成本变化的传导，也要求客户承担波动。容量是否宽松、服务是否可替代、客户是否容易切换，决定后续议价；完整的三情景框架见[推理生产函数§2](大模型推理的微观生产函数与架构经济学.md)。

据此，算电协同的收益应分成两步验证：先测量同质量交付的资源与现金支出是否减少，再确认这些节约如何在供应商收益、客户净价和服务改进之间分配。

## 五、平台与价格基准的业务选择

资源目录、撮合、跨池调度、全栈交付和独立价格评估解决不同问题，可以组合而不必逐级升级。先与现有询价、直接合同和本地调度比较增量价值，再决定是否引入平台；标准化既可能压缩信息差收益，也可能降低小平台的获客与交付成本。

| 能力 | 可交付价值 | 需要验证的收益来源 |
|---|---|---|
| 资源发现与询价 | 缩短采购时间 | 报价有效率、订单转化和客户愿付费 |
| 跨池调度 | 降低空置、提高可用性 | 扣除迁移、网络和适配后的净收益 |
| 全栈服务 | 统一保障与账单 | SLA 兑现、续约与真实服务成本 |
| 价格基准 | 提高可比性、支持合同与风险管理 | 数据覆盖、代表性、治理及合同采用 |

价格评估可以在集中交易形成前发挥作用，集中交易也能产生价格发现；不存在所有商品均“先 PRA、后交易所”的历史定律。缺少集中撮合也不自动使 OTC 价格无法用于基准。

基准管理员的利益冲突必须管理，但不应把“不参与任何交易”写成唯一合法组织形态。数据准入、优先级、关联样本识别、审计、更正、申诉和停止发布规则，才是可检验的治理机制。PUE 调整价、区域价差和绿色升贴水要有足够同规格样本，不能靠成本假设制造“市场溢价”。

## 六、落地工作顺序

1. 定义目标交易：裸卡、整机、集群或模型服务，以及相应 SLA。
2. 明确功率、电量、付费时间和有效产出的计量边界。
3. 同时收集设备、机房、能源、网络和运维合同，消除重复计费。
4. 在代表性负载下测试吞吐、质量、延迟和可中断性。
5. 比较现有方案与跨区、错峰、储能或迁移方案的增量现金流。
6. 用实际成交与可执行报价更新基准，并标明日期和样本覆盖。

**小结**：当任务可迁移或可延迟、方案满足交付约束且增量节约覆盖迁移与可靠性代价时，算电协同有改善经济性的空间。检验应使用同一批任务的总成本、交付率与风险，而不是只比较电价或 PUE。市场和合同决定谁获得收益，项目运行记录决定收益是否真正实现。
