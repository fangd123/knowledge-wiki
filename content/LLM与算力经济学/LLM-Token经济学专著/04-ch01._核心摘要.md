# ch01. 核心摘要

> 本书研究异构计算服务的计量、契约与制度选择。“Token 经济学”是主题名称，不以 Token 成为货币为预设结论，也不以某类创业项目胜出为既定答案。

## 1.1 核心命题

**在同等质量、履约和风险约束下，候选制度能否比现行法币采购降低采购、履约与交易的总成本，或带来足以覆盖新增成本的服务价值？** 这是全书共同的反事实问题。研究从业务任务开始，而不是从发行某种凭证开始。

全书围绕四个相接的问题展开：

| 问题 | 本书需要得到的结果 | 接入后文的用途 |
|---|---|---|
| 计量：交付什么，怎样比较？ | 任务、验收、完整成本与迁移基线 | 检验路由、核验与采购是否有增量收益 |
| 契约：谁承诺，谁负责？ | 数据与服务权利、SLA、付款及违约边界 | 判断方案是否可执行、成本由谁承担 |
| 制度：为何增加某种安排？ | 与人工、直连、既有网关和普通合同的比较 | 选择供给组织、激励、授权与支付组件 |
| 采用：谁愿付费，能否持续？ | 付费需求、单位经济、压力测试与停止条件 | 形成有条件的试验优先级，而非成功率排名 |

其中，**采购者的成本改善、服务商的盈利和行业总福利是不同结果**。采购优化可能压缩供应商收入；平台获得收费也不证明客户受益。后文分别核算这些主体，避免用一个“价值增长”替代全部判断。

货币化是第三问中的特殊分支：若服务请求权出现跨主体转让、第三方接受、以该权益定价或跨期持有需求，再分别检验相应的货币功能。技术上可转移、账面有余额或自动付款，本身都不足以完成这一推导。

## 1.2 三大核心研判结论

1. **可比性来自任务与契约，不要求单个 token 同质。** 固定质量、时限、数据条件和成本边界后，可以比较不同模型与处理政策；方法见 [ch00 三项工具](ch00-入门预读.md#0.9%20贯穿案例与三项采购工具)和 [ch16](ch16-token汇率.md)。
2. **制度的经济性来自增量收益，而不是名称。** 路由、专家核验、服务券、授权账户和价格合约分别解决不同问题；以现有工具为基线，新增收益须覆盖集成、验证、履约、资金及治理成本。
3. **采购改善与商业机会之间还隔着采用和收入验证。** 客户愿付费、交付可持续、竞争后仍能留存收入，才支持经营判断。市场规模和压力情景用于约束假设，不能替代客户证据。

这使后半部的场景与创业讨论接回前半部：先证明某个交易问题值得解决，再研究谁能提供解决方案。现有协议与产品作为可选组件在 [ch05](ch05-生态地图.md)集中说明，发布与采用证据分开记录。

## 1.3 六组可组合方案，而非六选一赛道

以下编号与 [ch08](ch08-六种产品形态.md) 一致。它们来自不同分析层级，同一项目可以组合使用；编号不代表成熟度或优先级。

| 编号 | 方案与分析层级 | 首要验证问题 |
|---|---|---|
| 一 | 垂直业务交付：AI 与专家核验 | 客户是否为结果复购，核验成本与责任是否可承担 |
| 二 | 运行治理：多模型路由与网关 | 总交付改善是否超过集成、评测和平台费用 |
| 三 | 风险产品：采购与价格风险管理 | 真实敞口是什么，供应或对冲安排是否适配 |
| 四 | 权利形式：服务券与可转让权益 | 为何需要持有或转让，承兑与负债是否匹配 |
| 五 | 供给组织：分布式专业服务 | 外部收入是否覆盖供给、验证与协调成本 |
| 六 | 支出治理：受托账户与授权控制 | 能否可靠约束支出并处理退款、故障与归责 |

例如 [ch00 的技术报告核验队列](ch00-入门预读.md#0.9%20贯穿案例与三项采购工具)可以只采用方案一，也可按需要增加二与六；五是候选供给来源，三与四是另行证明必要性的合同安排。这个教学案例不包含实测收益，不用自设结果证明某种组合更优。

## 1.4 证据到建议的边界

全书区分四类内容：已有资料支持的事实、用于解释的机制、明确标注的教学假设、尚待试验的产品建议。同一资料在多个章节被引用，不会变成多份独立证据。

后文建议的证据链统一为：**客户问题 → 现有替代品 → 预期增量收益 → 待验条件 → 停止条件**。ch13 先规定评价标准，ch15 设计并记录实验，ch14 再给有条件的试验选择；目前未开展真实客户与付费路由对照，不能把建议写成已验证结论。

接受“不发券、不建指数、不套保，继续使用普通合同”的结果，是制度比较有效的必要部分。历史类比帮助提出机制与反例，不替代这一反事实检验。
