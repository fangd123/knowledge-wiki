# ch13. 决策框架：预先登记评价标准、采用与停止条件

> 本章接 [ch12 的脆弱参数与风险触发器](ch12-风险情景.md)，在正式试验前确定如何判断结果。先登记目标、基线、成本边界和停止条件，再按 [ch15](ch15-下一步.md)收集证据；不能看到结果后再改标准以保住原方案。

## 13.1 四项决策准则

1. **先定义客户问题。** 写清客户正在为哪项任务付多少钱、哪里失败、现有替代方案为何不够好。
2. **把核心假设转成试验。** 专家接受积分、路由能节约总成本、客户愿买保供等是不同假设，应分别验证。
3. **比较完整替代方案。** 自建、直连 API、现有网关、人工流程和不做项目都可能是合理选择。市场集中不意味着新进入必败，也不等于差异化必胜。
4. **按实际权利与资金流审查业务。** 软件、服务转售、资金托管和金融合约不能仅靠命名区分；闭环积分也有独立义务。

### 事先登记的评价卡

| 项目 | 试验前写清什么 | 何时停止、缩小或转向 |
|---|---|---|
| 主体与目标 | 采购者比较交付成本与风险；服务商另验付费需求、利润与现金 | 客户目标没有改善，或经营者长期无法覆盖履约成本 |
| 质量与权利 | 任务范围、独立验收、非劣门槛、重大错误、时限与数据授权 | 关键权利不成立，或突破预设质量与风险上限 |
| 成本与迁移 | 全量任务成本、验收率、计费期间、预计交付量和迁移费 | 运行收益不能覆盖维护与迁移，或不确定性超过可接受范围 |
| 采用与收入 | 内部项目看真实预算和持续使用；对外业务看独立付费与复购 | 只有免费试用、补贴流量或无法落实的口头意愿 |
| 现金与责任 | 试验预算、不可回收投入、预付及奖励义务、赔付边界 | 现金、承兑或尾部损失超过已授权预算 |
| 增量制度 | 新增路由、积分、指数或风险工具分别解决哪个未满足问题 | 既有工具效果相当且更简单，或新增成本超过收益 |

具体阈值由业务损失、合同、预算和测量精度决定，不采用通用“节约百分比”或固定用户数。探索阶段可修订假设，但须记录原因，并用新的独立样本验证；正式比较的规则应在观察该批结果前冻结。

## 13.2 按客户问题选择可组合试验

```text
目标客户是否愿意为具体业务结果或治理问题付费？
├─ 尚无证据 → 访谈历史采购、观察流程，做小范围付费试验
└─ 有初步证据
   ├─ 有行业数据权利和专家供给 → 方案一：AI + 专家核验
   │  └─ 专家不需要积分 → 试验现金报酬或订阅，不强行建立积分循环
   ├─ 有跨模型质量、可靠性或成本治理需求 → 方案二：路由与治理
   ├─ 有机器支出授权与核对需求 → 方案六：受托支出控制
   ├─ 有可量化价格或容量敞口 → 先设计供应/价格合同
   │  └─ 对冲工具、资本及适用资质齐备 → 再评估方案三
   └─ 有分布式供给与可验证任务 → 评估方案五的外部收入与抗作弊

若拟发行可转让服务券 → 按方案四另验接受需求、承兑、授权与负债
若拟发布行业指数 → 另行验证代表性、独立性、修订规则和客户采用
```

分支可组合，不是依次升级的阶段。普通服务合同、法币月结、内部成本表或已有网关已经解决问题时，可以停留在那里，不必发行服务券、发布指数或建立专用支付产品。

拥有数据平台客户可降低获客难度，但原订阅合同不一定授权 AI 训练、转售数据或让会员提交竞争敏感信息，必须逐项核查。

## 13.3 四项退出成本较高的架构选择

### 选择一：是否公开发行代币

公开销售可能增加发行、交易、托管和证券等义务，也会改变客户与投资者预期。技术上可以停止某项产品，但已有持有人、合同与法律责任不会随停止自动消失；“发币后永久固定一种法律身份”也过于绝对。

不发币可以减少部分复杂度，仍须处理普通企业、数据、消费者与支付责任。使用已有支付资产与自行发行代币应分开决策。

### 选择二：服务权益如何兑付、转让和退款

先说明谁承兑、可兑换什么、是否过期、是否转让以及争议和合法退款怎么处理。积分、法币余额和固定服务券的风险不同。

受限流转可能降低一些资金转移属性，却不会自动免除预付消费、税务或劳动报酬要求。x402 是协议，不是支付牌照；接入 Stripe 也不意味着平台全部业务义务转移给它。

### 选择三：谁保管资金和密钥

中心化账本、第三方支付与链上合约各有性能、恢复和信任取舍。应以客户所需的可靠性、可审计性和责任分配选择，而非宣称某种架构永远高效。

哈希存证能帮助发现记录篡改，不能证明原始用量、服务质量或账单本来就正确。预算系统还需防止并发重复预占、超时重复付款和撤销后继续执行。

### 选择四：服务哪些法域与部署环境

“在岸/离岸”不是一套全球法律划分，海外注册也不能消除客户所在地或实际经营地义务。应明确客户、数据、人员、付款、模型托管与交付所在地，以及税务和供应商服务资格。

本地模型和私有部署可能有优势，但它们不自动满足全部行业规范；境外平台也不是在所有本土业务中都无法竞争。

## 13.4 不同用途对应不同证据门

| 拟采用的用途 | 应交付的证据 | 允许采用或扩大范围的条件 |
|---|---|---|
| 客户与流程验证 | 任务样本、现有成本、数据权利、付费试验 | 有复购或明确预算，验收责任可执行 |
| 工作流与治理 | 真实全量成本、质量与失败日志、可撤销授权 | 改善超过维护和迁移成本，重大风险可控 |
| 行业基准 | 代表性任务集、版本、方法和外部复核 | 第三方实际用于采购或合同且冲突可管理 |
| 风险管理产品 | 客户敞口、可执行供应或对冲、资本模型 | 基差、尾部损失、流动性和许可满足要求 |

这些是按用途触发的证据责任，不是从工作流走向指数、再走向金融化的升级路线。行业基准除了被使用，还须验证代表性和客户决策的增量改善；被某合约引用不能单独证明它有效。

对技术报告核验队列，先冻结验收、人工基线与成本口径。若测试仅支持改进核验流程，就只采用该改进；专家不需要积分时停止积分试验，不必连带否定服务；内部测评已够用时不启动公共指数项目。
