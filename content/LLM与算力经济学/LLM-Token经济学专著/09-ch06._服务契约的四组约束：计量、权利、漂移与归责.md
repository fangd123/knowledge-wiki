# ch06. 服务契约的四组约束：计量、权利、漂移与归责

> 本章承接 [ch02 的制度比较](ch02-命题精确化.md)，把方案能否执行拆成计量、权利、漂移与归责四组约束。它们同样影响普通服务采购；发行凭证只是其中需要增加承兑与转让检查的特殊情形。

## 6.0 导言：四组约束要求不同的处理工具

计量差异需要测评；账户和数据权利需要授权；能力漂移需要版本与替代条款；资金、服务和法律责任需要明确归属。第三方账本能改善记录，却不能替代这四类工作。

对技术报告核验队列，本章应产出一张实际可填的约束表：允许处理哪些文档、由谁最终验收、使用哪些服务、模型变更时如何替换、失败时谁返工或赔付。只有新增转让或预付安排时，才再增加凭证持有人、承兑和余额保护条款。

## 6.1 约束一：计量异构与价格变化

### 6.1.1 纵向维度：价格下降的适用边界

一些任务域的质量调整推理价格显著下降，但不同发布日期、能力、方向、缓存与服务等级的目录价不能直接拼成“同等能力价格指数”。架构优化、竞争、补贴与硬件变化都可能影响价格，摩尔定律不规定 API 的固定年度跌幅。

判断跨期价值应先区分持有对象，再使用同口径的价格与履约记录：

| 持有对象 | 降价影响 | 仍可能持有的经营理由 |
|---|---|---|
| 固定数量旧模型配额 | 替代采购的法币价格可能下降 | 短期已知用量或折扣 |
| 固定法币余额 | 同一余额可能购买更多服务 | 付款便利、预付折扣 |
| 指定时段预留容量 | 取决于时段供需与交付条款 | 高峰保供、连续性 |
| 固定质量任务券 | 取决于替代交付成本与验收 | 锁定业务结果预算 |

提前采购的折扣、供应中断损失和资本占用应共同衡量。即使预期单价下降，“零库存永远最优”也不成立。

### 6.1.2 横向维度：分词与账单异构性

同一文本在不同 tokenizer 下计数不同；输出长度、思考预算与工具调用又由模型策略决定。没有原文、版本和 usage 的“中文一万字等于某模型多少 token”只能是示意，不能当作实测。

缓存写入、命中输入、普通输入、输出、存储与外部工具费用也不共享固定倍率。若 reasoning 已包含在 billed output 中，不应再次计费。跨模型比较应转为相同任务与质量条件的总成本，详见 [ch16](ch16-token汇率.md)。

### 6.1.3 可实施的解决路径

- 固定业务任务篮子、质量门槛、时限与成本边界，发布带样本和版本的比较结果。
- 对质量、延迟和数据边界分别分组，避免把不可替代的服务强行合成一个价格。
- 用法币记账、按实际服务计量；是否用稳定币结算另行决定。
- 保留模型替换、指数修订和退出规则，持续监控漂移。

上述方法不要求所有模型能力一致；在限定任务域内即可实施，并随版本与任务变化持续更新。

### 6.1.4 大宗商品制度史对照

品级、交割地点和基准治理可借鉴；“标准任务有效成本”则是基于选定任务的统计指标，不是 BTU 式物理单位。建立指数不自动取得定价权，还需要代表性、独立性和合同采用。

## 6.2 约束二：账户、转售与服务权益的合同边界

### 6.2.1 合同权利先于数据库转移

[OpenAI Service Credit Terms](https://openai.com/policies/service-credit-terms/)是检查服务额度转让、到期与退款限制的例子。应读取实际适用版本及企业补充合同，不能概括为所有厂商所有额度均受完全相同限制。

共享主密钥会引入越权、无法归责及违约风险；允许应用向自己的终端客户提供服务，与允许转卖账户余额，也不是同一权利。

### 6.2.2 可能的经济动因

限制转售可维护分层价格、降低欺诈和履约管理成本，也可形成客户锁定。但价格歧视不要求阻断每一种套利，只要求套利约束足以维持价差。开放转让也可能扩大销售，所以供应商并非必然毫无合作动机。

可转让性即使改善，提示词、缓存、数据、评测与系统适配等转换成本仍然存在，不会瞬间归零。

### 6.2.3 合法可执行的产品路径

| 路径 | 必须取得的条件 | 未解决的问题 |
|---|---|---|
| 官方额度转让 | 发行方允许转让及清晰受让权利 | 价格与供应商信用风险 |
| 聚合服务转售 | 上游转售/托管许可与下游合同 | 聚合方资金、服务与数据义务 |
| 联盟服务提货券 | 多方承兑、替代服务与清偿约定 | 资产负债匹配与争议处理 |
| 纯 BYOK 软件网关 | 用户与上游关系、密钥和数据授权 | 软件安全与采购复杂度 |

“数字算力仓单”只是类比。实物仓单通常代表已存在库存，未来推理尚待生产；持牌第三方也不能将未获许可的上游额度变成可自由转让的权利。

## 6.3 约束三：能力漂移与交付连续性

### 6.3.1 模型能力与契约连续性

同名模型可能升级、下线或改变输出行为。不能把“2026 年一千 token 必然完成复杂形式化验证”写成通用事实，也不存在所有模型 12–18 个月统一下线的规律。

固定模型版本能降低行为变化，却增加停服风险；只写“未来最新模型”则可能产生价格、质量与接口争议。能力提升与单价下降不必精确抵消，两者都需用实际任务衡量。

### 6.3.2 可交付的合同标的

可选择指定版本服务、硬件容量、任务结果或混合安排。合同应包含版本替代、验收、支持期限、可用容量、退款和赔付规则。任务券仍可能因基准过时、数据泄漏或验证争议失效；GPU 小时也受硬件形态、网络和地点影响。

上游 GPU 价格指数不是下游任务成本的直接锚。现金结算只能补偿特定指数价格变化，容量不足仍须通过真实供应合同解决。

## 6.4 约束四：法律定性与机器交易归责

### 6.4.1 设计特征与需要核查的法律问题

| 设计特征 | 需核查的问题，不能仅凭特征直接定性 |
|---|---|
| 平台内预付消费 | 消费者退款、期限、余额保护、预付业务规则及会计 |
| 专家劳动换积分 | 劳动或劳务报酬、税务、知识产权、可兑换价值和条款公平性 |
| 跨主体转移或提现 | 支付、电子货币、资金转移及反洗钱规则与适用例外 |
| 公开可交易代币 | 发行、销售、托管、交易服务及当地加密资产限制 |
| 按法币锚定与兑付 | 稳定币分类、储备、兑付资格及发行许可 |
| 收益分配或投资安排 | 证券、集体投资或其他金融产品规则 |
| 现金差价远期/期权 | 衍生品分类、交易和中介许可、客户资格 |

“不可提现、不可转让”可能降低部分金融属性，**不是全球免牌照或完全合规的充分条件**；禁止依法应退的预付款本身也可能产生问题。法币结算同样可能涉及支付或客户资金监管。

### 6.4.2 不同法域不能共用一张许可证标签

美国稳定币法、各州资金转移规则、欧盟 MiCA 的不同资产分类、新加坡支付服务规则及香港制度并不等价。GENIUS Act 的生效与实施节点还须逐项核对；不能把所有条款都当成已无条件适用于所有产品。MiCA 也不能概括成所有参考商品的代币一律只能持有国债。

中国境内的虚拟货币、支付、预付消费、数据和生成式 AI 规则分别适用。普通软件服务、现金支付专家报酬、依法签署的容量采购合同等均应按具体业务分析；“闭环积分是唯一合法路径”以及“所有场外采购远期均违法”的概括均不成立。

### 6.4.3 Agent 归责与工程证据

Agent 通常由人或法人委托，不天然取得独立法律人格。授权错误、商户未交付、模型建议错误和密钥被盗有不同责任链。签名委托、预算预占、幂等交易、撤销与证据留存有助于审计，但不自行决定赔偿责任。

## 6.5 四组约束的处理清单

| 约束 | 当下可做的工作 | 不能承诺的结果 |
|---|---|---|
| 计量异构与价格变化 | 同任务评测、完整账单与敏感性分析 | 通用固定智能单位或永不贬值 |
| 转让与账户限制 | 谈判授权、明确转售与承兑责任 | 用技术绕过原合同 |
| 能力与供应漂移 | 版本、替代、容量及赔付条款 | 固定模型或单一指数永久有效 |
| 法律与归责 | 按法域、资金流、客户类别审查 | 闭环、链上或持牌合作即全面免责 |

## 6.6 大宗商品制度经验与边界

质量规范、样本审计、利益冲突管理、保证金与违约处置值得借鉴；各机制只能处理某类风险。CCP 不消除所有信用风险，独立报价不保证流动性，仓单也不使未来生产等同于现存库存。

关于基准治理参见 [算力基准抗操纵微观结构与IOSCO治理设计](../04-算力指数与金融化机制研究/算力基准抗操纵微观结构与IOSCO治理设计.md)。

## 6.7 本章小结

当计量口径、上游授权、替代交付和责任归属可以写清，候选方案才具备进入试验的基础；若某项权利无法取得，应缩小交付范围或放弃对应组件。这样得到的是具体合同边界，而不是关于整个行业成熟年份的判断。
