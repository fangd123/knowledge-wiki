# ch05. 生态地图：全球计算经济与支付结算全景透视

> 核查日期为 2026-11-15，ERC 状态、OpenRouter 费率与 ACP 名称区分已于 2026-11-17 复核。官方文档可证明产品、条款或公告内容；不能直接证明市场占有率、独立性能或商业成功。下文将协议、模型服务、资金账户、指数与金融合约分开。

**本章衔接：**先读 [ch07 职责图](10-ch07._系统分层：计算与_Token_经济的_L0–L7_八层架构解构.md)，再按客户需要查阅本章。这里提供带时点的组件与条款快照，不作创业排名；其收入和成本如何进入同一笔交易，交给下一站 [ch09](12-ch09._价值链分布：利润池结构、议价权与演化迁移.md)分析。

## 5.1 协议层：支付、授权与任务编排

### 5.1.1 x402 与 Cloudflare Pay-per-crawl

[x402](https://docs.cdp.coinbase.com/x402/how-it-works)定义机器可读的支付交互。典型 HTTP 流程是：请求服务，收到支付要求，客户端签署支付凭证后重试，服务方或 facilitator 验证，执行工作并结算，返回结果及结算信息。当前文档明确强调对传输、网络、资产和计费方式的可扩展性，不能将协议等同于单一链上的 USDC 转账。

协议使用 HTTP 402，但不是 IETF 已将其所有机制纳入 HTTP 标准的证明。它也不天然免除身份识别、权限、商户服务条款、退款或版权许可。

两件 Cloudflare 事件须分开记录：

- [Pay-per-crawl](https://blog.cloudflare.com/introducing-pay-per-crawl/)于 **2025-07-01**宣布私测，以 HTTP 支付意向和定价处理内容访问，Cloudflare 在该产品中担任 Merchant of Record。
- [与 Coinbase 成立 x402 Foundation](https://blog.cloudflare.com/x402/)的公告日期为 **2025-09-23**。

这不等于“Cloudflare 覆盖的站点均已开启付费”，也不意味着支付一次抓取费用便取得所有训练和再分发权。

### 5.1.2 MPP 与 Shared Payment Tokens

[Machine Payments Protocol](https://stripe.com/blog/machine-payments-protocol)于 **2026-03-18**由 **Tempo 与 Stripe**联合发布。它规定 Agent 与服务端如何协调付款，支持微支付、重复付款等场景；Stripe 接入可以使用稳定币，也可通过 SPT 使用卡和先买后付方式。

[Shared Payment Token](https://docs.stripe.com/agentic-commerce/concepts/shared-payment-tokens)是受限制的支付凭证，不能与 MPP 协议本身画等号。金额、有效期、接收方及可用支付方式应按实际 API 版本实施，不应假设所有钱包均能无条件互通。开放协议的采纳还取决于客户端、商户、服务商、风控与运维投入。

### 5.1.3 A2A 与 AP2

A2A 处理跨系统 Agent 协作；[A2A x402 扩展](https://github.com/google-agentic-commerce/a2a-x402)处理相关支付集成；[AP2](https://github.com/google-agentic-commerce/AP2)以可验证授权证据支持受托购买，包含意图和购物车等委托结构。

签名能够证明谁签了什么内容，不能单独判定代理权限、消费者保护和合同争议。协议设计应与预算策略、身份验证、付款服务商规则和当地法律共同工作。

### 5.1.4 ACP、ERC-8004 与 ERC-8183

Virtuals 的 **Agent Commerce Protocol**处理任务、报价、托管与验收；它与 Stripe/OpenAI 语境中的 **Agentic Commerce Protocol**存在相同缩写，引用时必须写明组织和版本。

- [ERC-8004：Trustless Agents](https://eips.ethereum.org/EIPS/eip-8004)提出身份、声誉和验证登记机制。
- [ERC-8183：Agentic Commerce](https://eips.ethereum.org/EIPS/eip-8183)定义带预算托管、提交与评估者验收的任务状态机，**不是把未来收益证券化的收益权标准**。

2026-11-15—16 事实审校读取时两者均标为 **Draft**，2026-11-17 复核仍为 **Draft**；草案、实现和广泛生产采用是三个不同状态。

## 5.2 计算与智能要素市场层

### 5.2.1 Bittensor 与 dTAO

[Bittensor 文档](https://docs.bittensor.com/)描述矿工、验证者、子网与动态子网代币机制。子网可用不同评分函数组织服务供给，dTAO 引入子网资产与池机制；排放规则会演进，不能把某版机制当成长期固定公式。

应分别观测外部客户收入、代币激励、验证成本、质押与流动性。判断供给是否可持续，需要子网级的收入、成本与退出样本，不能以链上转移或评分代替独立客户需求。

### 5.2.2 Virtuals 与 Agent 商业

Virtuals 提供 Agent 生态与任务协作机制。是否允许分润、代币持有者享有何种权利，取决于具体项目合同。服务收入、代币交易和持有人权利须分别记录，不能用一项指标替代另一项。

### 5.2.3 Akash、Render、Gensyn 与其他网络

Akash 的竞价租赁、Render 的图形计算、Gensyn 的分布式机器学习以及 io.net 等的资源组织方式各不相同。网络延迟、互连与故障率使部分广域分布式资源难以替代紧耦合训练集群，但是否适用于推理、批处理或某类训练，仍须按工作负载测试。

低报价必须与显存、地域、可靠性、传输成本、数据要求和支持服务一起比较，不能以“闲置 GPU”直接推出更低总成本。

## 5.3 中心化模型、采购合同与金融合约

### 5.3.1 模型与托管不是同一商品

DeepSeek-V4.1-Flash、Kimi K3.1 Pro、GLM-5.3-Flash 等已有官方模型资料。模型卡记录发行方的架构与性能自述；托管价格、客户任务效果和许可证另行核查。具体入口与观察日期见 [附录 C](02-附录_C._核心文献、行业规范与实证数据源汇编.md)，账单案例见 [ch16](19-ch16._跨模型任务成本：完整账单、验收与迁移条件.md)。

例如 [Kimi K3.1 Pro LICENSE](https://huggingface.co/moonshotai/Kimi-K3.1-Pro/blob/main/LICENSE)对特定规模的 Model as a Service 业务另设协议要求，不能统一称所有开放权重均为无限制 MIT 商用。模型与具体云托管商的价格、缓存、并发和地域可用性亦不相同。

### 5.3.2 预付余额、最低消耗承诺与预留容量

三种采购安排须分开：预付余额不必保证容量；最低消耗承诺可能只是折扣条件；预留吞吐合同才按具体 SLA 提供相应保障。它们具有跨期风险分配效果，但不能不看条款就统称等价金融远期，更不能把 TPM/RPM 的限额当成保底吞吐。

### 5.3.3 GPU 指数与场内合约的已核验状态

[ICE 2026-09-29 公告](https://www.ice.com/publicdocs/futures_us/exchange_notices/ICE_Futures_US_Exchange_Notice_ORNN_Compute_4Q2026_20260929.pdf)明确：拟推出基于 **Ornn OCPI** 的 H100（`HPR`）与 B200（`BKL`）月度现金结算合约；该公告当时**尚未设定挂牌日期或时间表**。2026-10-05 提供的是参考数据与假设结算价，用于系统准备，不等于合约已开市。合约规模按对应月份实际小时数，拟覆盖最多 24 个连续合约月。

[CFTC 2026-08-19 新闻稿](https://www.cftc.gov/PressRoom/PressReleases/9286-26)是对算力衍生品的一般公开征询，不是对某份合约的最终批准。[2026-09-21 NYMEX 审查延长函](https://www.cftc.gov/filings/documents/2026/orgdcmnymexcompcontr260921.pdf)涉及具体申报，将审查期延至 11 月 9 日；日期到来不等于自动批准或上市。2026-11-17 复核：NYMEX 11-04 函再延至 2027-01-08（附条件：其他注册机构不抢先自证/获批/挂牌可比合约，详见实证台账 §1.8），最新状态以 04 实证台账 日期化条目为准。

**ICE–Ornn** 与 **CME–Silicon Data** 是不同合作安排。有关 CME 产品代码、最终规则及截至 11 月 15 日的最新交易状态，本章尚未获得完整可读的一手文件，保留待核验，不能宣称已具流动性的对冲市场。详细研究见 国际算力定价与衍生品市场全景。

现金结算合约分配指数价格风险，**不交付 GPU 或模型容量**；它也不必与客户实际 API 成本高度相关。

## 5.4 聚合路由与治理层

### 5.4.1 OpenRouter

统一 API、供应商选择、故障回退与统一账单可降低接入成本，但路由商不因转发请求就成为承担双边库存报价义务的做市商。

[FAQ](https://openrouter.ai/docs/faq)在本次核查时列示（2026-11-17 复核原文一致）：底层模型价格不加 token 价差；普通购买 credits 费率 **5.5%，最低 USD 0.80**；加密支付费率 **5%**。BYOK 免费额度按套餐及**目录推理成本**计算，按量套餐为每月 **USD 25,000**，超出部分按相应目录成本收 **5%**，企业套餐另议。费率与额度会变动，实际采购须保存当时条款。

不加 token 价差不等于零总费用，也不表示每个企业直签折扣都会透传。模型数量与调用榜不能用来直接推断全球市场份额或认定新进入窗口已经关闭。

### 5.4.2 差异化网关与托管

Vercel、Cloudflare、LiteLLM、TensorZero、Portkey 等在部署、观测、评估与企业治理上各有侧重；fal.ai、Replicate 等覆盖多模态托管。自托管可减少某些中介数据流，但若仍调用外部模型，提示词仍可能出域。数据驻留取决于完整调用链而非产品标签。

## 5.5 账户、钱包与授权层

Privy、Turnkey、Crossmint、CDP 等提供不同的密钥、签署和支付能力。具体是否托管、使用哪种隔离技术、支持哪些策略，应按产品版本核查。

机器支出控制至少需要：任务身份、收款方允许列表、金额和频率限额、并发预算预占、撤销与到期、幂等重试、审计与争议证据。提示词中的“不要超支”不能替代这些确定性约束。钱包服务也不自动等同于存管银行或保证金清算机构。

## 5.6 需求侧观测与统计边界

“Tokenmaxxing”等社区用语可以作为行为观察，但缺少代表性样本时不能证明行业生产率或支付普及度。以 token 消耗排名评价效率，还可能奖励浪费。

Agent 错误采购确实提出授权与归责问题，但既有合同、代理、消费者与支付规则并非全部失效。AP2/SPT 增强证据与控制，不能替代司法或合同裁决。

所谓“Flow Gap”应具体拆成报告收入、年化速率、已付款调用、补贴、自交易和未结算款项，而不是将 ARR 与链上交易额机械相除。传统支付上的收入不会自动出现在链上面板中。

## 5.7 按职责回看组件位置

```text
L7 业务应用与人工核验
L6 账户、身份与支出策略
L5 支付交互、授权与任务编排
L4 路由、观测与账单治理
L3 用量、质量、SLA 与价格基准
L2 模型、推理引擎与托管
L1 GPU、网络、数据中心与电力
L0 融资、采购承诺与价格风险管理
```

这是分析分类，不是每笔交易必须逐层经过的协议栈；多家公司可纵向整合，同一层也可有不同商业模式。

## 5.8 准入窗口的检验方法

对拟采用或提供的组件，核实客户问题、现有替代品、总交付成本、数据与资金权限以及可持续收入。技术报告核验若只需普通模型调用与企业月结，就没有理由因清单中出现某协议而增加支付或代币模块。评价标准在 [ch13](16-ch13._决策框架：预先登记评价标准、采用与停止条件.md)预先确定，实际对照在 [ch15](18-ch15._试验设计与证据记录：按预设标准采用、调整或停止.md)设计。

## 5.9 大宗商品映射的限度

评测、价格评估、路由采购和清算承担不同职责。PRA 并非交易所，API 网关并非 CCP，钱包并非银行；把它们类比有助于设计职责，却不能搬用许可、资产安全或无风险保证。
