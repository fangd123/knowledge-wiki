# ch04. 概念坐标系：异构服务的四项交易坐标

> 判断一个计算商业方案，先分别写明服务计量、货币记账、结算资产和交付权利。按 token 收费与按美元收费可以同时成立；二者不应占据互斥的矩阵行。

**本章衔接：**接 [ch01](ch01-摘要.md) 的主问题，本章把候选制度拆成可填写的交易坐标；随后进入 [ch16 核心方法](ch16-token汇率.md#16.0%20核心方法阅读入口)，给这些坐标对应的账单和交付政策定成本。

## 4.1 理论框架：计价与结算的正交分离

以“输入 USD 2/百万 token、以银行卡支付”为例，四个对象分别是：

| 维度 | 本例 | 要回答的问题 |
|---|---|---|
| 服务数量单位 | 输入 token | 什么用量被计费，是否含缓存和多模态编码？ |
| 货币记账单位 | 美元 | 报价、应收款与退款以什么货币表达？ |
| 支付与结算安排 | 银行卡及其清算网络 | 谁付款、谁收款、何时最终结算、谁处理争议？ |
| 交付契约 | 指定模型的按量调用 | 是否保证质量、吞吐、可用性，额度是否可转让？ |

计价和结算可以分离，但并非完全互不影响：跨币种结算增加汇率风险，结算延迟产生信用与资金占用成本，支付资格也会限制客户范围。信用卡、银行转账、实时支付与链上转账各有时延、费用及争议机制，不能统一概括成“传统支付慢、区块链毫秒无风险”。

法币支付可以通过 API 自动执行；Agent 可以使用其委托人的受控账户。模型不具备独立法人身份，不意味着银行支付轨道不能服务自动化工作流。

在 [技术报告核验教学案例](ch00-入门预读.md#0.9%20贯穿案例与三项采购工具)中，企业可按验收任务向服务商付款，服务商内部按 token 与人工工时核算，双方用法币记账并按月结算。客户合同应约定核验范围、来源证据、人工复核和时限；这套安排已经完整，不需要先发行可流转凭证。

## 4.2 产业全景分析矩阵

下面以**服务计费方式 × 结算安排**分类。每一格还需另注记账货币；表中是可实施组合，不是已测得的市场份额。

| 服务计费方式 | 银行法币结算 | 稳定币结算 | 网络代币结算 | 合同允许的服务权益抵扣 |
|---|---|---|---|---|
| 按 token / 请求 / 图像等用量 | 普通 API 账单、预付余额 | 接受相应支付方式的 API | 具体网络允许的服务采购 | 平台服务券核销 |
| 按席位 / 套餐 | 软件订阅 | 支持该方式的商户订阅 | 特定生态订阅 | 套餐券 |
| 按 GPU 小时 / 预留容量 | 云租赁与容量合同 | 支持稳定币的算力市场 | 特定网络租赁合同 | 指定容量提货权 |
| 按验收任务 / 成果 | 专业工作流交付 | 自动化服务采购 | 链上任务托管与验收 | 联盟服务互换安排 |

同一产品可横跨多格。预付款、月结和即时付款是支付时点，不是新的货币单位；GPU 小时是投入量，验收任务是产出量，也不能混作同一计量标准。

## 4.3 典型组合的运行机理

### 4.3.1 法币记账、用量计费、法币结算

供应商记录 usage，按价格表生成账单，再从预付余额扣款或按合同月结。模型托管、账单治理、税务开票和质量保证均可提供差异化服务，采用法币结算并不意味着创业空间已被封闭。

### 4.3.2 法币记账、稳定币结算

商户可将一次任务标为 USD 5，再接受相应稳定币付款。必须说明资产、网络、兑换率、网络费用、到账条件和退款方式。稳定币可能偏离锚定值；发行人、托管人、桥与收款商户的风险不会因链上转账而消失。

### 4.3.3 预付服务余额与固定配额

“充值 USD 100，按当时价格扣款”与“买入固定版本的一百万输出 token”是不同契约。前者在降价后可能购买更多服务，后者的替代采购价值可能下降。额度耗尽后的阻断还存在异步计量与并发超支窗口，需要网关预占预算和最终对账。

### 4.3.4 HTTP 支付交互：x402 与 MPP

[x402 官方流程](https://docs.cdp.coinbase.com/x402/how-it-works)包括返回支付要求、客户端签署支付凭证、服务方或 facilitator 验证、执行请求及结算。支付凭证不一定是已经广播交易的哈希；具体先后关系和报头取决于协议版本与 scheme。认证、额度限制和支付验证也不必是同一个动作。

[MPP](https://stripe.com/blog/machine-payments-protocol)由 Tempo 与 Stripe 于 2026-03-18 联合发布。Stripe 实现支持稳定币，也支持通过 Shared Payment Tokens 使用卡及先买后付方式。因此，不能将 MPP 固定放在“稳定币专属”象限，更不能把协议的存在视为稳定币已成为行业主流的证据。

### 4.3.5 网络代币激励与服务收入

Bittensor、Virtuals 等生态的代币可承担激励、质押或特定交易用途，但具体子网如何收费须逐项核实。验证者评分与代币排放不是每一次外部服务收入；代币上涨也不是客户购买推理的同义表达。

### 4.3.6 可转让计算服务券的理论安排

假设联盟承认一张券可兑换指定服务，用户 A 可用券向 B 支付报酬，B 再要求发行方履约。这是服务请求权的转让，须有承兑、转售授权、余额账本和违约处理；不是把已经生成的文本词元当作货币划转。

若发行方只提供一个模型、可随时调价或限制到期，券的货币功能就很有限。许可链或第三方托管可以记录转移，但不能凭技术扩张上游服务合同的权利。

### 4.3.7 容量采购与反向拍卖

Akash 等市场以需求、竞价和租约配置计算资源。竞价机制不决定结算资产，也不保证“全市场最低成本”：硬件规格、网络、数据搬迁、可用性与支持服务均需比较。不能把 Akash 一概标为银行法币结算，也不能把租用 GPU 小时称为已经交付合格业务成果。

### 4.3.8 分布式任务交付与验证

Render、Gensyn、io.net 的工作负载和验证机制不同。复制执行、挑战、概率检查、可信执行或密码学证明均有适用边界，不能将它们统一描述为“节点提交 ZKP，链上即验证任意推理质量”。计算过程正确与答案符合业务要求仍是两层问题。

## 4.4 矩阵能够支持哪些产业判断

这张矩阵支持按客户约束组合用量计费、软件订阅、任务交付与自动付款，而不是预测所有产品沿某条对角线迁移。采用哪一格，要比较新增价值、完整成本与可执行权利。

比较方案时，应衡量每次已验收交易的支付、对账、资金占用及失败处理总成本。微额调用可以先记账、周期净额结算，未必需要每生成一个 token 就发生一笔交易。

## 4.5 目标客户与场景约束

| 客户类型 | 首先核实的需求 | 候选安排 |
|---|---|---|
| 大型企业 | 采购合同、成本中心、数据边界、发票和审计 | 企业月结、预算账户、按量或容量合同 |
| 开发者 | 价格透明、接口兼容、可用性与小额付款成本 | 预付、按量、订阅或自动支付 |
| 链上组织 | 国库资产、签署权限、适用法域与出入金 | 允许的代币或稳定币工具 |
| 消费者 | 可理解价格、授权与退款、总预算 | 套餐或任务定价、熟悉的支付方式 |
| 受托 Agent | 幂等、限额、撤销、收款方验证、故障恢复 | 委托人账户加确定性策略执行 |

这些是访谈清单，不是“开发者天然偏好稳定币”“企业绝对排斥加密资产”的人口统计结论。

## 4.6 与大宗商品贸易的可迁移经验

“Brent 基准 ± 升贴水，以美元结算”里，Brent 是价格参照，桶是数量单位，美元是货币单位。SWIFT 是报文系统，信用证是银行有条件付款承诺，仓单是货物权利；它们不能并列为同一种结算货币。

可迁移的机制是质量与交付条件、基准选取、价差规则和争议证据。这个类比支持清晰订约，不能单独证明某一支付资产必然胜出。

## 4.7 本章小结

一套可核查的商业坐标应写成“计量方式 + 价格函数及货币 + 结算安排 + 交付权利”。只有各项权利和收费边界明确，才能比较不同处理政策的成本；采用新的付款轨道不是独立的收益证明。
