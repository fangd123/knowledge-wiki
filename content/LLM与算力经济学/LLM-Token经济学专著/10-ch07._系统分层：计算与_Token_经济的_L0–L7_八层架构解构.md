# ch07. 系统分层：计算与 Token 经济的 L0–L7 八层架构解构

> L0–L7 是本书的分析框架，不是已获行业认可的技术标准，也不意味着每笔调用或现金流必须依次经过八层。使用它是为了明确职责、风险与收入边界。

**本章衔接：**[ch06](09-ch06._服务契约的四组约束：计量、权利、漂移与归责.md)确定可执行性约束，本章回答由谁承担这些职责；再到 [ch05](08-ch05._生态地图：全球计算经济与支付结算全景透视.md)选择或核查实际组件。先有职责图，再看项目清单。

## 7.1 为什么需要分层分析

技术产业可能专业化，也可能因协调、效率或竞争而纵向整合。“所有通用技术必然水平解耦”不是定律；OSI 是通信概念模型，也不是产业必然分层的经验证明。

本框架用于回答：谁生产服务，谁计量与验证，谁承诺履约，谁承担资金和价格风险，以及终端收入如何支付这些成本。不能将某层的总营业收入与另一层的毛利相加后称为终端收入分配。

## 7.2 计算与 Token 经济 L0–L7 八层全景栈

| 层级 | 主要职责 | 主要分析单位 |
|---|---|---|
| L7 应用与工作流 | 完成业务任务并验收 | 合格成果、客户留存、贡献毛利 |
| L6 账户与支出控制 | 授权、预算、身份与密钥管理 | 受控支付、余额义务、异常损失 |
| L5 协议与任务编排 | 机器可读交互及授权证据 | 协议兼容、验证与争议流程 |
| L4 路由与治理 | 模型选择、可观测性与账单管理 | 总交付成本、可靠性、服务费 |
| L3 计量与基准 | 用量、质量、SLA 与价格比较 | 测量口径、代表性与治理 |
| L2 模型与推理 | 权重、推理引擎、托管服务 | 模型能力、成本、利用率 |
| L1 计算基础设施 | GPU、网络、存储、机房、电力 | 可交付容量、TCO、地理限制 |
| L0 融资与跨期风险 | 资本、采购承诺、风险管理 | 现金流、信用、价格与容量风险 |

L0、L3 和 L6 常横向覆盖多层，而非只位于单一调用链中。直接购买模型 API 的应用可以不使用第三方路由或链上支付。

## 7.3 各层的经济机理与约束

### L0. 金融资本与跨期风险管理层

股权、信贷、租赁、预付采购和衍生品的现金流及法律属性不同。普通企业可以融资或签供应合同，不能一概称 L0 为持牌机构专属；面向他人经营特定金融业务时才需按活动与法域判断许可。

预付最低消耗不必保证供给，现金结算也不提供容量。GPU 期货的公告、数据上线与正式交易应分开，已核验状态见 [ch05](08-ch05._生态地图：全球计算经济与支付结算全景透视.md)。项目现金流建模见 [智算中心全生命周期财务模型与敏感性测算手册](../智算中心全生命周期财务模型与敏感性测算手册.md)。

### L1. 物理算力与硬件基础设施层

芯片设计、制造、封装、云租赁和机房运营的壁垒不同，不能统称一个利润率相同的垄断层。资本、供电、互连与利用率往往重要，但“并网普遍需 3–5 年”必须有地域和项目样本。

中小团队是否自建取决于稳定负载、设备来源、运维能力、数据要求和替代租赁成本。单凭企业规模或芯片名义性能不能判断胜负。

### L2. 基础模型与推理工厂层

训练研发、开放权重、后训练和托管可由不同企业承担。高沉没研发支出可能推动集中，但 Sutton 类模型有质量竞争与需求等假设，不能据此证明“通用模型新进入窗口永久关闭”。详见 [大模型层的内生沉没成本、开源溢出与价格歧视均衡](../大模型层的内生沉没成本、开源溢出与定价机制.md)。

开放权重也不把服务成本压到电费：折旧、闲置容量、网络、人员、研发和资本成本仍需覆盖。不同许可证还可能改变商用与托管选择。

### L3. 计量标准、质量审计与价格基准层

Tokenizer 计量、MLPerf 工作负载性能、云集群评级、GPU 租赁价格和模型任务质量分别回答不同问题。不能将 OCPI、Silicon Data、MLPerf、Arena 和 Artificial Analysis 当成可互换的“智能指数”。

有用的基准须公开样本、版本、质量门槛、硬件/服务规格、缺失值处理和修订政策。行业任务成本仍有改进空间，但已有测评和成本工具，不能宣称整层空白。路由经营者发布指数时应披露样本偏差与利益冲突，不应把自有流量直接当全市场。

### L4. 智能路由与治理层

路由选择模型、供应商与失败回退路径，价值在于降低合格交付的总成本，或改善可靠性与治理。OpenRouter 当前费用见 [ch05](08-ch05._生态地图：全球计算经济与支付结算全景透视.md)；“0% token 价差”不等于零总费率，也不是市场垄断证明。

私有网关不自动使外部 API 数据留在本地。使用低价模型也可能增加验证与返工。应把分类器、缓存冷启动、评测及运维费用一起计入。

### L5. 通信、支付与授权协议层

x402、MPP、AP2、A2A 与不同 ACP 不是一个层次的替代品：它们分别侧重付款交互、授权或任务协作。开放协议可能降低集成成本，但并不自行提供牌照、资金保管或商业仲裁。

兼容已有协议通常有价值，是否支持多种协议应按实际客户需求决定；没有必要仅因协议存在就全部接入。

### L6. 账户、钱包与授权托管层

密钥托管、预算控制、账本和支付执行可以分离。预算系统应原子预占并在超时、重试和退款后正确释放或结算；“调用前检查剩余额度”不足以处理并发超支。

安全、客户资金责任、数据访问与故障赔偿是产品核心。软件提供者、钱包托管人和支付服务商的角色须在合同与实际资金流中一致。

### L7. 终端应用与垂直工作流层

应用把模型接入业务流程，客户为结果、方便或风险降低付费。行业数据、分发渠道和工作流嵌入可能形成优势；专家反馈只有在准确、获授权且能改善结果时才增加价值。

积分并非数据反馈的必要条件。现金报酬、员工工作流、订阅或声誉也可能更有效。应测量人工复核后的完整成本和客户复购，不能把“有闭环”直接当成护城河。

## 7.4 八层结构的可比评估

分层用于定位职责，比较则应回到同一客户和合同。对候选项目填写下表，而不是为整层赋予统一利润或成功率：

| 问题 | 可观察证据 |
|---|---|
| 客户为何需要独立供应商？ | 真实采购需求、替代方案与流失原因 |
| 收费是否覆盖交付成本？ | 账单、人工、支持、退款与获客成本 |
| 哪类投资不可回收？ | 研发、集成、硬件、牌照与合同义务 |
| 优势是否可持续？ | 留存、迁移成本、数据权利、竞争响应 |
| 风险由谁承担？ | SLA、资金与数据流程、损失及赔付上限 |

## 7.5 价值分配与战略假说

议价权可能集中在稀缺基础设施、差异化模型、客户入口或独立基准，但它会随替代品、供需与监管变化。收入、成本与资本投入须按具体合同分账，方法见 [ch09](12-ch09._价值链分布：利润池结构、议价权与演化迁移.md)。

“应用 + 路由 + 预算治理”可以协同，也会增加维护负担。独立指数也可能带来长期收入，但公信力和合同采用不能由数据积累自动推出。算力服务与商品市场的对应应作为业务设计假说。

## 7.6 将分层映射到同一任务队列

以 [技术报告核验教学队列](03-ch00._入门预读.md#0.9%20贯穿案例与三项采购工具)为例，区分必要职责与是否外购独立产品：

| 职责 | 在队列中的落实 | 不必额外建立的安排 |
|---|---|---|
| L7 业务交付 | 客户定义用途，服务方承担核验与交付责任 | 不必用积分代替专家现金报酬 |
| L3 计量与验收 | 记录全量任务、账单、来源证据与裁决 | 内部比较不必先发布公共指数 |
| L4/L6 运行与支出治理 | 选择服务、预占预算、限制权限并对账 | 既有工具足够时不必自建网关或钱包 |
| L1/L2 供给 | 按许可和 SLA 采购托管推理或部署模型 | 不必自建机房或采用分布式网络 |
| L0/L5 合同与交互 | 约定付款、交付、授权与争议证据 | 普通月结不必升级为代币或金融对冲 |

一家公司可以承担多项职责，也可以采购外部能力。组织选择应比较协调成本、专业能力和责任边界；产品组合见 [ch08](11-ch08._六组可组合方案：客户问题、交付责任与单位经济.md)，基准用途比较见 [算力与Token价格基准构建与撮合演进指南](../算力与_Token_价格基准构建与撮合演进指南：PRA_方法论与市场设计实践.md)。

## 7.7 本章小结

分层的产出是一张职责与依赖图：哪些能力必须具备，谁承担义务，哪些已有工具能够满足要求。它不规定每一层都要成立独立公司，也不预测利润固定归属。
