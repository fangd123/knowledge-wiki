# 算力与 Token 价格基准构建与撮合演进指南：PRA 方法论与市场设计实践

> **导读**：本篇集中提供基准与撮合项目的实施方法：先验证客户问题与替代方案，再按用途选择采价、合同、治理和法律安排。市场事实查 04 的日期化台账，机制解释查相应理论篇；这里的试点与模板不是已经完成的客户验证。

## 零、项目入口：反事实、客户净收益与停止条件

### 0.1 先填客户决策卡，再决定是否建设基准

每个项目先记录主体、具体任务或净现金流敞口、质量/时限约束、现用工具和可接受风险。随后比较以下选项；法币结算、双边合同及现有数据库可以是长期方案，而不只是过渡阶段。

| 客户问题 | 必须纳入的比较基线 | 主要评价指标 | 不采用或停止条件 |
|---|---|---|---|
| 采购价格难比较 | 同规格 RFQ、现有数据库、账单审计 | 同质量总支出、寻源工时、错误/争议成本 | 改善来自降质或客户选择偏差；收益不足以覆盖数据和集成成本 |
| 未来租价风险 | 不套保、固定价合同、封顶/重议条款、适配衍生品 | 样本外现金流波动、尾部损失、基差及资金占用 | 基差不稳定、缺少可执行报价或保证金压力超过预算 |
| 容量/交付不足 | 预留、验收、SLA、备用供应商 | 合格交付、业务中断损失与备用成本 | 仅得到现金赔付而关键业务仍无法交付；备援无实测能力 |
| 信用与期限错配 | 押金、担保、抵押、现金缓冲；有实际供给时比较保险 | 违约损失、期限缺口、集中度、担保/保费 | 缺承保或资金支持；压力情景仍不可承受 |
| 融资估值困难 | 合同现金流分析、设备评估与既有信用模型 | 对信用判断、估值区间和尽调效率的增量信息 | 指数不能解释净现金流/残值，或增加模型误判 |

### 0.2 独立验证与影子套保的执行顺序

1. **冻结对象与基线**：固定服务规格、账单口径、样本期、客户群和替代方案；先定验收质量、风险预算、成本上限及停止条件。指标和阈值由项目承担者预先选择，不用统一行业数字替代判断。
2. **核验数据而非先看曲线**：区分报价、新成交与存续租赁；关联方和重复记录去重，检查来源集中度、缺失、版本及修订。用未参加指数编制的授权账单、独立抽样或留出来源验证目标市场覆盖，避免用同一输入自证代表性。
3. **以样本外结果比较方案**：训练期只用于选基准、估套保比率与规则，留出期评价表现，滚动时保留当时可得数据版本。影子套保记录实际采购/销售现金流、假设合约支付、基差、数量/期限错配、费用和保证金流；没有可执行报价时只报告模型敏感性，不称可实现交易收益。二元合约须按实际阶梯支付测算，不替代为线性对冲。
4. **核算客户净效益**：比较同质量下的总支出、操作工时和争议损失；风险管理另报告尾部损失及现金缓冲需求。扣除订阅、集成、核验、交易、资金、治理和合规增量成本，避免把风险下降和其货币估值重复计为两份收益。前后对比须控制规格、市场价格与客户构成变化；无法控制时只列关联结果。
5. **小范围采用、复评或退出**：数据充分且样本外改善超过预设门槛，再进行限用途试点。数据失效、基差漂移、成本超标或客户不续用时，暂停扩展、收窄覆盖或回到原有合同；已进入结算的产品按预定停编与替代条款过渡。

### 0.3 五本账：不要用采用自证价值

| 账目 | 能证明什么 | 仍须另行证明什么 |
|---|---|---|
| 数据质量 | 指定对象的覆盖、可追溯性和误差 | 有客户愿意付费或其决策改善 |
| 合同采用 | 某份合同引用、实际使用及存续规模 | 数据代表性、付费授权和净客户效益 |
| 客户净效益 | 相对已有方案的经验证改善 | 数据商能获得多少收入、社会净福利是否同幅增加 |
| 机构经济性 | 实收收入、续费、获客与持续维护/责任成本 | 超额租金、永久壁垒或全行业福利 |
| 市场势力与租金 | 结合替代选择、切换成本和正常回报分析的超额收益 | 仅凭高融资估值、合作名单或合同数量不能确认 |

事件盘口预测的是基准未来取值；依基准赔付证明引用规则被执行。**两者都不是对底层市场代表性的独立验证。** 客户试点通过也不自动授权金融用途，后者还须评估结算风险和适用法律。

## 一、价格口径：挂牌价、可执行报价与成交价

价格评估首先要界定研究对象：公开零售价、可执行报价和实际成交价可能不同，也可能一致。可执行（tradable）不等于已成交（transacted）；是否纳入指数，应由基准所代表的市场与证据质量决定，而非由报价公开与否决定。

### 1.1 算力租赁侧的价格离散与隐性条款

在 GPU 裸金属、八卡整机与智算集群租赁市场上，表面上针对同一款芯片的报价往往相差数倍，其失真根源来自四重机制：

1. **零售与长协的条款差异**：目录价与长协价的差异可能补偿期限、起购量、可撤销性和信用风险。未经同规格样本验证，不应宣称普遍有40%–50%折扣，也不能把不可撤销长约直接与随用随退价比较。
2. **销售层级与渠道链条叠加**：同一批物理服务器在大型 IDC 整机直供批发、区域云平台分销、二层代理转租以及开发者散装切片零售平台之间流转，每一层均叠加不同的空置风险溢价与账期成本。
3. **捆绑销售与补贴扭曲**：部分低价宣传样本隐去了强制捆绑的高价并行存储、公网带宽回传费或驻场运维费；而部分区域智算中心的低报价则计入了地方“算力券”或专项电费补贴（仅对特定注册地或特定白名单企业生效，不具备普遍可成交性）。
4. **有价无市与排期断层**：在供应链紧俏期，部分网页挂出的低价属于早已售罄的历史残留报价（无现货库存、交付排期长达数月）；而在局部产能过剩期，机房为保现金流私下给出的实单底价又远低于官方对外报价牌。

### 1.2 模型 Token 侧的价格幻觉与非对称计费

在大模型 API（MaaS）市场上，“每百万 Token 标价最低”同样远不等于“真实采购成本最低”：

- **Tokenizer 不统一**：同一文本的 Token 数可能不同，须保存测试文本、切词器与版本，不能用统一百分比替代实测。
- **计费结构多维化**：分别记录输入、输出、缓存、批处理、上下文区间和速度档位；输入输出倍率不是统一常数。
- **价格不揭示全部成本或能力**：低价可能来自效率、促销、补贴或服务边界差异。没有供应商成本证据不能直接认定低于全成本；配额、模型路由及质量须单独核验。

### 1.3 五类来源与交易状态标签

为识别证据差异，本文提出五类来源标签。它们不是天然从低到高的可信度排序；同一来源也可能同时具有多种交易状态。若组合使用不同输入，应披露选择、权重与回退规则，不能无说明地简单混算：

| 来源或交易状态 | 定义与采集来源 | 商业可执行性特征 | 在价格评估体系中的定位 |
|---|---|---|---|
| **官网目录标价** | 官方公开挂牌价 | 若容量可用、条款完整且可直接购买，可能就是可执行零售价 | 用于公开调价监测或对应零售指数；不能因来自网页便一律排除 |
| **市场宣传报价** | 销售海报、社群推广、招商推介材料报价 | 常缺失税费、有效期、SLA、起购量等前置约束 | 可保留为宣传观察样本；补齐目标口径要求的条件前，不作为可执行价或成交价 |
| **渠道与代理报价** | 算力经纪商、云代理商、系统集成商对外报价 | 需核实上游真实授权、排期确定性与垫资账期 | 可观察渠道报价及流通环节差异，不自动代表终端成交 |
| **定向询价（RFQ）报价** | 针对明确业务规模、配置、租期与合规要求的回复 | 有配置和有效期也未必可立即接受，须核实保留条件、容量及约束力 | 可纳入对应报价库；不因形式正式就自动给高权重 |
| **已成交价** | 可核对交易标识、时间、数量、完整条款及履约状态的脱敏实单 | 成交也须排除关联交易、虚假过单及特殊补贴 | 与可执行但未成交的报价分列；真实不等于代表性充分 |

这五类标签是内部记录方式，并非公认的质量等级。**来源渠道与交易状态应分字段保存**，例如官网也可能产生可核验成交；若方法组合使用，应解释适用目的及权重。同一笔上游成交被多家代理转载时须去重，并按共同控制主体识别独立信源。

## 二、异质算力的归一化方法：从“裸价差”走向“有效价差”

算力与大宗标准工业品（如 99.99% 电解铜）最大的不同在于其高度的多维异质性。市场研究者与采购方最常犯的方法论错误，就是拿着中西部某机房的“裸卡时低价”与东部沿海核心机房报价直接横向相减，得出存在巨额套利空间的误判。

### 2.1 核心原则一：裸价差 ≠ 有效价差——把“带宽与时延”视为场景硬约束

以跨区域采购为例，电价、土地、冷却和网络条件可能不同，但具体差异应由同日、同负荷口径的报价证明。不能用未注明地区和时段的电价区间代表整个东西部市场。即使裸租金较低，“便宜”也不自动等于“可用”：

- 西部算力节点距离东部终端用户与企业内网物理距离数千公里，光纤传输时延较高且跨省大带宽专线回传费用昂贵；
- 离线任务往往更能容忍传输延迟；跨城同步训练、高频控制和一般在线问答的时延预算差别很大。**不能笼统认定远端机房无法做在线推理**，应以实测网络、TTFT和端到端SLA判断。

因此，对跨区训练、低时延推理等依赖网络的任务，“跨区带宽与网络时延”不只是一个附加运费项，而是决定该批算力能否进入特定买方候选池的**可用性边界（Scenario Availability Constraint）**。这类区域比价不应停留在笼统的“裸卡时横比”，而应计算**“分场景/质量调整后的有效价差”**；对不受网络约束的离线任务，则按实际约束选择比较口径：
- 在**离线训练与批处理货架**上，将西部裸算力租金加上必要的数据集传输、驻场运维折算与故障恢复损耗后，与东部同规格集群比价；
- 在**低延迟在线推理货架**上，严格在满足城域/区域毫秒级时延圈与并发 SLA 达标的合格节点内部进行横向比价，不将时延不达标的异地低价样本混入拉低基准。

### 2.2 核心原则二：先验证价差主因，不预设“地理区域”为唯一主轴

不能预设电价是主要因素，也不能用固定的电费/折旧占比反证它不重要。成本占比取决于造价、寿命、利用率和核算边界；全球供应链并不使不同法域、配置和交货期的硬件价格统一。先计算各项目 TCO，再对同口径交易样本检验价差来源。

若用途是解释跨区价差或检验归一化规则，可在可比样本上采用分层比较、特征回归或**方差分解（Variance Decomposition）**等方法。方法取决于样本覆盖、变量重叠与可识别性，不把某一种分解设为所有基准的统一门槛，也不以解释方差直接决定指数权重。可考察的因素包括：

1. **芯片代际与互联规格因子**（如旗舰受限卡 vs 合规主力推理卡 vs 国产主力卡，SXM NVLink 整机 vs PCIe 单卡）；
2. **局部供需松紧与交付排期因子**（现货即开即用 vs 排队等待数周、紧缺整机集群不拆分溢价 vs 零散尾货折价）；
3. **地理区域能源与政策因子**（工业电价梯度、气候 PUE 差异、地方算力券/电费补贴、靠近大客户研发总部的区位溢价）。

这些比较首先描述相关性，不能未经识别便归因为电价或政策的因果效应。样本不足时可保留分项报价和未识别范围，不强行合成统一指数。网络与地理限制可能长期存在，但业务组合、带宽成本、资本流动和供给变化仍会改变价差，不能据此推出“永久不收敛”。

### 2.3 统一可比报价字典（Standardized Quote Schema）

为实现跨服务商、跨区域的同口径归一化，本文建议样本库采用统一的结构化字段字典，缺失字段显式标注而不是静默混算。下列为按用途裁剪的候选核心字段，不是对所有机构的强制标准：

| 算力租赁样本库核心字段（17 项） | 模型 Token 与 API 样本库核心字段（17 项） |
|---|---|
| 1. 物理地理分区与具体可用区（时延圈） | 1. 供应商名称与角色（模型原厂 / 云托管商 / 路由聚合商） |
| 2. 服务商类型（公有云自营 / 大型 IDC / 专业算力云 / 渠道转租） | 2. 模型精确名称、版本号与参数/架构类别 |
| 3. 加速卡具体型号与单卡显存容量 | 3. 部署交付模式（公有共享 API / 云端专属实例 / 本地私有化） |
| 4. 计费颗粒度单位（卡时 / 卡月 / 八卡整机月 / 千卡包年） | 4. 输入 Token 单价（元/百万 Token，区分阶梯） |
| 5. 机内物理互联（NVLink / HCCS / PCIe）、机间组网（IB / RoCE）及通信库版本（NCCL / HCCL） | 5. 输出 Token 单价（含推理模型思维链计费规则） |
| 6. 配套 CPU、系统内存与本地/并行存储规格 | 6. 上下文缓存价格（Cache Hit / Cache Miss 计费标准） |
| 7. 公网带宽、跨区回传条件与专线费用口径 | 7. 离线批处理（Batch）折扣率与长上下文分段加价阈值 |
| 8. 准入适用场景标签（分布式训练 / 低时延推理 / 批处理） | 8. 最大支持上下文窗口长度与单次最大输出限制 |
| 9. 资源独占性（物理独占 / 虚拟切片及超卖比） | 9. 并发与限流配额（RPM、TPM、最大并发连接数） |
| 10. SLA 可用性承诺、故障响应时效与中断赔付/赠时规则 | 10. 性能实测表现（首字延迟 TTFT、每秒生成 Token 数 TPS） |
| 11. 合同期限与折扣结构（按需 / 包月 / 包季 / 闭口包年） | 11. SLA 可用性承诺与限流降级保护条款 |
| 12. 电力计费方式（全包价 vs 裸机柜加电费按实结算）及当地电价 | 12. 数据安全与合规承诺（零留存、不用于模型训练、境内不出境） |
| 13. 政策补贴状态（是否已抵扣算力券或地方电价补贴） | 13. 起购门槛、预充值阶梯折扣与年度用量包折让率 |
| 14. 现货状态与预计上线交付周期 | 14. 额度有效期与到期展期/结转规则 |
| 15. 含税口径与增值税发票类型 | 15. 含税口径、币种结算方式与账期（预付 / 月结） |
| 16. **来源渠道、交易状态与核验记录** | 16. **来源渠道、交易状态与核验记录** |
| 17. 报价有效截止日、信源编码与采价时间戳 | 17. 报价有效截止日、信源编码与采价时间戳 |

## 三、报价样本库冷启动与“广度 + 深度”双轨采价机制

在缺乏集中行情的早期阶段，可以先维护有版本、字段与来源记录的结构化样本库，再结合自动采集和人工核验。更新频率应与市场变化及用途匹配，不能默认月度采集足以支持日度结算基准。

### 3.1 双轨采价建议：自动采集与人工核验互补

公开目录、可执行订单和双边协议可能服务不同客户群。自动采集与人工核验可互补；不预设所有目录价都无用，或所有重要交易都只能依靠访谈取得。建议分工如下：

| 采价轨道 | 执行主体 | 核心覆盖对象 | 核心产出价值 |
|---|---|---|---|
| **广度轨（公开监测层）** | 自动采集与异动探测 | 模型价格页、实例目录、版本及扩产公告 | 按已披露覆盖范围和频率监测，保留抓取失败及数据年龄；不承诺全市场实时覆盖 |
| **深度轨（实单核验层）** | 分析师与授权数据接口 | 买卖方报价、合同、订单及账单 | 区分报价与成交，核实条款、实际付款及关联关系；授权采购接口可与人工访谈并用 |

同一买方向多家供应商发出的可比RFQ，有助于控制客户需求差异。但报价回复不是成交，最终选择也受信用、关系和未观测质量影响。应将回复、落选原因、签约与履约证据关联保存，不能把这种案例视为消除了全部噪声或可单独识别地区因果价差。

### 3.2 按需求选择产物：允许止步于报价观察

共同底座是有版本的字段、来源、权限和质量记录；采样范围随用途确定。通过第零节的验证后，选择下列产物，而非依次升级：

| 经验证的需求 | 可交付产物 | 发布前的条件 |
|---|---|---|
| 内部采购留痕 | 内部报价/账单样本库 | 字段可追溯、合法授权；无需公开指数 |
| 观察某细分市场 | 报价区间、行业内参 | 标明来源类别、覆盖、样本年龄与不确定性 |
| 组织同口径采购 | 标准 RFQ、供应商比选与部署拐点测算 | 真实客户需求、履约责任与利益冲突控制 |
| 持续比较价格或任务成本 | 指定用途价格指数/有效成本指数 | 稳定采样、样本外验证、版本与停编机制 |
| 合同调价或金融结算 | 适配的基准授权 | 在前项数据条件之外验证基差、操纵成本、责任与法律适用 |

需要报价不等于需要撮合，需要采购参考也不等于需要金融结算。若现有数据或双边合同已满足需求，项目可以停止于其中任一产物。

## 四、交易组织选项与商业合同锁价机制

是否撮合、承担履约或提供指数是不同经营选择。授权报送、采购系统接口、账单核验和客户 RFQ 都可成为采样渠道；应比较其成本、选择偏差和利益冲突，而不为获得数据预设必须经营交易市场。

应先区分资源、服务用量与合同权益，再按数据来源、客户需求、利益冲突及适用监管选择业务范围；不参与撮合也可通过授权报送、订单接口和账单核验获取样本。

### 4.1 底层分流：容量转售与API代采取决于契约权利

卡时与Token首先是不同服务的计量单位；可转让的对象是容量或服务权益，而不是单位名称本身。相关合同差异如下：

| 对比维度 | 算力卡时 / 整机产能（Compute Capacity） | 模型词元 / API 用量（Model Token） |
|---|---|---|
| **标的可比性** | 必须固定卡型、软件、拓扑、地点和SLA；相同硬件不保证不同任务性能相同 | Token用量不可天然跨模型等价；平台可另设服务兑换规则，但不改变任务成本差异 |
| **权益可转让性** | 预留容量能否转租、拆分和转让取决于上游合同、技术隔离与交付资格，不是卡时的固有物理属性 | Token是计量单位；预付额度、授权经销权或服务凭证能否转让取决于具体合同，不能一概认定可转或不可转 |
| **需要核验的市场形态** | 容量撮合、预留转售与硬件买卖分别核验平台规则、转让授权和实际成交 | 聚合路由、集采、预付额度转让是不同安排；不能仅凭常见形态断言全球没有其他市场 |
| **可测试的采购组织形式** | 一对一协议对接、授权闲置容量调剂 | 多供应商标准 RFQ、集采比选 |

### 4.2 四类交易组织方案：按责任与用途组合

四类方案不是市场成熟度排序。固定价采购不需要第三方指数；信息服务可以长期独立经营；金融套保也不要求同一经营者先建设撮合平台。

| 功能 | 交易组织形态 | 核心机制运作方式 | 数据与责任要求 | 客户用途 |
|---|---|---|---|---|
| 信息服务 | 结构化报价与需求匹配 | 区分宣传、报价与成交，双方自主签约 | 广告、数据、居间与行业资质责任 | 寻源、预算与市场观察 |
| 询价与协议采购 | 任务型 RFQ 与容量采购 | 同规格比价、一单一议 | 代收资金、代签或承担履约会改变义务 | 采购与交付，不自动形成代表性市场样本 |
| 商业合同 | 固定价/浮动价长协、任务用量包、容量预留 | 约定数量、价格、服务、取消和违约责任 | 可裁定计量；选择指数调价时才额外需要适配基准 | 锁价、保供与灵活性之间的取舍 |
| 金融风险管理 | 场内期货或合规场外衍生品 | 按合约支付转移价格风险 | 适配敞口、基差、流动性、保证金与相应资格 | 不承担底层服务交付；可与商业采购组合 |

### 4.3 如何选择商业锁价、容量保障与金融套保

固定价商业采购可能更直接满足早期企业需求，但不是唯一正确工具。应根据敞口、供应保障、基差、流动性和合规条件选择，也可组合使用：

1. **交割与套保适配问题**：过去未使用的卡时不能储存，但可约定未来时段提供容量，或按指数现金结算。不可储存不等于不具备期货条件；技术降本也不意味着做多套保必然亏损，应比较锁价、基差及风险预算。
2. **分开管理价格与供应风险**：现金结算衍生品可用于价格风险管理，却不保证实际容量可得；SLA与备用容量也不自动锁定全部成本。两类工具可能互补。
3. **按法域与交易实质判断**：中国现货交易场所、场内期货、场外衍生品及支付凭证适用规则不同。不能把集中竞价、保证金或T+0等单一特征写成“各国一律禁止”的充分条件；落地前须核对最新法规、主体资格与具体合约设计。
4. **电力中长期合同的有限类比**：电力也受时段与容量约束，虽可通过储能转移一部分供应，仍不能把今日服务时段直接留到未来。可借鉴其锁价和容量安排，但算力的技术、网络与监管边界不同；以下条款均需定价、协商和履约保障：
   - **年度阶梯固定价与封顶保护条款（Price Cap + Downward Adjustment）**：约定年度基准采购量与封顶单价，防止算力紧缺期成本失控；同时设置“官方公开降价联动下浮条款”，避免在技术通缩期沦为高价冤大头；
   - **指数挂钩浮动长协**：可以按季度参考适配指数在约定区间调价；这改变双方价格风险分配，但不消除客户违约、基差或容量不足风险，任务有效成本指数也不能未经转换代替GPU租价指数；
   - **高峰容量预留（Capacity Reservation）与 SLA 偏差结算**：针对财报季、促销季或集中训练窗口提前认购保底并发吞吐（Provisioned Throughput / 预留卡时），明确未达标时的费率扣减、额度展期与备用资源池自动切换条款。

## 五、价格基准中立性与撮合业务的利益冲突隔离原则

同时提供价格评估与交易服务会形成潜在利益冲突。应根据控制权、数据来源、人员激励和持仓设置并检验控制，而非只凭业务名称判断独立性。

### 5.1 商业定位与利益冲突：先算收益，再检验治理

利益冲突需要治理，但不等于所有基准管理员必须与交易业务属于不同法人。第三方指数授权是一种安排；关联方编制则需要相应披露、监督和控制。具体交易所合作与交易状态参见[市场核查报告](../04-算力指数与金融化机制研究/算力指数、衍生品与预测市场实证核查报告.md)，不在此把商业合作推定为独立性已经获得认证。

撮合可提供佣金收入、采购服务和数据接触机会，三者应分别核算。佣金、订阅和咨询均可能形成合理业务，也均有激励冲突；不能用“最终要成为 PRA”替代对客户需求、单位经济性和来源偏差的验证。通过撮合得到的样本也未必代表未使用该平台的客户。

如果基准分析师直接按撮合GMV与佣金考核，会增加以下风险，但不能据此认定任何具体机构已经失真或违规：
1. **激励扭曲导致数据失真**：业务人员为促成交易赚取佣金，会产生压低或抬高参考报价的利益动机，甚至为凑交易量引入虚假过单，直接污染底层价格样本库；
2. **信源参与激励变化**：贡献者可能因竞争或保密顾虑减少报送，也可能因服务价值继续合作；应监测退出、覆盖和报价偏差，而非预设全部供应商必然抵制。

### 5.2 算力与 Token 价格评估机构的四条防火墙准则

为兼顾早期实单数据获取效率与长期价格基准公信力，本文提出以下四项治理设计准则，供按业务规模和风险裁剪，并以执行效果检验；它们不是 IOSCO 或任何法规的逐条转述：

1. **组织与考核隔离**：建议将价格分析与商务拓展的决策、考核和数据权限分开，避免分析师直接按样本方交易量或广告收入获酬；具体控制按规模和冲突风险设置，并检查执行效果。覆盖、核验、方法一致性及纠错及时性可作为质量指标。
2. **商业付费不购买指数权重**：订阅、赞助或广告不应换取样本优先权。按事先公布的方法核验各类输入；离群值不自动等于错误，也不应为追求平滑而随意删除真实价格。
3. **明确收入来源与利益冲突控制**：固定咨询费、订阅费与交易佣金都有不同激励。非抽佣是本文的可选定位，不是独立性的充分条件；关联服务、持仓、人员激励及客户集中度均应披露并监督。
4. **方法披露与可审计留痕**：方法论文件说明各 SKU 参数边界、采集窗口、不同来源和交易状态的使用规则、缺样本处置及修订政策；保存版本化采价记录。商业秘密和个人信息可以分权限审计，不以全部原始数据公开为前提，也不将公开文件本身当作复算通过的证明。

---

### 5.3 授权、组织与法律审查：按实际业务逐项决策

在第零节确认用途后，再准备下列材料。治理设计是经营方案，法律义务须由具体适用规则确定；机构注册地、聚合输出或使用 IOSCO 模板都不是通行许可证。

| 决策事项 | 执行材料与审查内容 |
|---|---|
| 授权用途 | 分开研究、内部定价、再分发、盘中风控和最终结算；约定数据年龄、版本、修订通知、责任及终止，不预设离散结算一定优先 |
| 结算规则 | 固定指标代码及规格版本、观察窗口、时区、发布日、缺值回退、修订截止与争议程序；区分历史数据库纠错和已冻结结算 |
| 组织形式 | 比较现有主体、职能隔离与独立法人；按客户需求、实际控制、成本、税务实质和监管要求选择，不按融资新闻自动设立离岸中心 |
| 数据路径 | 画出采集者、处理者、接收方、字段与用途；逐项审查授权、保密、个人信息、重要数据、行业目录和出境程序，芯片名称不决定数据类别 |
| 业务与产品资格 | 核对实际提供的是数据、居间、履约、投资服务还是交易设施；境内外和场内外分别分析，不能以信息服务名义替代实质判断 |
| 连续性与审计 | 从首批样本保存报送、清洗、判断、版本和投诉记录；按适用要求设置监督/鉴证，预定停报通知、替代基准及过渡责任 |

若考虑香港、新加坡或其他法域，应比较上述业务所需的实际许可、客户接受度、法律与税务成本、数据路径及退出条件；不存在脱离业务细节的统一最优选址。聚合、去标识和权限控制可降低部分风险，但不自动豁免全部义务。

## 六、总结：按验证结果采用、收窄或退出

价格基准项目的正面链条是：**定义客户决策→识别现有方案的缺口→建立可核验样本→独立验证与客户试点→选择合适产品和治理**。报价分层、质量校准和授权账单可以改善比较；能否产生净客户效益、持续收入及可接受的结算风险，要分别验证。

项目交付至少包含决策卡、样本与版本记录、比较结果、费用/风险预算、授权范围及停止/过渡条件。选择内部工具、报价观察或双边合同本身可以是成功结果，不以发布指数、进入衍生品或设立新法人作为完成标志。

> **定位说明**：IOSCO 2013年《金融基准原则》有19项，2012年《石油价格报告机构原则》针对石油PRA，二者不是同一套编号规则。其可为算力基准设计提供参考，但不是自动适用于所有算力机构的许可证，也不保证交易所采信。以下为本文建议模板，具体披露、独立性、审计及保留义务须按适用法规与合同确定。2026-11-17 已成功重取 IOSCO 官网 PDF 全文（FR07/13，2013-07，48 页），下表编号逐项映射已按原文核对；原文要求管理员每年公开披露遵循程度并允许比例适用，具体义务仍以适用法规与合同为准。

| 章节序号与标题 | 本文建议披露的制度与数理要素 | IOSCO 参照主题（不是逐项合规认证） |
| :--- | :--- | :--- |
| **第 1 章：治理与利益冲突** | 管理员责任、监督安排、人员职责、持仓及商业利益披露；按风险选择职能隔离、限制交易和独立审查 | 原则1–5；不等于统一要求独立法人 |
| **第 2 章：基准标的物理与商务标准定义** | 明确每一只基准代码（Ticker）对应的十维硬件配置网格（芯片精确型号、显存、互联拓扑、地域时延圈、PUE 等级）、租期窗口（如 $\le 7$ 天按需即期 vs 1 年期长协）、计价币种（含税/不含税）及最小合格交易批量。 | 原则 6（Benchmark Design） |
| **第 3 章：数据源与净价** | 报送规则、来源分类、赠金和捆绑费用处理；目录价能否纳入取决于基准对象及可执行性，不能按来源标签一律剔除 | 数据充分性、输入层级与报送者行为准则 |
| **第 4 章：异质归一化与抗操纵稳健估计算法** | 非标准配置向基准配置折算的特征回归/品质升贴水表；单一数据贡献商最大权重封顶比例（如 $\bar{w} \le 20\%$）；成交量加权分位数双侧缩尾（Winsorization）分位阈值。 | 原则 6、8 |
| **第 5 章：三级流动性回退瀑布（Waterfall）** | 明确评估窗口最低合格样本量门槛（$V_{\min}$ 与最少独立报送商数 $M_{\min}$）；当真实成交不足时，依次回退至“可执行双边紧盘口（Level 2）”与“跨期衰减滚存 + 关联机型稳态比价外推（Level 3）”的确定性算式。 | 原则 7、8（Hierarchy of Data Inputs） |
| **第 6 章：受限专家判断（Expert Judgment）边界** | 穷举允许分析师行使人工复核的极端场景清单；强制双人交叉复核签字制度；月度披露各等级瀑布触发占比。 | 原则 11、12 |
| **第 7 章：方法论重大变更、重算勘误与停编过渡** | 硬件代际切换（如旧卡流动性枯竭退市、新卡增设主力代码）的触发定量指标；不少于 30 天的市场公开征求意见程序；历史数据报错重发（Restatement）时间窗。 | 原则 10、12、13（Periodic Review & Transition） |
| **第 8 章：审计留痕、外部鉴证与申诉通道** | 记录保留期、审计频率和投诉处理程序；哈希须配合可信采集与访问控制，不能证明原始数据真实 | 16投诉、17审计、18审计轨迹、19监管合作；15为数据收集内部控制（Internal Controls over Data Collection，11-17 已按原文核对） |

**模板补正**：20%主体封顶至少需要5个独立主体才可行，须在归一化后的最终权重上约束；30天征求意见、年度外部鉴证、三级回退及独立法人均为这里的设计选项，不能统一归称IOSCO强制要求。无成交日如连回退数据也不足，应允许暂停发布或标记不具代表性。
