# 终端环境改造

围绕输入效率、上下文切换与脚本执行体验做的一整套系统优化，核心目标是消除开发者在终端使用中反复遇到的摩擦点。

## 为什么值得关注

默认的终端环境（无论是Windows自带的CMD/PowerShell，还是Linux的默认Bash）在日常开发使用中存在大量可以优化的摩擦：命令输入没有自动补全、没有语法高亮导致错误难以发现、SSH断线导致远程任务中断、字体不适合长时间阅读代码。这些都不是致命问题，但累积起来每天消耗的时间和精力是可观的。终端环境改造的价值在于：一次投入，持续受益。

## 核心配置方法

**一、Windows Terminal 配置**

在Windows环境下，Windows Terminal是最值得安装的终端宿主。安装方式：微软应用商店搜索"Windows Terminal"直接安装。

核心配置项（交互式设置 > 导出备份到云盘）：
- 字体：安装 FiraCode（针对编程优化的字体，支持连字符，长时间阅读舒适）
- 字号：建议14，大屏幕下阅读舒适，不需要频繁眯眼
- 多标签和多面板：Windows Terminal原生支持，无需额外配置

FiraCode下载：从 Nerd Fonts 官方发布页获取，安装后在设置中选择 "FiraCode NF"。

**二、Shell 环境配置（Ubuntu/WSL）**

通过SSH远程连接到Ubuntu服务器时，推荐以下完整配置链：

1. 安装基础依赖：
```bash
sudo apt install -y zsh curl wget git tmux
```

2. 安装 Oh My Zsh（Zsh的配置管理框架，集成插件和主题管理）：
从 ohmyz.sh 获取安装脚本，安装后默认启用多种实用功能

3. 安装 starship（跨Shell的状态栏提示符，显示Git状态、当前目录、命令执行时间等）：
```bash
sh -c "$(curl -fsSL https://starship.rs/install.sh)"
echo 'eval "$(starship init zsh)"' >> ~/.zshrc
```

4. 安装语法高亮插件（fast-syntax-highlighting）：命令输入时实时显示语法是否正确，红色表示有误，大幅降低敲错命令的概率

5. 安装自动补全插件（zsh-autosuggestions）：根据历史命令提示补全，按右箭头接受建议，减少重复输入

**三、Tmux 配置**

Tmux是终端复用器，解决SSH断线导致远程进程中断的问题。核心价值：关闭SSH连接后服务器上的进程继续运行，重新连接后恢复会话。

推荐安装 Oh My Tmux 主题包，增强视觉效果和快捷键体验：
```bash
cd && git clone https://github.com/gpakosz/.tmux.git
ln -s -f .tmux/.tmux.conf
cp .tmux/.tmux.conf.local .
```

关键快捷键：`<prefix> m` 绑定鼠标模式；`<prefix> -` 纵向分割；`<prefix> _` 横向分割；`C-a` 作为 `C-b` 的替代前缀（键位更便捷）

## 常见问题与解决

- **Windows Terminal 远程 Tmux 无法鼠标选择复制**：这是很多终端软件的痛点，Windows Terminal 原生对此支持良好，开启鼠标模式（`<prefix> m`）后可以正常鼠标选择和复制
- **安装 Oh My Zsh 时网络超时**：使用镜像地址替代默认地址（将 raw.githubusercontent.com 和 github.com 替换为国内镜像），原始文章中提供了可用的镜像链接
- **starship 提示符乱码**：原因是终端字体不支持 Nerd Fonts 图标，安装 FiraCode Nerd Font 后在终端字体设置中选择该字体即可解决

## 扩展方向

- 探索 WSL2（Windows Subsystem for Linux 2）作为本地Linux开发环境，减少对远程服务器的依赖
- 研究 zoxide（更智能的目录跳转工具）和 fzf（模糊搜索工具）进一步减少导航摩擦
- 研究将个人 dotfiles（zshrc、tmux.conf 等配置文件）托管到 Git 仓库，实现多机器同步
- 探索 Neovim 或 VS Code Remote 结合终端的工作流
