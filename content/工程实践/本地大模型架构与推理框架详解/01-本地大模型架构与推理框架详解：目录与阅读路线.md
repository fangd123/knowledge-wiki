## 0.3 来源标记的含义

正文的关键数字和说法后面带着来源标记，表示可信度：

| 标记 | 含义 | 可信度 |
|---|---|---|
| 【文件头】 | 从本机 GGUF 文件元数据直接读出（层数、头数、维度等） | 最高，就是本机文件的事实 |
| 【源码】 | 读 llama.cpp / vLLM 等源码得到 | 高（以写作时版本为准） |
| 【官方】【官方技术报告】 | 模型卡、官方文档、技术报告 | 高，但分数是厂商自测 |
| 【论文】 | 论文结论 | 高，但实验条件可能和本机不同 |
| 【本机实测】 | 来自本机调研报告的测量 | 高，但样本量有限（见 7.3） |
| 【计算】【推算】 | 根据上面的事实按公式算出来的 | 取决于输入和公式假设 |
| 【作者自报】 | 社区项目作者自己报的数字，没有独立复现 | 中，参考用 |
| 【社区】 | Reddit、GitHub 讨论里的说法 | 中低，可能只有一两人测过 |
| 【推断】 | 作者根据原理推测，没有找到直接证据 | 低，当作假设 |
| 【已核】/【未核】 | 参考资料是否打开原文核对过 | — |

## 0.4 术语表

按首次出现的大致顺序排列，括号里是主要讲解的章节。

**模型结构**
- **Token / 分词器**：模型处理的最小单位。现代词表有 15 万–25 万个，比 BERT 的 3 万大很多（1.3）。
- **因果（自回归）生成**：每次只预测下一个 token，并且只能看前文。BERT 是双向的“完形填空”（1.2）。
- **RoPE**：旋转位置编码。通过旋转 Q/K 向量来表示相对位置，可以外推到更长的上下文（1.4）。
- **RMSNorm / Pre-Norm**：比 LayerNorm 更简单的归一化，放在子层之前（1.5）。
- **SwiGLU**：带门控的前馈层，有三个矩阵（gate / up / down）（1.5、2.3.4）。
- **GQA（分组查询注意力）**：多个 Q 头共享一组 K/V 头，KV 缓存因此成倍缩小（1.6）。
- **门控注意力（Gated Attention）**：在注意力输出上乘一个 sigmoid 门（1.7）。
- **线性注意力 / GDN（Gated DeltaNet）**：用固定大小的状态矩阵代替随长度增长的 KV 缓存。Qwen3.8 有 3/4 的层是 GDN（1.7、2.3.2）。
- **混合架构**：线性注意力层和全注意力层按比例交替，例如 3:1（2.3.3）。
- **MoE（专家混合）**：每个 token 只激活少数几个“专家”前馈层。总参数大，激活参数小（1.8、2.5）。
- **共享专家 / 路由器**：路由器决定用哪些专家；共享专家每个 token 都会用（2.5）。
- **QSA**：Flash-Next 的稀疏注意力（2.5）。
- **n-gram 表（Engram）**：查表式记忆。Flash-Next 有一张 51B 参数的表（2.5）。
- **MTP（多 token 预测）**：模型自带一个小预测头，一次多猜几个 token，可以用作推测解码的草稿（2.3.5、6.4）。
- **mmproj**：视觉编码器的投影文件，在 GGUF 里单独存放（2.3.6）。

**训练与后训练**
- **预训练 / 中期训练 / 后训练**：分别学知识、补长上下文和推理能力、学对话和对齐（1.9）。
- **SFT**：监督微调，学习示范答案（4.1）。
- **RLHF / PPO**：用奖励模型做强化学习（4.1）。
- **DPO / SimPO**：直接在偏好对上优化，不需要单独的奖励模型（4.1）。
- **GRPO / RLOO**：用组内对比代替价值网络的强化学习方法（4.1）。
- **RLVR**：用可自动验证的奖励（答案对不对、测试过不过）做强化学习（4.1）。
- **蒸馏**：用大模型的输出（或概率分布）教小模型（4.1）。
- **LoRA / QLoRA**：只训练低秩增量矩阵的轻量微调（4.1）。
- **对话模板（chat template）**：把多轮对话拼成模型输入的格式，模板错了分数会掉（4.1）。
- **模型合并 / abliteration**：前者是把多个模型的权重做算术组合；后者是去掉“拒答方向”（4.1）。
- **long2short / 过度思考**：让推理模型少想一点，省 token，但不一定更准（4.3）。

**量化**
- **bpw**：平均每个权重占多少位（3.5）。
- **FP16 / BF16 / FP8 / INT8 / INT4**：不同数字格式（3.2）。
- **仅权重量化 / 权重+激活量化（W4A16 / W8A8）**（3.4）。
- **块缩放（block scale）/ 超级块**：每 32 或 256 个权重共用一个缩放因子（3.5）。
- **k-quant（Q4_K_M 等）**：llama.cpp 的分层缩放量化（3.5）。
- **i-quant（IQ3_XXS 等）**：用格点码本的低位量化（3.5）。
- **imatrix（重要性矩阵）**：用校准数据统计每个权重的重要性，指导量化（3.5）。
- **PTQ / QAT**：训练后量化 / 量化感知训练（3.6）。
- **GPTQ / AWQ**：经典的 4 位训练后量化算法（3.6）。
- **离群值 / 旋转（QuaRot、SpinQuant）**：激活中的极端值让量化变难，正交旋转可以把它们摊平（3.6）。
- **GSQ-RCO**：本机 3 位档用的量化方法（3.7）。
- **MXFP4 / NVFP4**：4 位浮点格式，区别在块大小和缩放精度（3.8）。
- **KV 量化（q8_0 / q4_0 KV）**：压缩 KV 缓存（3.10）。
- **PPL（困惑度）/ KLD（KL 散度）**：衡量量化质量。KLD 和原模型逐 token 比较，更可靠（3.11）。

**推理引擎**
- **Prefill / Decode**：预填充（一次处理整个输入，算力受限）和逐 token 解码（带宽受限）（5.1）。
- **TTFT / TPOT / 吞吐**：首 token 延迟 / 每个输出 token 的时间 / 单位时间的总 token 数（5.1）。
- **KV cache**：缓存之前所有 token 的 K/V，避免重复计算（5.2）。
- **连续批处理（Orca）**：每一步都可以加入或移出请求（5.3）。
- **PagedAttention**：像操作系统分页一样管理 KV 显存（5.3）。
- **前缀缓存 / RadixAttention**：相同的前缀只算一次（5.3）。
- **分块预填充（Chunked prefill）**：长输入切块，和解码请求交错执行（5.3）。
- **FlashAttention**：分块计算注意力，不把完整的注意力矩阵写回显存（5.4）。
- **MMQ / MMVQ**：llama.cpp 直接在量化数据上做矩阵乘 / 矩阵-向量乘的内核（5.4）。
- **内核融合 / CUDA Graphs**：减少内核启动次数和显存往返（5.4）。
- **ggml / GGUF / mmap**：llama.cpp 的张量库 / 模型文件格式 / 内存映射加载（5.6）。
- **`-sm layer` / `-sm row` / `-sm tensor`**：多卡切分方式，按层、按行、按张量（5.6）。
- **MoE 卸载（`--cpu-moe`、`-ot`）**：把专家权重放在内存里，GPU 只放其余部分（5.6）。
- **HIP / ROCm / Vulkan / CUDA**：AMD 和 NVIDIA 的计算栈（5.7）。
- **gfx1201 / WMMA / MFMA**：R9700 的芯片代号 / 消费级卡的矩阵指令 / 数据中心卡的矩阵指令（5.7）。
- **rdna-boosts**：针对 RDNA4 的 llama.cpp 补丁集（5.7）。
- **Roofline**：用“算力上限 vs 带宽上限”判断瓶颈在哪的模型（3.3、7.1）。

**推测解码**
- **草稿 / 验证**：小模型或预测头先猜，大模型一次验证多个 token（6.1）。
- **拒绝采样**：保证输出分布和不用推测时完全一样的接受规则（6.2）。
- **接受率 α / 草稿长度 γ / 每步期望 token 数 E**：E = (1 − α^(γ+1)) / (1 − α)（6.3）。
- **n-gram 草稿 / Medusa / EAGLE / DFlash**：不同的草稿来源（6.4）。
- **自适应深度**：根据接受情况动态调整猜几个（6.5）。
- **状态回滚**：猜错时，线性注意力的状态要退回去（6.8）。

**评测**
- **pass@1 / 平均分**：每题只采样一次的通过率（7.2）。
- **污染**：测试题出现在训练数据里（7.2）。
- **McNemar 检验**：两个模型在同一组题上的配对显著性检验（7.3）。

## 0.5 已知的空白

具体清单见 [08_参考资料](09-第_8_章_参考资料汇总.md) 8.9。主要几条：
- 显卡带宽（640 / 936 GB/s）没有对照官方规格页逐项核实；
- “Vulkan 为什么在 R9700 上比 HIP 快”只有推断，没有一手分析；
- 社区微调变体的训练细节大多没有公开，第 4 章的分析主要依据本机实测和模型卡；
- 本机实测的题集小，分差多数不显著（见 7.3）。
